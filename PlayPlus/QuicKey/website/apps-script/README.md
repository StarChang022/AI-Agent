# 聯絡表單備份試算表：建立步驟

官網每收到一則留言，除了寄信到 `service@playplus.com.tw`，也會在背景把資料新增到這份 Google 試算表。試算表只是**備份**，留言以信箱為準。寫入失敗時（連不上、密碼不符、找不到「留言」工作表等），官網會寄一封「[官網] 試算表備份失敗」通知到 `service@playplus.com.tw`（Cloudflare 環境變數 `ALERT_TO`），通知信裡不會有任何表單內容。

程式碼：同一個資料夾裡的 [`Code.gs`](./Code.gs)。

## 一、建立試算表與 Apps Script（內部人員操作）

> 用 `playplus.com.tw@gmail.com` 建立（見 `docs/上線前規格.md` D13），共用權限只開給需要看的人。這個帳號要開啟兩步驟驗證。

1. 在 Google 雲端硬碟新增一份試算表，命名例如「Quickey 官網留言」。
2. 選單「擴充功能」→「Apps Script」，開啟編輯器。
3. 把預設的 `Code.gs` 內容全部刪掉，貼上本 repo 的 `apps-script/Code.gs`，按「儲存」。
4. 設定密碼：左側齒輪「專案設定」→ 最下方「指令碼屬性」→「新增指令碼屬性」
   - 屬性：`SHEET_TOKEN`
   - 值：自訂一組長密碼（建議 32 個字元以上的隨機英數字，可以用密碼管理工具產生）
5. 回到編輯器，上方函式選單選 `setupSheet`，按「執行」。第一次會要求授權，用同一個帳號同意即可。
   執行完試算表會出現「留言」工作表，第一列是：時間、姓名、公司、Email、電話、類別、內容、寄信成功。
6. 右上角「部署」→「新增部署作業」→ 齒輪選「網頁應用程式」
   - 說明：例如「官網留言備份」
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。
7. 把**網址**和**密碼**交給開發，設定成 Cloudflare Pages 的 Secret：
   - `SHEET_WEBHOOK_URL` = 網頁應用程式網址
   - `SHEET_TOKEN` = 第 4 步的密碼

> 「誰可以存取：所有人」是讓官網伺服器能送資料進來；沒有附上正確密碼的請求不會寫入任何資料。

## 二、確認有接通

部署後可以在終端機送一筆測試資料（把網址和密碼換成自己的）：

```bash
curl -L -X POST 'https://script.google.com/macros/s/xxxx/exec' \
  -H 'Content-Type: application/json' \
  -d '{"token":"你的密碼","name":"測試","company":"","email":"test@example.com","phone":"","topic":"其他問題","message":"=1+1 這是測試","mailSent":true}'
```

- 回應 `{"ok":true}`，試算表多一列，「內容」欄顯示 `=1+1 這是測試`（文字，不會算成 2）→ 成功。
- 回應 `{"ok":false,"error":"unauthorized"}` → 密碼不符，檢查指令碼屬性。
- 回應的是一整頁 HTML（Google 登入頁）→ 部署的「誰可以存取」不是「所有人」。
- 測完把這一列刪掉。

## 三、注意事項（失敗大多來自人為改設定）

- **修改程式後**，要用「部署」→「管理部署作業」→ 編輯（鉛筆）**原本那一個**部署，版本選「新版本」再部署。不要「新增部署作業」，新增的話網址會變，官網就送不進來。
- 不要改工作表名稱「留言」，也不要刪掉這個工作表；可以調整欄寬，但不要插入或調換欄位順序。
- `playplus.com.tw@gmail.com` 能登入就能看到所有留言者的個資：知道密碼的人離職或異動時要改密碼；試算表共用的人離職時要移除共用。
- 每次改過 Apps Script 或試算表後，到官網送一筆測試留言，確認信箱和試算表都有收到，而且**沒有**收到「試算表備份失敗」通知，測完刪掉。
- Apps Script 的「執行作業」紀錄只會記錄錯誤原因，不會記錄表單內容；修改程式時也不要加上印出表單內容的程式碼。
- 有人要求刪除個資時，信箱和試算表都要刪，做法見 `docs/上線前規格.md` 附錄 B。
