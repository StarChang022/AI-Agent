Quickey Design System

代墊款管理工具（Quickey）設計系統。主色為品牌綠 #00B39F（取自 Logo），實心底/文字強調走 WCAG 合格的 #008072。前台採 mobile-first 大圓角卡片語言，後台繼承相同 tokens。

設計理念

  • 主色克制：品牌綠只用在主要動作按鈕、選中分頁、Logo。頁面主體以中性灰階為主，表頭/卡片/背景不鋪主色。
  • 狀態語意化，且與主色脫鉤：6 種請款狀態各有專屬顏色，一眼可辨。主色不可挪用當狀態色——「已核銷」已改成固定紫色，不再借用 primary，避免未來主色再換色時撞色。
  • 數字第一：金額使用 currency 文字樣式 + tabular-nums 等寬對齊。
  • 不炫技：避免大範圍漸層、大 hero、插畫、pastel 卡片色。
  • 重要動作要有存在感：多數元件走克制路線，但憑證上傳這種流程關鍵動作，改用比一般 input 更明顯的拖放區樣式。

元件規範

專案優先使用 PrimeVue 元件（已由 presets/trust-blue.ts 對齊主色，未來改名對齊品牌綠），以下僅供 PrimeVue 無對應元件、或需自製共用元件時參考。以下圖示為手繪示意 SVG，實際專案一律使用 PrimeIcons（pi pi-*）。

Buttons — button-primary / secondary / danger / text

危險動作（駁回、作廢）改成外框樣式而非實心紅底，跟其餘按鈕的克制感一致。Icon+文字按鈕的 icon 跟隨文字顏色（currentColor），icon-only 按鈕固定 40×40 置中。

Status Badge / Tag / Category Chip — status-badge / tag / category-chip

Tag（對應 PrimeVue <Tag>）跟 category-chip 用途不同：category-chip 是分類本身（統一灰底、不做強調變體），Tag 是附加在資料上的一般語意標記，例如 BudgetsView 的超支警示用 severity="danger"。

Tab（含數量徽章） — tab

對應 PayoutView / ReviewView / CategoriesView 三處手刻 tab，統一成同一種樣式：下方 2px 指示條貼齊文字下緣，數量徽章選中時底色 primary-50、文字 primary-text，未選中時走灰階。

數量徽章只放在「還需要有人處理」的分頁（例如簽核中、駁回、已核銷待發放、待簽核、待付款、未讀）。「全部」與終點狀態（已發放、已作廢、已付款、完成、已處理、已讀）不顯示數字——這些數字只會一直累加、看了也不用做什麼；總數看表格底部「共 N 筆」。類別、人員這類清單盤點的分頁也不顯示。

Dialog 用於表單型彈窗（例如 UsersView 新增/編輯人員、重設密碼），footer 順序固定：取消在左、主要動作在右。Drawer 用於篩選條件、次要詳情等不需要打斷主要流程的內容，從右側滑入。

樣式三層架構

由下往上選擇，第一個 yes 就用該層：

  • ① 需要 props / slot / v-model / 條件邏輯？→ Vue 元件（StatusBadge、AmountText、PageHeader、EmptyState）
  • ② 視覺組合在 3 個以上地方重複、且有明確語意？→ Utility class（styles/index.css 的 @utility，如 .card、.card-lg、.category-chip、.field-label、.upload-dropzone）
  • ③ 只是一次性排版？→ Tailwind 原生 utility 直接寫在 template

Design tokens 定義在 frontend/src/styles/index.css 的 @theme 區塊，PrimeVue 主色透過 frontend/src/presets/trust-blue.ts 對齊。全域樣式集中在 styles/index.css 用 .p-button / .p-inputtext 等原生 class 覆寫，不做每個元件個別 :pt pass-through。

新增 UI 前檢查清單

  • 需要的顏色 / 圓角 / 陰影是否已在 @theme？沒有 → 先加 token
  • 有沒有現成的 utility class 可以用？
  • 這段 pattern 之後會重複 3 次以上嗎？→ 抽 utility
  • 有邏輯或狀態嗎？→ 抽 Vue 元件
  • 手機版字級都 ≤ 14px？
  • 按鈕/分頁/徽章/Tag 的圓角是否用 rounded-full（不是 rounded-control）？

無障礙

  • Icon-only 互動元素必加 aria-label；裝飾性 icon 加 aria-hidden="true"
  • 表單欄位：<label> 綁定 for；必填 aria-required；驗證錯誤 aria-invalid + aria-describedby
  • Modal / Dialog：可用 Esc 關閉、focus 移入並鎖定、關閉按鈕有 aria-label
  • 互動一律用 <button> / <a> / <RouterLink>，不用 <div @click>
  • 狀態、錯誤、必填不能只靠顏色分辨，要搭配文字或 icon
  • Focus outline 不可被 CSS 移除，自訂用 :focus-visible
  • 動態訊息：一般 aria-live="polite"，緊急錯誤 aria-live="assertive"
  • 手機可點區域 ≥ 44 × 44 px

待整理 / 相關文件

  • Toast 位置與長度規範尚未整理視覺規範（跟 Dialog/Drawer 不同，Toast 已有大量實際用例）。
