## A. 系統架構

### A.1 前後台雙介面

| 介面 | 頁面 |
|------|------|
| **前台** | 登入、首頁（個人本月統計）、表單填寫、歷史記錄 |
| **後台** | 登入、儀表板、請款記錄列表、審核列表、人員管理 |

### A.2 各職級可登入介面

| 職級 | 前台 | 後台 |
|------|:----:|:----:|
| 員工 | ✅ | ❌ |
| 主管 | ✅ | ✅ |
| 財務 | ✅ | ✅ |
| 管理員 | ❌ | ✅ |

主管與財務自己也會提報代墊款，故兩者需可同時登入前後台。

## C. 請款記錄的狀態

一筆請款記錄共有 **6 種狀態**：

| 狀態 | 說明 |
|------|------|
| **草稿** | 建立但尚未提交，員工可編輯或刪除 |
| **簽核中** | 已提交，正在跑簽核流程 |
| **駁回** | 任一簽核者退回，員工可修改後重新提交 |
| **已核銷** | 全部簽核通過，等待財務撥款 |
| **已發放** | 財務已撥款（終態） |
| **已作廢** | 財務作廢（終態） |

### 狀態流轉

```
草稿 ─► 簽核中 ─► 已核銷 ─► 已發放
          │
          └─► 駁回 ─► （員工修改後重新提交）─► 簽核中
```

**駁回後重新提交**：走完整簽核路徑（部門主管 → 財務），不從駁回點續跑。

---

## D. 簽核路徑

依提報人的職級與部門結構，動態決定簽核路徑：

| 提報人 | Step 1 | Step 2 |
|--------|--------|--------|
| 員工 | 該員工部門的所有主管 | 財務人員 |
| 主管 | 同部門其他主管（若只有一人 → 自審） | 財務人員 |
| 財務（財務部有主管） | 財務主管 | 其他財務（若只有一人 → 自審） |
| 財務（財務部無主管） | 跳過 | 其他財務（若只有一人 → 自審） |

**通則：**
- 「同職級互審」為預設規則
- 「同職級只有一人」則自審
- 「無對應上級主管」則跳過該 step

---

## E. 部門模型

- 員工只隸屬**一個**部門
- 一個部門可有**多位**主管
- **財務部**本身也是一個部門，可有主管、也可以無主管
- 部門由**管理員**維護（新增／編輯／指派主管）

---

## F. 權限規則修正（覆寫原 PRD 第 8 章的部分項目）

| 操作 | 原 PRD | 本次修正 |
|------|--------|---------|
| 財務刪除他人記錄 | ✅ 已核銷前可刪 | ❌ 不可刪，改用「作廢」 |
| 財務編輯他人記錄 | 未明說 | ❌ 不可編輯，只能簽核時「駁回」 |
| 主管查看他部門記錄 | 未明說 | ❌ 只能看自己部門 |
| 員工刪除記錄 | ✅ 草稿 | ✅ 草稿（維持） |
| 已核銷／已發放記錄 | 未明說 | 不可刪除，只能作廢 |

管理員權限沿用原 PRD 第 8 章（可查看全公司、審核、標記已發放、作廢、設定系統參數），實質為 super-user。

---

## G. 其他確定項目

- **發放動作**：由財務執行
- **作廢動作**：由財務執行，限「已核銷前」的記錄
- **後台審核頁**提供兩個獨立按鈕：
  - 「標記已核銷」→ 簽核中 → 已核銷
  - 「標記已發放」→ 已核銷 → 已發放
- 不做：金額分級加簽
