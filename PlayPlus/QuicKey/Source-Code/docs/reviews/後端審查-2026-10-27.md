## 怎麼測的

- 這個分支的 `Gemfile.lock` 需要 googleauth 等套件，本機沒裝，`bin/rails runner` 起不來。我改成只載入 ActiveSupport + 這兩個檔案（`Ocr::ReceiptTextExtractor`、`Ocr::ResultMerger`）離線跑，行為與 Rails 內一致。
- 輸入文字**全是我自編的**，不是真實 OCR 輸出；統編、發票號碼都是假號碼。行序、換行位置我盡量照 Enterprise OCR 常見的樣子，但真實全文可能不同，下面「重現」請當作代表性例子，不是實測保證。
- 測試腳本在我的暫存區；可重跑的示範在 `docs/reviews/2026-10-27/ocr-extractor-示範.rb`（含修正寫法與驗證）。

**不建議合併。** 有一個會把伺服器卡死的正規表達式（P0），以及 6 類「填錯」且信心度標 0.9 的情況（P1）。標準格式（電子發票證明聯、一般三聯式的樣本）都抓得對，問題集中在「版面稍有不同就填成別的值」。

## P0

### P0-1　`UNIFIED_TAX_ID` 指數時間，一張圖就能卡死一條 Puma thread

`receipt_text_extractor.rb:40`、呼叫處 `:157`

```ruby
UNIFIED_TAX_ID = /統一編號((?:\s*\n\s*[^\n\d]{1,2})*)[\s:]*(\d{8})(?!\d)/
```

`\s*` 和 `[^\n\d]` 都能吃空白與換行，同一段空白有無數種切法。「統一編號」後面如果**沒有** 8 碼數字、又接一串短行，引擎會把每種切法都試一遍。

重現（`Regexp.timeout = 10`）：

```
統一編號
元

元

元
…（「元＋空行」重複 25 組）
總計 100
```

| 後面接的短行數 | 耗時 |
|---|---|
| 15 | 0.06 秒 |
| 20 | 2.4 秒 |
| 25 | >10 秒（逾時，實際不會結束） |

另一個形狀：`統一編號` 後接 30 行「`  個`」（行首兩個空白）也 >10 秒。

為什麼現實會發生：免用統一發票收據、三聯式的「統一編號」欄常是空白，後面緊接表格的單字格子（元、個、式）；Enterprise OCR 的全文常有空行。惡意使用者也能故意做一張這樣的圖（只要登入員工即可）。

後果比單純慢更糟：
1. 卡在 `ReceiptTextExtractor.call`，整條 thread 100% CPU，沒有逾時；
2. 這時 Google **已經計費**，但 `ocr_controller.rb:67` 的 `consume!` 還沒跑到 → 公司沒被扣次；
3. 同一個使用者重送幾次就能吃光 Puma thread。

**修法**（已驗證：同樣的樣本 0.000 秒，且 4 種正常寫法結果與舊版一致，見示範檔）：

```ruby
UNIFIED_TAX_ID = /統一編號((?:[^\S\n]*\n[^\S\n]*[^\s\d]{1,2})*)[\s:]*(\d{8})(?!\d)/
```

換行前後只吃「不含換行的空白」，格子字元不含空白，三段互不重疊。

**再加兩道保險**（避免以後別的 regex 再出事）：
- `config/initializers/` 加 `Regexp.timeout = 1`（Ruby 3.2+ 支援，本機 3.3.4）。
- controller 在 `Ocr::ReceiptTextExtractor.call` 外包 `rescue Regexp::TimeoutError, StandardError`：當作這個檔案無結果、**照常把頁數算進 `pages`**（Google 已計費），並 `Rails.logger.error`。見 P2-5。

其他 regex 我逐一壓測（單行 3 萬字、`2026 10 ` ×5000、`1*1 ` ×5000、`合計` ×5000 行…），全部 <0.1 秒，數千字的全文沒有效能風險。有問題的只有這一條。

## P1　填錯且信心度 0.9（比留空嚴重）

### P1-1　買受人那一行用「統編」，買方統編被當成賣方統編

`receipt_text_extractor.rb:36-38`、`:150-154`

常見的三聯式 / 手開發票版面：`買受人 大同有限公司 統編 12345678`。`SELLER_TAX_ID` 的 `統編` 會抓到它，而 `BUYER_LABEL_BEFORE`（`:37`）只看**緊鄰前面**有沒有「買方 / 買受人」，這裡中間隔了公司名，所以沒被排除。

重現（role=expense）：

```
AB-12345678
2026-10-15
買受人 大同有限公司 統編 12345678
總計 100
```

結果：`counterparty_tax_id = "12345678"`（0.9）。這是**我方**自己的統編，被填成廠商統編。role=income 時反過來填進 `our_tax_id`。

若同時有賣方那行 `福華文具行有限公司 統編 87654321`，兩個值都落進 sellers，`only` 因不唯一回 nil → 兩個都空（僥倖安全，不是設計）。

建議：判斷「這個統編屬於哪一方」改成看**同一行**有沒有「買受人 / 買方」，而不是只看前 10 個字元。

### P1-2　買受人名稱被當成賣方名稱（名稱與統編互相錯配）

`receipt_text_extractor.rb:170`、`:176`

重現（role=expense）：

```
買受人:
大同有限公司
統一編號:12345678
賣方 福華文具行 統編 87654321
2026/10/15
總計 $1,260
```

結果：`counterparty_name = "大同有限公司"`（買方），`counterparty_tax_id = "87654321"`（賣方）。名稱與統編屬於不同公司。

原因：`COMPANY_NAME` 只認「有限公司」等字樣，賣方「福華文具行」沒有符合 → 沒有賣方名稱候選；買方名稱在下一行、那一行沒有「買」字，所以被當成賣方。

這個欄位標了低信心度、會進 `lowFields`，前端有提醒，所以嚴重度比其他 P1 低；但「名稱」跟「統編」錯配，使用者看到統編正確很容易忽略名稱。

同類問題：
- 買受人與統編同一行時，名稱會帶上尾巴：`our_name = "大同有限公司 統編 12345678"`（`:176` 沒有去掉 `統編/統一編號…`）。
- 賣方名稱會帶標籤：`營業人 福華文具行股份有限公司` → `counterparty_name` 帶「營業人 」。
- 電子發票備援規則（`:172`）取「電子發票證明聯」上一行：上一行是 `TEL:02-27581234` 時，名稱就是電話。

### P1-3　金額抓到「數量合計」或「現金」

`receipt_text_extractor.rb:44`、`:190-192`

(a) **數量合計**：`AMOUNT_EXCLUDES` 只排除「銷售額 / 稅額」。

```
AB-12345678
2026-10-15
數量合計 3
```
→ `amount = 3`（0.9）。同理 `共3項 合計 3` 後面才印 `$450`，也只會取到 3（同一行有數字就不往下找）。

(b) **標籤與值分行時取到第一個帶 $ 的值**（ea4b6b2 的 lookahead）：

```
實收金額
找零
現金
$2,000
$740
$1,260
```
→ `amount = 2000`（客人給的現金，不是應付金額）。ea4b6b2 只擋了「沒有 $ / 元的數字」，沒擋「有 $ 但不是這個標籤的值」。我的版面是自己排的，真實 OCR 是否會把欄位拆成這樣沒把握；但只要標籤與值分行就有這個風險，且信心度是 0.9。

建議：
- `AMOUNT_EXCLUDES` 補 `數量 件數 項`，或改成「標籤前面緊鄰的字必須是行首 / 空白 / 冒號」。
- lookahead 找到的值降為低信心度（見 P2-3），或遇到「找零 / 現金 / 付款」等字樣就停止往下找。

### P1-4　8 碼流水號被當成統編；「英文 2 碼 + 8 碼」單號被當成發票號碼

`receipt_text_extractor.rb:26`、`:36`

(a) `SELLER_TAX_ID` 含 `No`，手寫收據、單據上的 `No.00001234` 流水號會變賣方統編：

```
免用統一發票收據
No. 00001234
日期 115/10/15
合計新臺幣 3,000 元整
```
→ `counterparty_tax_id = "00001234"`（0.9）。`Order No 12345678` 同理。

(b) `INVOICE_NUMBER` 沒有任何語境限制，任何「兩個大寫字母 + 8 碼數字」都算發票號碼：

```
7-ELEVEN 代收繳款證明
銷帳編號 ST12345678
…
```
→ `invoice_prefix="ST"`、`invoice_digits="12345678"`、`document_type="invoice"`。超商繳款證明、`OD20261015` 這類訂單號都會中。連帶使 document_type 錯成 invoice。

建議：
- **統編檢查碼**：台灣統編有檢查碼（2023 年起總和能被 5 整除）。加上去可以擋掉大部分流水號、電話、單號，成本約 10 行。我寫了示範並驗證（`22555003` 通過，`00123456`、`12345678` 不通過），見 `docs/reviews/2026-10-27/ocr-extractor-示範.rb`。注意：加了之後，之前用假統編 `12345678` 的測試文字都要改成合法號碼。
- 發票號碼：要求所在行或前後兩行出現「發票 / 證明聯 / 期別（115年09-10月）」之一才採用；或排除前面緊鄰「單號 / 編號 / 訂單 / 帳」的比對。

### P1-5　日期：商品規格被當日期、沒有範圍檢查

`receipt_text_extractor.rb:32`、`:128-139`

第三個 pattern `(\d{3})/(\d{1,2})/(\d{1,2})` 會吃任何「三位數/數字/數字」：

```
收據
品名 管 100/12/31
總計 100
```
→ `incurred_at = "2011-12-31"`（0.9）。若同時有真日期，兩個值不同 → nil（安全）；**沒有真日期時**就會填錯。另外 `99年1月2日` → 2010-01-02、`999/1/1` → 2910-01-01 都會直接採用，沒有範圍檢查。

建議：年份限制在合理區間（例如民國 100 年到今年+1；西元 2000 到今年+1）；pattern 3 前後要求不是 `/`、英文字母或數字（目前只擋前面數字）。

### P1-6　沒讀到發票號碼 → 一律判成 receipt → 稅率填 exempt_0

`receipt_text_extractor.rb:107-109`、`:217-226`

`document_type = prefix ? "invoice" : "receipt"`，而 receipt 會直接推 `tax_rate = "exempt_0"`（0.9）。發票號碼只要 OCR 讀成 `AB 12345678`（中間空白，regex 只容許 `-`）或少一碼，就整張被當收據：

```
統一發票
2026-10-15
銷售額合計 1200
營業稅 60
總計 1260
```
（`營業稅 60` 不是「稅額」，沒被抓；沒有號碼）→ `document_type="receipt"`、`tax_rate="exempt_0"`。但這張明明是 5% 營業稅。

這是規格 §4 的推導規則本身的風險（「發票號碼讀不到」≠「這是收據」）。建議：
- 只有全文出現「免用統一發票」或「收據」才推 receipt → exempt_0；沒讀到號碼也沒這些字樣時 `document_type` 留 nil、`tax_rate` 留 nil。
- `tax_amt` 的標籤加入「營業稅」，並在有 `pre_tax_amt` 與 `amount` 時可用 `(amount-pre_tax)/pre_tax ≈ 5%` 推導。
- 這幾點動到規格 §3.1 / §4，需要規劃拍板。

## P2

### P2-1　漏抓（留空，不嚴重，列出供排優先序）

- `應收金額 1260`：`:190` 只去掉「合計 / 總計 / 新臺幣」，「金額」沒去掉，同一行抓不到 → 要往下找 → 通常 nil。
- `銷售額 1200 稅額 60` 寫在同一行：`pre_tax_amt` 抓不到（`tax_amt` 抓得到）。
- `免稅銷售額 0` 與 `應稅銷售額 1200` 同時存在 → 值不同 → `pre_tax_amt` 為 nil。這是對的行為，但三聯式常見，之後可分開處理。
- `2026年10月15日`（西元年月日）不支援：`(?<!\d)(\d{2,3})\s*年` 會因為前一個字是數字而不比對。
- `合計新臺幣 壹仟元整` 只有國字時 amount 為 nil（規格已寫明）。

### P2-2　lowFields 與 overall 對照 §6

**符合 §6 的部分**：
- `lowFields` = merged 裡「有值」的 `ourName / counterpartyName`，加 `items`（`[]` 不列）；key 輸出 camelCase（`result_merger.rb:105-109`）。與規格一致，測試也對。
- 有衝突進 `conflicts.fields` 時 merged 為 nil、不會出現在 lowFields，符合。
- 固定值 HIGH 0.9 / LOW 0.5 符合 §3.1；推導欄位不計入 overall 符合。

**設計風險（不是 bug）**：
1. `overall` 是「抓到的欄位」的平均，**抓得越少反而越高**。只抓到金額（外加上面的誤抓）時 overall=0.9，前端「overall < 0.6 才警示」幾乎不會觸發。例：
   ```
   小店
   訂單號 OD20261015
   總計 $350
   ```
   → 只有 `amount` 和誤抓的發票號碼，overall=0.9、lowFields=[]。
   建議把「覆蓋率」納入 overall（例如抓到欄位數 / 預期欄位數），或 `warnings` 多一條「只辨識出 N 個欄位」。
2. 推測性高的規則仍標 HIGH：lookahead 找到的金額（P1-3b）、「統一編號 → 其他視為賣方」（`:160` 的 fallback）、`No:` 標籤（P1-4a）。若填錯，前端完全不會提醒。建議這幾條路徑降為 LOW 並列入 lowFields（要擴充規格 §6 的 lowFields 定義，請規劃決定）。
3. 規格 §6 說「前端對 lowFields 扣掉 ourName 與代墊款 items 後若仍有欄位才 warn」；`ourName` 即使抓錯，使用者也看不到，所以 `ourName` 抓錯（P1-1、P1-2）的實際傷害是：值會被 `only` 擠成 nil 或錯放到對方欄位，而不是顯示在畫面上。

### P2-3　`names` 的小問題（低嚴重度，信心度已標低）

- `:171` 去尾的 `sub(/\s*(?:No|統編|統一編號)…\z/)` 的 `No` 會誤砍英文名：`Nobel Trading 有限公司` → 空字串 → 被 `.presence` 濾掉 → 漏抓（不是填錯）。
- `COMPANY_NAME` 不含「行」「店」「號」「工作室」，福華文具行這類只會靠備援規則或抓不到。

### P2-4　`items` 會吃規格尺寸（已標 LOW，列出供參考）

`ITEM_LINE`（`:54`）：`圖畫紙 30x40 1200` → 單價 30、數量 40、小計 1200，剛好乘得起來 → 產生一筆假品項。有 `lowFields: ["items"]` 提醒，且代墊款忽略 items，影響小。

### P2-5　Controller 防護

`ocr_controller.rb:51-67`

1. **抽欄位出任何非 DocumentAi 的例外 → 500 且不扣次**：`rescue` 只接 `InvalidDocument, Vips::Error`（`:62`）。`ReceiptTextExtractor`、`Regexp::TimeoutError`、未預期的 `NoMethodError` 都會讓整個 action 500，而 Google 已回傳（已計費）。建議在 `:56` 外面再包一層 `rescue StandardError`：當作「該檔無結果」，頁數照算。
2. **配額檢查與扣次之間沒有保留**：`ensure_available!`（`:45`）沒上鎖，同一家公司同時送 N 個請求都能通過，最後 `consume!` 扣到 0 為止（`quota.rb:46-47` 沒有負數），Google 那邊會多收。規格 §5 已接受「扣到 0」，只是提醒並發時超額幅度是 N 倍；MVP 可以不處理，上線後看用量。
3. `used = quota.consume!(pages)`（`:67`）在 `results.empty?` 判斷之前，所以「全部空白」也有扣次，與規格 §2「422 照樣扣次」一致 ✔。
4. 不記錄全文與統編到 log（`:63` 只記 `e.message`）✔。

1. **P0-1**：改 `UNIFIED_TAX_ID`、加 `Regexp.timeout`、controller 補 `rescue`（半小時內可完成，示範檔已驗證）。

## 殘留 / 新增問題（依嚴重度）

### R-1　同一行金額後面還有其他文字時，會丟掉正確的值，轉去抓「下面某一行」（中）

`receipt_text_extractor.rb:289-293`、`:309-314`

`same_line_money` 只在「金額後面沒東西、或接著另一個金額標籤」時才採用；否則回 nil，然後 `elsif money_below(i)` 往下找。往下找到的第一行如果剛好是 `$50` 這種整行金額，而且是緊接下一行，就以 **HIGH** 採用。

重現：

```
電子發票證明聯
AB-12345678
2026-10-15
總計 $1,260 現金 $2,000
$50
```
→ `amount = 50`（0.9）。正確的 1260 被丟掉。

另一個形狀（同一個原因，結果是留空）：`總計:380 賣方:22555003` 寫在同一行 → 金額 nil（真實證明聯通常把「賣方」放下一行，所以不一定遇得到）。

這條路徑原本就存在，不是這次修正引入的，但 P1-3 修完後它是「金額填錯」唯一剩下的主要入口。

建議：同一行有「開頭金額」時一律先採用它（尾巴不是金額標籤時降為 LOW 即可），不要再去 `money_below`；或至少「同行有金額就不往下找」。

另有一個小缺口：`共3項 合計 3` → `amount=3`（HIGH）。排除清單只有「數量合計 / 件數合計」，沒涵蓋「共 N 項 合計 N」這種寫法。實際版面是否存在不確定。

### R-2　「買受人」後面是空的，下一行任何文字都會當成買方名稱（中低，已標 LOW）

`:251-257`

規格說「標籤後沒字時取緊接的下一行」，但沒有限制下一行長什麼樣：

```
免用統一發票收據
買受人:
日期 115年10月15日
合計 $1,000
```
→ `ourName = "日期 115年10月15日"`；`買受人:` 接 `品名 數量 單價` 時 → `ourName = "品名 數量 單價"`。`買受人` 接 `福華商行`（賣方被印在下面）時，賣方名稱被當成買方，賣方名稱因此消失。

影響：expense 的 `ourName` 前端沒有欄位，看不到；**income** 時會變成 `counterpartyName`（客戶名稱）直接帶進表單，會被 `lowFields` 提醒，所以是低信心度可見的錯，不是無聲的錯。

建議：下一行要符合 `COMPANY_NAME`，或不含數字、且不以「日期 / 品名 / 數量 / 單價 / 金額 / 地址 / 統一編號」等表頭字開頭，才採用。

### R-3　「實收金額」可能是客人給的現金（中低）

`:56`

`AMOUNT_LABELS` 包含 `實收金額`。實務上它常是「收到的現金」，超過應付額時不等於含稅金額：

```
電子發票證明聯
AB-12345678
實收金額 2,000
找零 740
```
→ `amount = 2000`（0.9）。同時有 `應收 1,260` 時兩個值不同，會留空（安全）；**只有實收、沒有應收 / 總計時才會填錯**。

建議：只靠「實收金額」抓到的值降為 LOW，或同一份文字有「找零」時不採用「實收金額」。

### R-4　發票號碼放寬空白後，名單外的「XX 8碼」會跟真號碼打架（低中）

`:26`、`:28`、`:164-170`

`[- ]?` 讓 `AB 12345678` 抓得到（好），但：
- 全文有「發票」時，`ID 20261015`、`TW 20261015` 這類「兩個大寫字母 + 空白 + 8 碼」也算候選。有真號碼 `AB-12345678` 時兩個候選不同 → **兩個都丟掉**（真號碼也沒了，只是留空，安全）；沒有真號碼時 `TW 20261015` 會被當發票號碼（`documentType=invoice`）。
- `NOT_INVOICE_BEFORE` 只有「單號 / 編號 / 訂單 / 帳號」。`交易序號 ST12345678` 不在名單內，加上全文有「發票」字樣（例如「發票將另行寄送」）就會被當發票號碼。

建議：候選有多個時，優先採用「帶 `-`」的寫法（證明聯印的是 `AB-12345678`），沒有帶 `-` 的才退而求其次用空白寫法；黑名單補 `序號 / 流水號 / 卡號 / 序`，或改成「號碼所在行或前後一行要有 `證明聯 / 隨機碼 / 期別 / 發票號碼`」。

### R-5　`party_before` 在「單行很長」時是平方時間，不受 `Regexp.timeout` 保護（低）

`:227-232`

不是 regex，是 Ruby 迴圈：每個統編標籤都會對「同一行」重新 `scan`。實測：

| 一行的內容 | 字數 | 耗時 |
|---|---|---|
| `買方 12345675 ` ×3000 | 3.6 萬 | 3.1 秒 |
| `買方 12345675 ` ×6000 | 7.2 萬 | 11.9 秒 |
| 同樣 3000 個、每個一行 | — | 0.35 秒 |

真實憑證每行只有幾十字，OCR 也會換行，一般不會遇到；只有刻意造出「幾萬字、完全不換行」的全文才會。

建議：只往前看固定視窗，例如 `@text[[position - 40, line_start].max...position]`，就和字串總長無關。

### R-6　「收據」二字出現就判 receipt（低）

`:176`

```
統一發票 請留存收據
銷售額 1000
總計 1050
```
發票號碼沒讀到時 → `documentType="receipt"`（0.9）；稅率因為有銷售額 / 總計仍正確推成 `business_5`。前端 documentType 可能因此選成「收據」。

建議：`receipt` 條件改成「有『免用統一發票』」或「有『收據』且沒有『發票』」。

### R-7　標籤去不乾淨（低，LOW）

`:51`

`營業人名稱 福華商行` → `counterpartyName = "名稱 福華商行"`。`NAME_LABEL` 補成 `(?:營業人|賣方|買受人)(?:名稱|姓名)?` 即可。

### R-8　修正帶來的「留空」，不算填錯（低）

- `總計(含營業稅) 1260`：新加入的 `營業稅` 排除字樣會把整行排除，金額留空。
- 現在支援 `2026年10月15日` 後，若同一張還印 `兌獎期限 2026年12月25日` 這類另一個日期，兩個值不同，`incurredAt` 留空（電子發票證明聯本身不印兌獎期限，影響小）。
