# QUICKEY 產品需求文件 @2026/08/19

## 1. 產品定位

**核心價值：中小企業收支管理**

QUICKEY 要解決的問題是「錢從哪裡來、花到哪裡去、賺不賺錢、誰花的、有沒有超預算、審核有沒有卡住」。損益以發生日（收入為開立日）為基準，現金流以收付款日為基準。

不取代會計做帳或報稅。

**目標受眾：收支需要管理的中小型企業與一人公司。**

- 中小型企業：50 人以內，產業不限，有多個支出來源，需要控管支出與預算。
- 一人公司：自行開立發票、自行管理收支的個人銷售業者，通常沒有員工，主要使用一般支出、收入、報表與預算功能。
- 後台操作者分兩種：企業中多為行政人員（不習慣使用財務系統）；一人公司則由老闆本人操作，老闆不一定具備完整的會計知識。2.32.3
- 個人接案者（未成立公司）暫不納入範圍。

代墊款／員工請款是支出管理底下的一項功能，跟一般支出（行政/財務直接登錄的採購、廠商發票、訂閱費等）共用同一套支出資料與介面。

## 2. 目標受眾與角色


| 角色     | 使用範圍             | 說明                                  |
| ------ | ---------------- | ----------------------------------- |
| 企業主    | 後台（唯讀為主／預算與統計視角） | 關心整體支出狀況、預算執行率，不一定親自操作記帳            |
| 行政人員   | 後台主要操作者          | 建立/核對一般支出、審核代墊款請款、建立傳票、管理部門/員工/預算   |
| 員工（選用） | 前台               | 提交代墊款/請款申請，查看自己的請款進度；沒有員工的公司不會用到此角色 |


---

一人公司的老闆同時具備企業主與行政人員的角色。

### Persona（草稿）

**P1 行政人員（中小企業）**

- 情境：負責日常收支登錄、核對憑證、審核員工請款，不習慣財務系統。
- 裝置：電腦為主，外出時可能用手機處理審核。
- 熟悉度：辦公軟體熟練，會計知識有限。
- 主要任務：登錄收入與支出、核對辨識結果、審核請款、維護預算。
- 痛點：月末對帳耗時；不確定類別與科目怎麼選；怕誤改他人的記錄。
- 成功標準：單筆收入或支出可在 1 分鐘內完成登錄；審核時不需要離開頁面找資料。

**P2 企業主**

- 情境：關心公司整體花費、預算執行率，以及代墊款是否累積過多。
- 裝置：電腦與手機都會使用。
- 熟悉度：懂經營，不一定懂會計。
- 主要任務：看儀表板、看預算使用率、看待付款與待收款。
- 痛點：數字不夠即時；報表看不懂。
- 成功標準：打開儀表板後 30 秒內能掌握本月收支與預算狀況。

**P3 一人公司老闆**

- 情境：自己開發票、自己記收支，沒有員工，同時兼任行政與企業主。
- 裝置：電腦與手機都會使用。
- 熟悉度：懂銷售，會計知識有限，不一定分得清會計科目與類別。
- 主要任務：登錄收入與支出、查看損益、管理待收款。
- 痛點：不懂科目與類別的差異；怕記錯；沒有人可以問。
- 成功標準：不需要懂會計，也能完成登錄並看懂損益。

**P4 員工（選用）**

- 情境：因公務先自費，需要向公司請款，常在外面。
- 裝置：手機為主。
- 熟悉度：一般使用者。
- 主要任務：提交請款、上傳憑證、追蹤審核與發放進度。
- 痛點：不知道何時能拿到錢；上傳憑證步驟麻煩。
- 成功標準：從拍照到送出請款可在 1 分鐘內完成。

## 3. 簽核流程

現階段規劃為**一層審核**：

```
員工提交請款 → 財務審核 → 財務發放
```

這是「現階段先做完整的一層」，不是最終只做一層。未來視客戶需求，可以擴充成多層簽核（例如加入部門主管加簽、金額分級加簽等），詳見第 6 節待確認事項。

## 5. 核心使用情境（依角色）

> 以下為概略情境，若後續發現流程更複雜（例如跨部門審核、企業主角色再細分等），建議另外獨立寫一份 User Flow 文件搭配流程圖，不塞進本 PRD。

**企業主**

- 主要透過儀表板了解公司整體花費狀況、各部門預算執行率、代墊款是否累積過多還沒撥付
- 較少親自輸入資料，以檢視/決策為主

**行政／財務**

- 一般支出登錄：收到廠商發票/收據 → 用拍照 OCR／文件上傳／Excel 匯入／手動建立輸入 → 核對 OCR 辨識結果 → 建立傳票 → 完成（不需審核）
- 代墊款審核：收到員工提交的請款 → 審核（通過／駁回，駁回後員工可修改重送）→ 核准後安排撥款、標記已發放
- 日常管理：維護部門/員工資料、設定或調整部門預算
- 月結：查看儀表板統計、匯出 Excel

**員工**

- 因公務先自費支出（如交通、餐費、雜項採購），需要跟公司請款
- 於前台提交代墊款申請（含憑證上傳）→ 追蹤審核進度 → 收到撥款結果

## 6. 其他事項

1. **品牌與 UI 視覺**：先採用 PrimeVue 元件庫，後續再依照實際畫面調整配色與視覺，本 PRD 不預設視覺風格。
2. **代墊款是否需要獨立列示**：分兩階段，不是「獨立」或「用標籤」二選一。
  - **核准前**：代墊款請款是獨立的請款佇列/列表，走自己的審核狀態機（草稿 → 簽核中 → 核准／駁回）。這階段還不是正式支出，**不進入**統一支出列表，也不算進儀表板的支出統計，避免把未確定的申請誤算成公司支出。
    - **核准後**：核准代表財務已確認這筆錢公司要付，此時系統把它轉成一筆正式支出紀錄，併入統一支出列表，用「來源」欄位（代墊款／一般支出）做標籤與篩選即可，不需要為已核准的支出另外拆一份清單。
    - 儀表板「未結清員工代墊款」KPI＝已核准但尚未撥款的金額加總。
3. **員工前台**：確定要做，QUICKEY 會包含員工提交請款用的前台介面。
4. **多層簽核的擴充規劃**：先把單層審核流程規劃完整、落地驗證，之後再提案給客戶討論是否需要多層簽核，現階段不預先設計多層規則。
5. **付費功能分級**：待競品分析更完整（有更多競品比較後）再決定哪些功能列為付費限定。
6. **個人接案者模式**：暫不納入 MVP。一人公司（自行開票、自行管理收支）已納入目標族群，個人接案者的需求後續再另外討論規劃。
7. **商業模式**：預計採用訂閱制。
8. **資料保留政策**：代墊款僅能作廢，不做硬刪除；支出、收入、固定收支範本、類別、帳戶刪除後進入垃圾桶，可還原，或由使用者永久刪除。永久刪除時內容仍保留於稽核日誌。實際保留年限待之後跟記帳士/會計師確認稅務相關法規要求後再訂。
9. **統計基準**：損益統計以發生日為準（收入為開立日）；代墊款於核准後轉為支出，以費用發生日計入。現金流統計以收付款日為準。資金移轉不計入損益與收支統計（見第 19 條）。報表預設以年為期間，逐月彙總。退回的統計規則待討論後補充。
10. **收付款狀態**：收入分「待收款」與「已收款」，支出分「待付款」與「已付款」。狀態可隨時切換，日期可填寫，每次切換都保留歷史紀錄。切換狀態時不清空任何資料。待收款、待付款的紀錄上，畫面隱藏實際收款日（支出另隱藏實際付款日與付款人），只顯示預計日期；資料保留，可於稽核日誌查看。
11. **刪除與垃圾桶**：收入與支出只能在待付款、待收款時刪除。已付款、已收款需先切回待付款、待收款，才能刪除。刪除規則見第 18 條。
12. **作廢**：只用於代墊款（請款），撥款前可作廢，保留簽核歷程。作廢時連動的支出移入垃圾桶，取消作廢時還原。
13. **編輯**：金額、日期、類別、廠商等內容任何時候都可以修改，包括已付款、已收款的紀錄，每次修改都保留變更前後內容。
14. **退回**：待討論，暫不納入本版規格。
15. **稽核日誌**：建立、刪除、還原、永久刪除、編輯、狀態切換、作廢、取消作廢都寫入稽核日誌，記錄操作人、時間與變更前後內容。日誌只能新增，不能由使用者修改或刪除。稽核日誌僅管理員可見，位於後台「系統」群組。
16. **結帳**：MVP 不設結帳期間，任何期間的紀錄都可以修改。報表數字可能因此變動，需以稽核日誌追查。若之後需要定稿，再另外討論結帳功能。
17. **固定收支**：可建立固定收入與固定支出範本，欄位為名稱、收支方向、類別、金額、週期（每月幾號，或每年幾月幾日）、開始月份、結束月份（可留空表示持續）。依週期自動產生待收款或待付款紀錄，日期為週期日；週期日遇到較短的月份時，產生在當月最後一天。到期後不再產生，範本移至「歷史」分頁。想停止產生，可把結束月份改為想要的最後一個月，或刪除範本；已產生的紀錄不受影響。修改範本只影響尚未產生的週期。每筆範本可查看它產生的所有紀錄。產生的紀錄即一般收入或支出，可編輯、切換狀態、刪除。
18. **全站刪除統一**：支出、收入、資金移轉、固定收支範本、類別、帳戶的刪除，一律先進入垃圾桶。垃圾桶內的紀錄可以還原，或由使用者永久刪除；不計入統計，不可編輯。代墊款維持只能作廢，不做刪除。
19. **資金移轉**：用於帳戶之間搬移資金，例如從銀行提領到零用金。於後台「收支管理」群組的「資金移轉」頁新增、查詢與編輯。欄位：轉出帳戶、轉入帳戶、金額、移轉日期、備註、憑證（選填）、手續費（選填，預設 0）。
  - 轉出與轉入帳戶不能相同，金額必須大於 0。
  - 移轉不計入收入、支出、損益、預算與儀表板，只影響兩個帳戶的餘額。現金流報表的合計因轉出與轉入相抵，不變。
  - 手續費大於 0 時，系統自動產生一筆支出（類別「手續費」、已付款、帳戶為轉出帳戶），計入損益與現金流。編輯移轉時同步更新該支出；手續費改為 0 時，該支出一併進入垃圾桶；刪除移轉時，該支出也進入垃圾桶。
  - 刪除依第 18 條進入垃圾桶。所有動作寫入稽核日誌。
20. **帳戶與起始金額**：帳戶分為銀行帳戶與現金兩種，建立時輸入帳戶名稱（例如「永豐-總公司」「零用金」）與起始金額。帳戶名稱在公司內不可重複。MVP 不記錄銀行名稱、分行與銀行帳號，只支援新台幣。
  - 起始金額視為建立當月月初的餘額。之後每年度的期初自動帶入上一年期末，不需重新設定。建立月之前的月份不顯示該帳戶。
  - 所有收入與支出都必須指定帳戶。手動新增與匯入時，預設帶入上一次使用的帳戶，可以更改。OCR 辨識不含帳戶，由使用者在核對步驟選擇。
  - 代墊款請款通過時指定帳戶，撥款時沿用該帳戶。
  - 上線前的歷史收支歸入系統建立的預設帳戶，其起始金額由使用者於上線時輸入實際金額。
  - 帳戶餘額 ＝ 起始金額 ＋ 已收款 − 已付款 ± 資金移轉。
  - 現金流報表預設顯示所有帳戶合計，可切換為單一帳戶；每月顯示期初現金、淨現金流、期末現金（期初等於上月期末）。
  - 修改起始金額需二次確認，寫入稽核日誌。
  - 指定或變更帳戶屬於編輯，任何狀態都可以，寫入稽核日誌。
21. **帳戶設定**：位於後台「系統」群組。列表顯示帳戶名稱、類型（銀行帳戶／現金）與起始金額。可新增（欄位與收支表單新增帳戶相同），也可編輯名稱與起始金額；修改起始金額需二次確認。已有任一收支或資金移轉紀錄引用的帳戶不可刪除，畫面出現不可刪除的提示；未被引用的帳戶依第 18 條進入垃圾桶。

## 7. 差異化定位（初稿，待更多競品分析後調整）

目前僅完成與 HAO!計的比較（【待補】比較文件 `docs/競品分析_HAO計.md` 尚未放入 repo），初步方向：

**現階段（內帳／內部管理）**

- 核心賣點是「控管」：審核流程、預算執行、多來源支出彙整，讓企業主與財務自己就能看懂內部支出狀況——就是給企業自己看的內帳
- 保留簡化的會計科目對應（供財務人員後續轉出傳票用），不要求使用者懂正規會計
- 不包含：正規會計科目全套、正式損益表與資產負債表（外帳／報稅等級）
- 納入 MVP：管理損益概覽（收入、支出、淨額），供企業主檢視獲利狀況

**後期規劃（正式財報／外帳）**

- 正規會計科目全套與正式財報是後期目標，並非永遠不做，只是現階段不列入範圍
- 未來可能路徑：跟會計師／記帳士事務所合作（類似 HAO!計的模式），把 QUICKEY 累積的內帳資料轉出或串接給專業會計端處理正式財報與報稅，而不是自己重造一個會計平台

待補齊其他競品分析後，此節再一併調整。
