# QA Checklist — 人員邀請模組

> **驗證對象**：管理員邀請 / 撤回人員、人員透過連結加入公司、人員前台修改密碼；以及本 change 附帶完成的部門欄下架、後台重設密碼下架。
> **前置**：以管理員身分登入後台（[admin@example.com](mailto:admin@example.com) / password123）進入「人員管理」。若要從全新狀態測試，請洽工程師協助清空 localStorage。
> **注意**：本清單只驗證「功能流程與規則」；顏色、字級、按鈕樣式等 UI 細節由設計規範統一把關，不在此列。

---

## 1. 頁面總覽

- [ ] 頁面標題為「人員管理」，右上角有「邀請人員」按鈕
- [ ] 標題下方顯示「人員名額：X / 10」，X 為現有人員 + 有效邀請的總數
- [ ] 表格欄位為：姓名、Email、身分、狀態、操作五欄，**沒有「部門」欄**
- [ ] 「身分」欄與「狀態」欄分開顯示；身分顯示「一般人員」或「管理員」；狀態顯示「使用中」或「已邀請」
- [ ] 「已邀請」列的身分欄顯示為「一般人員」（受邀者接受後一律為一般人員身分）
- [ ] 名額達 10 時，「邀請人員」按鈕呈灰色停用；滑鼠移到按鈕上會出現提示「已達人員上限 10 人」
- [ ] 名額未滿時，「邀請人員」按鈕可點

## 2. 邀請人員

- [ ] 點「邀請人員」→ 開啟 Dialog，只有 Email 與姓名兩個欄位（沒有密碼欄）
- [ ] Email 或姓名任一欄空白 → 顯示對應錯誤，不送出
- [ ] Email 格式不正確（例如 `abc`、`abc@`）→ 顯示「Email 格式不正確」，不建立記錄
- [ ] 名額已滿時強制點按鈕（若能點）→ 顯示「已達人員上限 10 人，請先撤回既有邀請或移除人員」
- [ ] Email 與現有人員重複（例如 `ming@example.com`）→ 顯示「該 email 已是公司人員」
- [ ] Email 與現有有效邀請重複（例如 `pending@example.com`）→ 顯示「該 email 已有有效邀請，請先撤回既有邀請再重發」
- [ ] Email 與已過期或已撤回邀請相同 → 可正常建立新邀請（不被視為重複）
- [ ] 成功發送 → Dialog 關閉、Toast 提示「已發送邀請」；表格出現新的一列，狀態為「已邀請」



## 3. 複製邀請連結

> **註記**：MVP 期間「複製連結」是唯一的邀請傳遞管道（後端尚未提供寄信）。Stage B 後端上線後，發送邀請時系統會自動寄邀請 email 給對方，此按鈕會降級為「輔助管道」——供 email 被擋垃圾信、或想改由 Slack / LINE / 當面等其他方式傳遞時使用；按鈕本身不會下架。

- [ ] 「已邀請」列的操作欄有「複製連結」按鈕
- [ ] 點「複製連結」→ Toast「已複製邀請連結」出現
- [ ] 將剪貼簿內容貼到其他地方 → 是 `<目前站台網址>/invite/accept?token=<某隨機字串>` 的格式
- [ ] 於瀏覽器隱私分頁（無 clipboard 權限）測試 → 出現一個帶連結的 prompt 對話框讓使用者手動選取複製



## 4. 撤回邀請

- [ ] 「已邀請」列的操作欄有「撤回」按鈕
- [ ] 點「撤回」→ 出現二次確認對話框「確定撤回對 [xxx@example.com](mailto:xxx@example.com) 的邀請？」
- [ ] 點「取消」→ 什麼都不發生
- [ ] 點「確認撤回」→ Toast「已撤回邀請」，該列從表格消失
- [ ] 撤回後名額進度顯示立即更新（例如從 5/10 → 4/10）
- [ ] 撤回後之前複製的連結貼到瀏覽器開啟 → Accept 頁顯示「邀請已撤回」



## 5. 編輯人員

- [ ] 「使用中」列的操作欄只有「編輯」與「刪除」兩個按鈕（**沒有「重設密碼」**）
- [ ] 點「編輯」→ 開啟 Dialog；只有「姓名」是可編輯欄位
- [ ] Dialog 內 Email 以 input 呈現但呈灰色停用（無法輸入），下方附說明「Email 一經建立不可修改」
- [ ] Dialog 內的「身分」下拉呈灰色停用（無法點開），下方有提示「此階段暫不支援新增 / 轉移管理員身分」
- [ ] Dialog 底部提示「密碼由本人自行於前台『帳號設定』修改；此處無法重設」
- [ ] 姓名清空按儲存 → 顯示「請填姓名」，不儲存
- [ ] 姓名修改後按「儲存」→ Toast 提示更新成功；表格對應列即時反映新姓名



## 6. Accept 頁 — 錯誤情境

從 UsersView 複製一個「待入職」邀請連結（token=`seed-token-pending`），或使用以下 seed token 直接組連結測試：

- [ ] 開啟 `/invite/accept`（無 token）→ 顯示「連結無效」錯誤，不出現表單
- [ ] 開啟 `/invite/accept?token=notfound123` → 顯示「連結無效」錯誤
- [ ] 開啟 `/invite/accept?token=seed-token-expired` → 顯示「連結已過期」錯誤，不出現表單
- [ ] 開啟 `/invite/accept?token=seed-token-revoked` → 顯示「邀請已撤回」錯誤
- [ ] 開啟一個已被接受過的 token → 顯示「此邀請連結已被使用過」+「前往登入」連結
- [ ] 每個錯誤畫面上都附有適當的協助文字（例如「請聯絡貴公司管理員重新發送邀請」）



## 7. Accept 頁 — 成功流程

以隱私分頁或登出後開啟 seed token 連結 `/invite/accept?token=seed-token-pending`：

- [ ] 表單顯示 Email「[pending@example.com](mailto:pending@example.com)」為唯讀
- [ ] 表單顯示姓名「待入職」為唯讀，下方有提示「若姓名有誤，請聯絡貴公司管理員重新邀請」
- [ ] 嘗試點姓名欄輸入 → 無法修改
- [ ] 密碼欄留白按「加入公司」→ 提示「密碼長度至少 8 碼」
- [ ] 密碼 < 8 碼 → 提示「密碼長度至少 8 碼」
- [ ] 兩個密碼欄不同 → 提示「兩次輸入的密碼不同」
- [ ] 兩個密碼欄都填 `newpass1234` → 點「加入公司」→ 自動導向 `/app/home`（前台首頁）
- [ ] 頂部使用者顯示為「待入職」，可以看到人員前台介面
- [ ] 回到後台管理員介面（另開分頁）→ 人員管理列表看到「待入職」為「使用中」，「已邀請」的那列消失
- [ ] 名額進度更新（原本 pending 佔一格，接受後仍佔一格但改為 active）



## 8. Accept 頁 — 已登入身分

- [ ] 以管理員身分登入後台
- [ ] 直接在網址列輸入 `/invite/accept?token=seed-token-pending`
- [ ] 頁面顯示警告訊息「目前已登入為 [admin@example.com](mailto:admin@example.com)。請先登出目前身分再開啟邀請連結」
- [ ] 有「登出目前身分」按鈕，點下去後才登出（不會偷偷登出）
- [ ] 登出後頁面自動切換為 Accept 表單（顯示 pending 邀請的 email 與姓名）



## 9. 修改密碼（前台 / 後台皆可）

> 前台底部導覽不再有「帳號」項目；修改密碼改由 header 右上角使用者名稱區塊點開下拉選單觸發。管理員登入後台亦同樣支援（後台 header 右上角一樣有下拉）。

- [x] 以一般人員身分登入前台（[ming@example.com](mailto:ming@example.com) / password123）
- [x] Header 右上角顯示人員姓名 + 頭像；旁邊有下拉箭頭
- [x] 點名字或頭像區塊 → 展開下拉選單，內含「修改密碼」「登出」兩項
- [ ] 點「修改密碼」→ 開啟修改密碼 Dialog
- [ ] Dialog 內有三個欄位：舊密碼、新密碼、再次輸入新密碼
- [ ] 舊密碼欄空白按「更新密碼」→ 舊密碼欄位下方紅字「請輸入舊密碼」，不送出
- [ ] 舊密碼填錯（例如 `wrongpwd`）→ 舊密碼欄位下方紅字「舊密碼不正確」，不送出
- [ ] 新密碼欄空白 → 新密碼下方紅字「請設定新密碼」
- [ ] 新密碼 < 8 碼 → 新密碼下方紅字「新密碼長度至少 8 碼」
- [ ] 新密碼與舊密碼相同 → 新密碼下方紅字「新密碼不可與舊密碼相同」
- [ ] 再次輸入密碼欄空白 → 該欄下方紅字「請再次輸入新密碼」
- [ ] 兩次新密碼不同 → 該欄下方紅字「兩次輸入的新密碼不同」
- [ ] 全部正確 → Dialog 關閉、Toast「密碼已更新」；**不強制登出**
- [ ] 登出後改用新密碼登入 → 成功
- [ ] 用舊密碼登入 → 失敗（Email 或密碼錯誤）
- [ ] 直接在網址列輸入舊 `/app/account` → 被導向登入頁或前台首頁（該路徑已下架）
- [ ] 以管理員身分登入後台 → header 右上角同樣有下拉，可修改自己的密碼



## 10. 資料保留

- [ ] 建立一筆新邀請 → 重新整理頁面 → 該筆邀請仍存在
- [ ] 建立一筆新邀請 → 關閉瀏覽器再重新打開 → 該筆邀請仍存在
- [ ] 撤回一筆邀請 → 重新整理 → 該筆仍然消失於列表（撤回狀態被保留）

- [ ] 後台「簽核」表格：申請人欄底下**沒有**部門小字

- [ ] 「人員管理」表格：**沒有**部門欄



## 12. 手機模擬（DevTools 375px）

- [ ] 「人員管理」表格水平可捲動，所有操作按鈕可點
- [ ] 表格內「身分」「狀態」的標籤**不會**被壓縮成一字一行；文字完整顯示於單行內
- [ ] 「邀請人員」Dialog 左右皆有留白（不會貼齊裝置邊緣），欄位可輸入
- [ ] 「編輯人員」Dialog 左右皆有留白，可完整顯示
- [ ] 修改密碼 Dialog 左右皆有留白，三個密碼欄可輸入
- [ ] Accept 頁單欄置中、表單可輸入、密碼欄可看到 password type 遮蔽



## 13. 已知限制

- [ ] 若管理員刪除了有代墊款歷史的人員，該人員的請款記錄仍會顯示為「（已離職）」而不會消失
