# QA Checklist — 收入管理模組

> **驗證對象**：管理員操作收入管理、以及與之連動的支出端新規則、類別管理、報表與儀表板。
> **前置**：以管理員身分登入後台。涉及支出端調整的章節請同時準備幾筆既有的支出資料以便對照。
> **注意**：本清單只驗證「功能流程與規則」；顏色、字級、提示停留秒數等 UI 細節由設計規範統一把關，不在此列。
> **對齊準則**：規格明訂「收入與支出的刪除、垃圾桶、還原、編輯、狀態切換行為一致」，驗收時請把兩邊當對照組一起看。

---

## 1. 初次進入「收入管理」

- [ ] 側邊欄看得到「收入管理」入口；點進去進入收入清單
- [ ] 清單欄位至少包含：開立日、客戶、金額、收入類別、收款狀態、收款日
- [ ] 可依收款狀態篩選「待收款」「已收款」
- [ ] 新公司（尚無任何收入）→ 顯示引導空狀態與「新增收入」入口
- [ ] 收入清單**不會**顯示被丟進垃圾桶的紀錄

## 2. 手動新增收入

- [ ] 右上「新增收入」→ 出現表單；欄位至少包含：發票／收據、客戶、統一編號、發票號碼、金額、稅率、稅額、開立日、收入類別、收入科目（選填）、附件、備註
- [ ] 收入類別下拉**只顯示收入類別**，不會混進支出類別
- [ ] 新公司第一次使用，收入類別下拉已有草稿選項：**銷售收入、服務收入、利息收入、其他收入**
- [ ] 必填欄位（例如金額、開立日、客戶、收入類別）留空按儲存 → 出現錯誤提示，表單不關
- [ ] 收款狀態預設為「待收款」；若當下已收到，可直接改為「已收款」並填收款日
- [ ] 儲存成功 → 出現「已新增收入」提示、回到清單並看到該筆

## 3. 收入品項明細

- [ ] 新增收入時可加入多筆品項：品名、數量、單價、小計
- [ ] 單價 × 數量 的小計由系統自動計算，使用者**不能**手動改小計
- [ ] 全部品項小計加總應等於收入總額（若含稅規則不同於支出，以金額欄為主，但需與品項總和一致，不能相差）
- [ ] **類別掛在整筆收入上**，單一品項**沒有**類別欄位
- [ ] 刪除某品項 → 總額即時重算

## 4. 拍照 OCR 新增收入

- [ ] 新增收入時可選「拍照 / 上傳收據」
- [ ] 辨識完成後 → 可辨識欄位（例如金額、開立日、客戶、發票號碼）自動填入表單
- [ ] 辨識結果可人工修改後再儲存
- [ ] 若辨識失敗 → 顯示提示並允許使用者改用手動輸入，流程不中斷
- [ ] 原始照片以附件形式保留在這筆收入上

## 5. 文件上傳辨識電子發票

- [ ] 新增收入時可上傳電子發票檔案（例：PDF、XML 等）
- [ ] 辨識後對應欄位（金額、稅率、稅額、發票號碼、開立日等）自動帶入
- [ ] 檔案保留在這筆收入的附件區
- [ ] 若無法辨識 → 顯示提示並允許人工修補，不會把表單清空

## 6. Excel 匯入收入

- [ ] 收入管理頁有「Excel 匯入」入口
- [ ] 匯入前可下載範本（欄位與單筆新增表單對齊）
- [ ] 匯入時若有欄位缺漏、格式錯誤 → 顯示錯誤明細（第幾列、什麼問題），不會部分成功部分失敗造成混亂
- [ ] 匯入成功 → 新增的收入出現在清單，收款狀態依匯入檔案帶入（未填則為「待收款」）
- [ ] 匯入的品項小計正確加總

## 7. 編輯收入（含已收款）

- [ ] 待收款的收入可編輯任一欄位
- [ ] **已收款的收入也可編輯**（例如改金額、改客戶、改類別）
- [ ] 編輯後儲存 → 系統保留「變更前」「變更後」內容於稽核日誌（詳見第 14 節）
- [ ] 垃圾桶內的收入**沒有**編輯按鈕

## 8. 收款狀態切換（待收款 ↔ 已收款）

**待收款 → 已收款**
- [ ] 任何時候都可切換為已收款，不需填寫原因
- [ ] 切換時可填收款日；不填則採預設（例：今日）
- [ ] 切換後原本的欄位（金額、客戶、類別、備註、附件等）**全部保留，沒有任何欄位被清空**

**已收款 → 待收款（切回）**
- [ ] 任何時候可切回待收款
- [ ] 切回後，收款日**資料仍保留**（寫在稽核日誌裡），只是**畫面上隱藏實際收款日**，只顯示預計日期
- [ ] 再度切回已收款 → 之前的收款日資料仍在，不需重填

**顯示規則**
- [ ] 待收款的紀錄在清單／詳情頁上**看不到**實際收款日欄位
- [ ] 已收款的紀錄則顯示實際收款日
- [ ] 以上動作全程記錄在稽核日誌

## 9. 刪除收入與垃圾桶

**刪除條件**
- [ ] 待收款的收入 → 可直接刪除，進入垃圾桶
- [ ] 已收款的收入 → **沒有「刪除」入口**；需先切回待收款才能刪除
- [ ] 嘗試用其他方式刪除已收款紀錄 → 操作被擋

**垃圾桶行為**
- [ ] 收入管理頁有「垃圾桶」入口
- [ ] 垃圾桶內的紀錄**不計入**任何統計（儀表板、損益報表、現金流報表）
- [ ] 垃圾桶內的紀錄**不可編輯**，但可「還原」或「永久刪除」
- [ ] 點「還原」→ 回到原本的清單，狀態回到被丟進垃圾桶之前的狀態
- [ ] 點「永久刪除」→ 需二次確認；確認後紀錄完全消失，無法再還原
- [ ] 垃圾桶內的收入不會出現在收入類別、客戶、發票號碼等任何搜尋結果中

## 10. 支出端行為對齊（本次連動改動）

> 收入上線時，支出要同步改成與收入一致的規則，否則「收支行為一致」驗收不過。

**軟刪除與垃圾桶**
- [ ] 刪除待付款的支出 → **不會立刻從資料庫消失**，改為進入垃圾桶（新行為）
- [ ] 支出管理頁有「垃圾桶」入口，與收入垃圾桶分開顯示（或同頁分頁）
- [ ] 支出垃圾桶的還原／永久刪除行為與收入一致（詳見第 9 節）
- [ ] 已付款的支出 → 沒有刪除入口，需先切回待付款才能刪

**狀態切回不清資料**
- [ ] 已付款的支出切回待付款 → **實際付款日、付款人資料全部保留**（舊版會清空，新版不會）
- [ ] 畫面上在待付款狀態時隱藏「實際付款日」與「付款人」，只顯示預計付款日
- [ ] 再度切回已付款 → 之前的實際付款日與付款人仍在，不需重填

## 11. 類別管理：支出類別與收入類別分開

- [ ] 進入後台「系統 > 類別管理」頁，上方有分頁：「支出類別」「收入類別」
- [ ] 兩邊的清單、使用中/已停用、新增、停用、拖曳排序行為各自獨立（支出改名不影響收入，反之亦然）
- [ ] 收入類別可選填「收入科目」欄位（與支出類別的會計科目對應）
- [ ] 新增收入時的類別下拉**只拿收入類別**
- [ ] 新增支出、新增代墊款時的類別下拉**只拿支出類別**
- [ ] 預算設定只能選**支出類別**，收入類別**不會**出現在預算頁
- [ ] 支出類別的其他行為（停用、改名對歷史紀錄的影響、使用筆數顯示等）請同步跑一次 `QA_類別管理.md`

## 12. 稽核日誌

- [ ] 後台「系統」群組底下有「稽核日誌」頁（僅管理員可見）
- [ ] 下列動作都會留下一筆紀錄（含時間、操作人、對象、變更前後內容）：
  - [ ] 收入新增、編輯、刪除、還原、永久刪除
  - [ ] 收入收款狀態切換（待收款 ↔ 已收款）
  - [ ] 支出新增、編輯、刪除、還原、永久刪除
  - [ ] 支出付款狀態切換（待付款 ↔ 已付款）
- [ ] 稽核日誌頁**只讀**，沒有編輯或刪除按鈕
- [ ] 嘗試用其他方式修改日誌 → 操作被擋
- [ ] 已丟進垃圾桶的紀錄，其日誌仍留在稽核日誌內，不會因為紀錄被永久刪除而消失

## 13. 損益報表（以發生日計）

- [ ] 側邊欄「報表 > 損益報表」可進入
- [ ] 預設期間：本年度 12 個月，可切換到月、季、自訂區間
- [ ] 收入落在「開立日」當月；支出落在「費用日期」（發票／收據上的日期、實際消費日）當月
- [ ] 同一筆收入先後跨月收款，不會影響它在損益報表的歸屬月（永遠依開立日）
- [ ] 畫面有年度合計與預算執行率
- [ ] 垃圾桶內的紀錄**不出現**在報表數字中
- [ ] 「匯出 Excel」→ 下載檔案；畫面每一格數字與 Excel 完全一致

## 14. 現金流報表（以收付日計）

- [ ] 側邊欄「報表 > 現金流報表」可進入
- [ ] 預設期間：本年度 12 個月，可切換到月、季、自訂區間
- [ ] 收入落在「收款日」當月；支出落在「實際付款日」當月
- [ ] 一筆 1 月開立、3 月收款的收入 → 損益報表落在 1 月、現金流報表落在 3 月（兩表數字不同是正常的）
- [ ] 待收款的收入 → **不會**出現在現金流報表的月份數字中，但會出現在「待收款清單」區塊，並顯示到期日
- [ ] 待付款的支出 → **不會**出現在現金流報表的月份數字中，但會出現在「待付款清單」區塊，並顯示到期日
- [ ] 垃圾桶內的紀錄**不出現**在報表數字中
- [ ] 「匯出 Excel」→ 下載檔案；畫面每一格數字與 Excel 完全一致

## 15. 後台儀表板的改動

- [ ] 進入後台首頁（儀表板）
- [ ] 看得到以下 KPI：**本月收入、本月支出、淨額（收入 − 支出）、待收款、待付款、待簽核**
- [ ] 「待付款」數字包含「一般支出的待付款」+「已核銷但尚未撥款的代墊款」加總
- [ ] 「近 12 個月收支趨勢」大圖同時顯示收入與支出兩條線／兩種色塊
- [ ] 儀表板**已移除**「預算使用率」卡（移到預算管理頁）
- [ ] 儀表板**已移除**「最近請款」卡（因為已有「待簽核」卡）
- [ ] 垃圾桶內的紀錄不影響上述任何數字
- [ ] 前台（員工端）的儀表板**維持原樣**，仍保有「最近幾筆請款」區塊（這一改動只動後台）

## 16. 跨模組影響

**預算**
- [ ] 預算頁的類別下拉只有支出類別，不會看到收入類別
- [ ] 收入資料不影響任何預算執行率計算（預算只對應支出）

**代墊款審核流**
- [ ] 代墊款審核流程不受本次改動影響
- [ ] 代墊款撥款後建立的支出，其刪除、狀態切換行為亦套用第 10 節的新規則

**類別停用**
- [ ] 停用某收入類別 → 該類別不再出現在新增收入的下拉，但歷史收入仍顯示原類別名稱
- [ ] 停用某支出類別 → 行為同既有 `QA_類別管理.md`

## 17. 資料保留

- [ ] 新增/編輯/狀態切換/刪除/還原/永久刪除/匯入/類別調整任一動作後，重新整理頁面 → 狀態仍在
- [ ] 關閉瀏覽器再重新打開 → 狀態仍在

## 已知不覆蓋（out of scope）

- 收入「退回」流程（本版不做）
- 收入目標設定（本版不做）
- 客戶主檔（本版客戶欄位為文字輸入，不做主檔管理）
- 多筆收款（一筆收入分多次收款，本版不做）
- 報表多維度篩選與進階分析（例如依客戶、依員工交叉分析）
- 結帳與期間鎖定（本版不做；過去月份仍可被編輯）
- 收入 OCR 的辨識準確率門檻（功能流程以上述章節為準，準確率屬演算法調校議題）
- 多公司 / 多工作區情境
