# QA Checklist — OCR 辨識

> **驗證對象**：新增支出、代墊款、收入三個表單共用的憑證 OCR。
> **前置**：以管理員（支出 / 收入）或員工（代墊款）身分登入；手邊備：一張清楚的紙本統一發票、一張模糊 / 不完整的收據、一份 PDF 版發票；另備「同一張發票分段拍的 2–3 張照片」以驗衝突解析。
> **注意**：本清單只驗「功能流程與規則」；提示文字字級、按鈕顏色、彈窗樣式由設計規範統一把關，不在此列。

---

## 1. 上傳憑證並辨識（支出）

- [ ] 進入「新增支出」→ 看得到「拍照 / 上傳憑證」區塊
- [ ] 上傳一張清楚的統一發票（jpg / png / webp 任一）→ 卡片出現縮圖，預設勾選「要辨識」
- [ ] 連續上傳 2–3 張 → 皆列入「要辨識」清單；辨識按鈕文字顯示「辨識已選的 N 張」
- [ ] 點「開始辨識」→ 按鈕變成「辨識中…」且不能連點；表單欄位暫時不可改
- [ ] 辨識成功 → 日期、賣方、統編、發票號碼、金額、稅率、品項自動帶入；畫面出現「辨識完成」提示
- [ ] 使用者可直接改任一欄位後儲存，不會被辨識結果鎖住
- [ ] 檔案本身保留在憑證區，不會因為辨識而被刪除

## 2. 多張憑證：欄位衝突解析

- [ ] 上傳 2 張同一張發票分段拍的照片，兩張都辨識得出賣方名稱，但辨識結果不同（例：「福華文具行」vs「福華文具」）→ 辨識完成後**跳彈窗**列出候選值讓使用者挑
- [ ] 彈窗內顯示每個衝突欄位的所有候選值 + 來自第幾張憑證（例：「候選 1：福華文具行（憑證 1）」）
- [ ] 使用者挑好所有衝突欄位後按「確認」→ 選定值進入表單欄位
- [ ] 彈窗沒處理完就關掉 → 衝突欄位保留為空，使用者可自行手動輸入
- [ ] 兩張辨識出完全相同的賣方 → **不會**為此欄位跳彈窗

## 3. 多張憑證：品項衝突解析

- [ ] 上傳 2 張都拍到「鉛筆 單價 20」的憑證，但一張是數量 3、另一張是數量 5 → 彈窗列出兩個候選品項讓使用者挑一個保留
- [ ] 兩張都有「鉛筆 單價 20 數量 3」且小計相同 → **不會**跳彈窗，自動合併為一筆
- [ ] 兩張一張有「鉛筆」、另一張沒有 → 鉛筆直接進表單品項，不視為衝突
- [ ] 兩張品項名稱相同但單價不同（例：「鉛筆 20」vs「鉛筆 25」）→ 視為**兩個不同品項**，兩筆都進表單，不跳彈窗
- [ ] 彈窗處理完後，表單品項區看得到：單一來源品項 + 使用者挑選的衝突結果

## 4. 勾選控制：補充資料 vs 要辨識

- [ ] 多張憑證卡片各自有勾選框；取消勾選後該張**不送**辨識，當作補充資料存著
- [ ] 全部取消勾選 → 「開始辨識」按鈕顯示「請勾選要辨識的憑證」且不能點
- [ ] 補充資料的 PDF / 圖片一樣會隨支出儲存，但**不消耗配額**

## 5. 重新辨識（覆蓋確認）

- [ ] 表單已有辨識結果或使用者手動填過欄位時，再按「辨識已選的 N 張」→ 跳確認視窗「會覆蓋現有欄位」
- [ ] 選「取消」→ 保留原欄位，不送辨識、**不扣配額**
- [ ] 選「覆蓋並辨識」→ 日期 / 金額 / 賣方 / 品項等以新辨識結果取代（有衝突照跳 §2、§3 彈窗）
- [ ] 覆蓋辨識時，新結果沒讀到的欄位（例：這次沒拍到統編）→ 該欄位被清空，不會殘留舊值
- [ ] 覆蓋辨識後，辨識不會給的欄位（類別、付款狀態、帳戶等）→ 維持原本填的內容不變
- [ ] 編輯既有紀錄（含員工草稿、被駁回重送）時，**不允許**對已存檔的憑證重跑 OCR，只有新加入的憑證可勾選辨識；若要重辨請先移除原憑證再重傳

### 清除所有欄位

- [ ] 新增支出頁：先辨識或手動填一些欄位，按「清除所有欄位」→ 欄位全部回到初始狀態，上傳的憑證圖片還在
- [ ] 新增收入頁：同上，欄位全部回到初始狀態，憑證圖片還在
- [ ] 清除後憑證圖片仍可勾選並重新辨識
- [ ] 編輯既有支出 / 收入頁 → 沒有「清除所有欄位」按鈕

## 6. 代墊款（員工前台）的辨識

- [ ] 員工進「新增代墊款」→ 流程與 §1、§2 相同（上傳 → 勾選 → 開始辨識 → 衝突彈窗）
- [ ] 辨識欄位對應代墊款表單：日期、賣方、統編、發票號碼、金額、稅率
- [ ] 辨識完成 → 說明欄不會被自動填入任何文字；畫面出現「辨識完成，請核對後送出」提示
- [ ] 代墊款沒有品項 → 辨識後不會出現品項，多張憑證即使品項不同也不會跳品項衝突的選擇，彈窗只問賣方、金額等欄位
- [ ] 辨識完成後可以直接改任一欄位
- [ ] 員工看不到管理員才有的欄位

## 7. 收入的辨識

- [ ] 進「新增收入」→ 看得到「拍照 / 上傳憑證」區塊
- [ ] 上傳一張我方開給客戶的發票 → 辨識後**客戶名稱**自動帶入 `客戶` 欄、**買方統編**帶入 `統一編號`
- [ ] 辨識後不會把「我方名稱 / 我方統編」帶回表單（因為表單只收客戶端資料）
- [ ] 多張收入憑證跨欄位 / 品項衝突 → 彈窗行為同 §2、§3

## 8. 辨識失敗 / 無結果

- [ ] 上傳一張完全看不清楚的圖 → 跳提示「無法辨識，請改用手動輸入」，表單**不會**被清空
- [ ] 之前已填的欄位**保留**（辨識失敗不覆蓋原欄位）
- [ ] 可以直接繼續手動輸入 / 再換張憑證重跑
- [ ] 「辨識不出內容」（服務有回應但讀不到任何欄位）→ **照樣扣次**，畫面上的剩餘次數跟著減少
- [ ] 格式錯 / 超過大小 / 次數用完 / 服務異常造成的失敗 → **不扣次**，剩餘次數不變

## 9. 檔案限制

- [ ] 上傳超過 5 MB 的大圖 → 上傳當下就擋下並提示「單檔不得超過 5 MB」，不送辨識、不扣配額
- [ ] 一次上傳超過 5 張 → 上傳當下就擋下並提示「一次最多 5 張」
- [ ] 上傳剛好 5 MB 內的檔案、一次剛好 5 張 → 可正常上傳（與一般憑證附件上限一致）
- [ ] 上傳不支援的格式（例：zip、docx）→ 擋下並提示支援格式清單
- [ ] 違規提示後，使用者可以移除違規檔再上傳

## 10. 辨識完成後的提示

- [ ] 辨識成功（沒有衝突）→ 一律看到「辨識完成，欄位已自動帶入，請核對後儲存（代墊款為送出）」，不會逐一點名哪些欄位是推測的
- [ ] 上傳一張字跡糊的收據並辨識 → 欄位照常帶入，一樣只看到上面那個提示，沒有另外的「信心度偏低」警告
- [ ] 帶入的欄位**不會被鎖**，可以直接修改
- [ ] 多張都辨識出但值不同時，一律進衝突彈窗，不會偷偷挑其中一個

## 10-1. 特殊憑證的辨識結果

- [ ] 品項格式不固定的憑證（手寫收據、代收款證明）→ 品項區留空，由使用者自己填，不會亂填品項
- [ ] 品項是「品名 + 單價 × 數量 = 小計」且小計對得上金額的明細 → 品項正常帶入
- [ ] 電子發票上的期別（例如「115年09-10月」）→ 不會被當成日期帶入；日期欄以憑證上真正的開立日期為準，讀不到則留空
- [ ] 沒有發票號碼、也沒有「收據」字樣的單據（例如超商代收款證明）→ 不會出現發票號碼，單據類型預設為發票，使用者可自行改成收據
- [ ] 免用統一發票收據 → 單據類型為收據、稅率為免稅，不會抓出發票號碼
- [ ] 有發票號碼的憑證 → 單據類型為發票
- [ ] 單據上的流水號、訂單號、銷帳編號（例如 No.00001234、ST12345678）→ 不會被當成統編或發票號碼
- [ ] 單據上印的「數量合計」「共 3 項」、客人付的現金與找零 → 不會被當成金額
- [ ] 同時印了買受人和賣方的發票 → 賣方統編和名稱帶入賣方欄，不會把買受人（我方）帶成廠商
- [ ] 多張憑證結果不一致、其中發票號碼不同 → 衝突彈窗中「發票號碼」是一題，選項顯示完整號碼（例如 FV-63156693）；選了之後字軌和數字一起帶入
- [ ] 憑證上的日期是民國年（例如「115年10月15日」）→ 日期欄帶入 2026-10-15
- [ ] 憑證上的日期寫成「115/10/15」→ 日期欄同樣帶入 2026-10-15
- [ ] 憑證上的日期是西元（例如「2026/10/15」）→ 日期欄帶入 2026-10-15
- [ ] 讀不到的欄位 → 留空，不會用猜的內容填進去

## 10-2. 電子發票 QR Code

> **測試檔**（資料夾「quickey收據範例圖」）：S__23625731.jpg（粥師傅）、S__23576581.jpg（BEYOND）、多張發票_分頁.pdf、多張發票_同頁.pdf、S__23576580_0.jpg（7-11，QR 是網址）。

### 單張電子發票

- [ ] 上傳 QR 拍得清楚的電子發票（粥師傅）並辨識 → 發票號碼、日期、含稅金額、買賣方統編、品項都和票面一致地帶入
- [ ] 同一張發票 → 賣方名稱照舊從票面文字帶入（QR 裡沒有店名），不會是空白
- [ ] 上傳 BEYOND 發票 → 號碼 EU-04855261、日期 2026-10-18、金額 150、統編 70768666、品項「統一藥品 1×150」，與票面一致
- [ ] 店家把店名寫在品項裡（例：「粥師傅 延吉店的訂購商品」）→ 那是品項，不會被當成賣方名稱
- [ ] 買方沒有統編的發票 → 買方統編留空，不會帶入全是 0 的號碼
- [ ] 品項筆數和票面對不上、或只讀到一半品項 → 品項依票面文字辨識，不會硬塞不完整的 QR 品項
- [ ] 電子發票照片經系統壓縮後 → 仍然讀得到 QR（記錄這次測了幾張、幾張讀得到，供調整壓縮用）

### 稅額分不出來的發票

- [ ] 發票上「銷售額」和「總計」金額一樣（例：粥師傅，總計 90）→ 稅率帶入「營業稅 5%」，未稅金額（86）和稅額（4）由含稅總額自動算出，使用者可以自己修改；不會被判定成免稅
- [ ] 發票沒有把稅額分開記載 → 同上：含稅總額照常帶入，稅率預設營業稅 5%，未稅和稅額由總額自動算出，可自行修改

### QR 讀不到或不是電子發票

- [ ] QR 模糊、反光、被遮住 → 結果和原本只靠文字辨識時一樣，不會報錯，也沒有額外提示
- [ ] 7-11 代收款（QR 是網址）→ QR 被略過，結果和原本一樣，不會報錯
- [ ] 非發票的單據（收據、手寫單據）→ 結果和原本一樣
- [ ] QR 內容日期或統編明顯不合理（例如統編不是正確的統編）→ 不採用這個 QR，結果和原本一樣

### 一個檔案裡有多張發票

- [ ] 上傳「多張發票_分頁.pdf」（每頁一張、號碼不同）並辨識 → 跳出「要用哪一張發票？」的選擇題
- [ ] 上傳「多張發票_同頁.pdf」（同一頁有多張）並辨識 → 同樣跳出「要用哪一張發票？」
- [ ] 每個選項標示「憑證 N 的第 K 張發票」，並列出發票號碼、日期、金額
- [ ] 選項順序：先依頁序，同一頁由上到下、由左到右
- [ ] 選一張後按確認 → 號碼、日期、金額、統編、品項整組一起帶入，不會出現「第 1 張的金額配第 2 張的號碼」
- [ ] 沒選就關掉彈窗 → 發票號碼、日期、金額、統編、品項都留空，使用者可自行填寫
- [x] 分頁 PDF、每頁一張發票：選哪一張，賣方名稱就是那一頁的店名（例：選粥師傅那頁 → 粥師傅；選 BEYOND 那頁 → 豐東興業股份有限公司），不會出現統編是這家、店名是另一家
- [x] 同一頁有兩張發票（同頁 PDF）：賣方名稱留空，由使用者自己填（統編等仍照所選發票帶入）
- [ ] 這題之外，賣方名稱等其他欄位的衝突照原本方式挑選
- [ ] 同一次上傳多個檔案（例：一份多張發票的 PDF 加一張單張發票）→ 選項列出所有檔案裡的全部發票

### 同一張發票重複出現

- [ ] 同一張發票的 QR 分成左右兩個 → 只算一張發票，不跳選擇題
- [ ] 同一張發票在 PDF 裡出現兩次（號碼相同）→ 只算一張，不跳選擇題
- [ ] 同一張發票分別上傳兩個檔案 → 只列一次，不出現「要用哪一張發票？」

### 代墊款表單

- [ ] 員工在代墊款表單辨識多張發票的 PDF → 一樣先問「要用哪一張發票？」
- [ ] 選好發票後 → 日期、金額、統編、發票號碼帶入；**不會**帶入品項（代墊款沒有品項）
- [ ] 收入表單辨識電子發票 → 買方統編帶入「統一編號」，我方（賣方）資料不會被帶回客戶欄

### 扣次

- [ ] 一張電子發票圖片（QR 讀得到）辨識 → 照常扣 1 次，和沒有 QR 時一樣
- [ ] 多頁 PDF（每頁一張發票）辨識 → 照頁數扣次（例：3 頁扣 3 次），不會因為讀到 QR 而少扣或多扣
- [ ] 7-11（QR 被略過）辨識 → 照常扣 1 次，剩餘次數即時更新

> **備註：2026-10-28 實測因無樣本而未測的項目**（有樣本再補測）
> - 同一張發票左右兩個 QR、或同一張發票在 PDF 裡重複出現，只算一張、不跳選擇題
> - QR 模糊、反光、被遮住時結果和原本一樣
> - QR 內容日期或統編明顯不合理時不採用
> - 買方有統編的發票：收入表單買方統編帶入「統一編號」、我方統編不被帶回（現有樣本的買方都沒有統編，只驗到不會帶入全 0）
> - 一次上傳多個檔案、各含多張發票時，選項列出全部發票
> - 收入、代墊款表單按「先不選」關掉彈窗後相關欄位留空（只在支出表單驗過）
> - 店名按頁對應：同頁留空與分頁選第 1 張（粥師傅）已測過；分頁選第 2 張（BEYOND）因省額度未重送，未單獨驗

## 11. 服務異常

- [ ] 後端未設定 Google 憑證時 → 使用者點「開始辨識」會收到「辨識服務暫時無法使用」提示；表單欄位保留；配額**不會被扣**；可再試或改手動輸入

## 12. 月配額：顯示剩餘次數

- [ ] 進入「新增支出 / 代墊款 / 收入」任一表單 → 憑證區塊附近看得到「本月剩餘 N 次」字樣
- [ ] 若有加購次數，顯示「本月 N / 加購 M」
- [ ] 每次辨識完成後，剩餘次數即時更新；中途沒重新整理也會變
- [ ] 不同角色看到的數字一致（管理員 / 員工看同一家公司的剩餘次數）

## 13. 月配額：扣次規則

- [ ] 1 張圖辨識成功 → 扣 1 次
- [ ] 一次辨識 3 張圖 → 扣 3 次（即使辨識只需 3 秒；按張計，不是按請求計）
- [ ] 一份 5 頁 PDF 辨識成功 → 扣 5 次
- [ ] 混合：2 張圖 + 一份 3 頁 PDF 一次送 → 扣 5 次
- [ ] 格式錯 / 超過 5 MB / 次數用完被擋下 / 服務異常 → **全部不扣次**
- [ ] 辨識不出內容 → **會扣次**（按張 / 按頁照算），畫面剩餘次數即時更新
- [ ] 多頁 PDF 辨識完，實際頁數比剩餘次數多 → 照常顯示辨識結果，剩餘次數扣到 0 為止，不會變負數
- [ ] 月費額度優先扣光才扣加購次數
- [ ] 月初（每月 1 日）後首次辨識 → 月費額度歸零重算，加購次數保留

## 14. 月配額：超額行為

- [ ] 月費額度 + 加購皆為 0 時點「開始辨識」→ 跳提示「本月 OCR 辨識次數已用完」
- [ ] 管理員看到額度已用完的提示 → 只有文字說明，沒有「前往加購」按鈕（加購頁上線前不提供入口）
- [ ] 員工（代墊款場景）超額 → 提示改為「本月額度已用完，請聯絡管理員加購」（員工看不到加購入口）
- [ ] 超額當下**不扣配額**（本來就 0 也不會變 -1）
- [ ] 使用者可以把辨識 cancel 掉改手動輸入；表單欄位保留

## 15. 月配額：加購

- [ ] 進管理員「加購設定頁」→ 看得到目前方案月費額度、本月已用、加購剩餘
- [ ] 加購 N 次後 → 加購剩餘數字即時增加
- [ ] 加購次數**跨月不歸零**（下個月仍可用）
- [ ] 月費額度歸零重置時，**不影響**加購次數
- [ ] 加購紀錄 MVP 不保留（無歷史清單；對客訴 / 對帳場景下個版本再補）

## 16. 稽核日誌

- [ ] OCR 辨識本身**不會**產生稽核日誌（看不到「某某人辨識了什麼憑證」條目）
- [ ] 辨識結果被存成一筆支出 / 收入 / 代墊款時，該筆資源的「建立」事件照常留在稽核日誌
- [ ] 加購次數動作**會**留稽核日誌（因為涉及財務記帳；由加購頁另案驗證）

## 17. 資料保留

- [ ] 辨識後中途離開頁面 → 行為同既有新增頁的離開守衛（會提示未儲存）
- [ ] 辨識結果不會自動存草稿；離開再回來欄位會空（除非系統原本就有草稿機制）
- [ ] 配額扣減會持久化；關閉瀏覽器再開回來剩餘次數不會變多

## 已知不覆蓋（out of scope）

- 電子發票 XML 直接匯入（本次只支援圖片 + PDF）
- 一次送多張**不同**憑證、各辨識成多筆（走批次匯入另案）
- 相同檔案快取、避免重複辨識
- 辨識欄位的字元層級座標 / 高亮
- 辨識準確率門檻（屬演算法調校，不在功能驗收範圍）
- OCR 使用量歷史明細 / 匯出報表（MVP 不做）
- 字串欄位的模糊比對（例「福華文具行」vs「福華文具」會當衝突，由使用者挑選）
- 即時彈窗加購 + 線上刷卡（本版不接金流）
