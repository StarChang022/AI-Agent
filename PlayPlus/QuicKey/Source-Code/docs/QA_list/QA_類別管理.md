# QA Checklist — 類別管理模組

> **驗證對象**：管理員操作類別管理功能時，各種情境下的行為與規則是否正確。
> **前置**：以管理員身分登入後台，進入「類別管理」頁面。若要從全新狀態測試，請洽工程師協助重置資料。
> **注意**：本清單只驗證「功能流程與規則」；顏色、字級、按鈕樣式等 UI 細節由設計規範統一把關，不在此列。

---

## 1. 初次進入頁面

- [ ] 看到 **13 筆起始類別**：交通費、差旅費、伙食費、文具用品、郵電費、水電瓦斯費、廣告費、交際費、修繕費、教育訓練費、保險費、租金支出、其他費用
- [ ] 起始類別與使用者自建類別在外觀上**沒有差別**（不會有「預設」「系統」等特殊標記），也不受任何操作限制
- [ ] 頁面上方分成兩區：「使用中」與「已停用」，兩區都顯示目前數量
- [ ] 首次進入預設停在「使用中」區
- [ ] 「使用中」有 13 筆、「已停用」有 0 筆
- [ ] 清單欄位為：類別名稱、會計科目、使用筆數、操作按鈕（「本月支出」欄已不存在；要看金額請到「類別預算」頁）

## 2. 新增類別

- [ ] 點頁面右上「新增類別」→ 出現填寫視窗（類別名稱、會計科目代碼兩個欄位）
- [ ] 若「使用中」清單為空 → 出現引導訊息與「新增類別」按鈕；點該按鈕效果等同於右上的「新增類別」（同一個填寫視窗）
- [ ] 只填名稱、代碼留空 → 可成功建立
- [ ] 名稱留空按儲存 → 出現錯誤提示「請填寫類別名稱」，視窗不關
- [ ] 輸入的名稱與現有類別相同（不分大小寫、不管前後有沒有空格）→ 出現「已有同名類別」錯誤，不允許建立
- [ ] 儲存成功 → 出現「已新增類別」提示、視窗自動關閉、新類別出現在「使用中」清單最後
- [ ] 新增後「使用中」的數量 +1
- [ ] 按「取消」或關閉視窗 → 不建立任何類別

## 3. 編輯類別

- [ ] 使用中的類別可以點「編輯」→ 出現預填好的視窗
- [ ] **所有類別（含起始 13 筆）都可以編輯名稱與代碼**
- [ ] 已停用的類別**沒有編輯按鈕**；要修改需先到「已停用」區點「解除停用」
- [ ] 沒有做任何修改直接儲存 → 不會誤判為同名重複，可成功關閉
- [ ] 改成與其他類別相同的名稱 → 出現「已有同名類別」錯誤
- [ ] 名稱清空後儲存 → 出現「請填寫類別名稱」錯誤
- [ ] 儲存成功 → 出現「已更新類別」提示、清單當下反映新名稱

## 4. 停用類別

- [ ] 使用中類別可以點「停用」→ 出現確認視窗，說明：停用後不會出現在新增支出/請款下拉；該類別基本預算與當期/未來預算會被清除（過往期間保留）；舊紀錄仍會保留類別名稱
- [ ] 點「取消」→ 類別維持不變
- [ ] 點「確認停用」→ 出現「已停用」提示、該類別從「使用中」消失,出現在「已停用」
- [ ] 兩區的數量對應加減
- [ ] **所有類別(含起始 13 筆)都可以被停用**
- [ ] 停用後**不會**動到過去已建立的支出或請款紀錄
- [ ] 停用會連帶清除該類別的基本預算與當期/未來期間的預算金額(過往期間保留);詳細測試點見 QA_類別預算.md「類別停用連動」

## 5. 恢復已停用的類別

- [ ] 進入「已停用」區，該類別旁有「解除停用」按鈕
- [ ] 點「解除停用」→ 直接生效（不需再確認）、出現「已解除停用」提示
- [ ] 類別回到「使用中」區，可以再次被選用
- [ ] 停用時被清除的基本預算與當期/未來預算**不會自動恢復**；需到「預算」頁面重新設定

## 6. 搜尋

- [ ] 上方搜尋框輸入英數字類別名稱關鍵字 → 清單即時過濾（不需按 Enter）
- [ ] 輸入中文（使用注音、拼音、倉頡等中文輸入法）→ 選字過程中清單**不會**跳動；確認選字（按空白/Enter 或選詞）後才過濾
- [ ] 輸入會計科目代碼數字（例如 `6114`）→ 找到對應的類別（例如「交通費」「差旅費」）
- [ ] 大小寫、全形半形不影響搜尋結果
- [ ] 找不到任何符合的類別 → 顯示「沒有結果」的空狀態畫面
- [ ] 清空搜尋 → 恢復顯示全部
- [ ] 搜尋只作用在目前所在的分區（在「使用中」搜尋不會跨到「已停用」）

## 7. 切換「使用中」與「已停用」

- [ ] 點「已停用」→ 上方出現說明文字，提醒使用者此區的類別不會出現在新增下拉，但舊紀錄仍會顯示原名
- [ ] 兩區的類別數量隨新增/停用/恢復即時更新
- [ ] 任一區無資料 → 顯示對應的空狀態說明（例：「停用類別後會出現在這裡」）

## 8. 調整類別順序（拖曳）

> 情境：想把常用類別往上搬，讓新增支出的下拉與預算列表更順手。

- [ ] 使用中類別每列左側有拖曳把手；按住把手拖曳可調整順序
- [ ] 已停用區**沒有**拖曳把手
- [ ] 搜尋狀態下**沒有**拖曳把手（避免只在搜尋結果內排序造成誤解）
- [ ] 點了欄位標題排序後，拖曳把手暫時消失；取消欄位排序後把手恢復
- [ ] 拖曳到新位置放開 → 看到「已更新類別順序」提示
- [ ] 重新整理頁面 / 關閉瀏覽器再打開 → 順序維持
- [ ] 到「新增支出」/「新增請款」/「類別預算」看類別清單 → 都依此順序顯示
- [ ] 新增類別預設排在使用中清單的**最後**
- [ ] 拖曳使用中類別**不會影響**已停用類別的排序（之後解除停用時仍會接在使用中類別後面）

## 9. 依欄位暫時排序

> 情境：想按某一欄暫時排序看資料，不希望覆寫自訂順序。

- [ ] 使用中區可點「會計科目」欄標題排序：第一次遞增、第二次遞減、第三次回到自訂順序
- [ ] 使用中區可點「使用筆數」欄標題排序，循環同上
- [ ] 已停用區的欄位排序行為相同
- [ ] 「類別名稱」欄不開放排序（固定依自訂順序，避免與拖曳混淆）
- [ ] 排序中拖曳把手暫時消失；取消排序（點第三次或切分頁）後把手恢復
- [ ] 排序**不會儲存**：重新整理頁面後，排序取消、回到自訂順序

## 10. 資料保留

- [ ] 新增/編輯/停用/恢復/調整順序任一動作後，重新整理頁面 → 狀態仍在
- [ ] 關閉瀏覽器再重新打開 → 狀態仍在

## 11. 對其他功能的影響（跨模組）

**新增支出（後台）**
- [ ] 進入「新增支出」，類別下拉**只顯示使用中類別**，已停用的看不到
- [ ] 選擇某類別存檔後，若之後該類別被停用 → 已存在的支出仍顯示原類別名稱、不會變成空白或錯誤
- [ ] 若該類別被改名 → 已存在的支出**當下反映新名稱**

**新增請款（前台）**
- [ ] 員工在前台送出請款時，類別下拉**只顯示使用中類別**
- [ ] 過去已送出的請款紀錄，即使類別被停用或改名，仍顯示送出當下的類別名稱（改名情境會反映新名稱）

**代墊款轉支出（撥款流程）**
- [ ] 管理員審核通過並撥款、要一併建立支出時，帶入的類別欄位是原代墊款上選擇的類別

**Dashboard 預算總覽**
- [ ] Dashboard 上按類別分組的金額，即使類別被停用，只要歷史上有支出就仍顯示

**極端情境**
- [ ] 若某筆舊紀錄的類別因某種原因找不到（例如資料異常）→ 該列不會整個消失或跳錯誤，會用可辨識的方式顯示（例如原代碼字串），讓使用者知道「這裡有資料，只是類別對不上」
