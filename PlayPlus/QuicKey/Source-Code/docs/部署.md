# Quickey 部署指南

**對象**：第一次把 Quickey 搬到自架 VPS 的開發者（Peggy / 其他 maintainer）。
**時機**：目前先準備好所有 Docker 設定，等實體 VPS 到位再按本文件執行。

---

## 架構總覽

```
Cloudflare（SSL 終結、DDoS 防護、CDN）
         ↓ HTTP :80
┌────────── VPS（Ubuntu 22.04） ───────────┐
│  docker compose -f compose.prod.yml      │
│                                          │
│  web (nginx)  ←── 外網 80                │
│    │                                     │
│    ├──> 靜態檔 /usr/share/nginx/html     │
│    └──> /api/*  →  backend:80            │
│                       │                  │
│                       └──>  db:5432      │
└──────────────────────────────────────────┘
```

HTTPS 全由 Cloudflare 代理層處理，VPS 內部通訊走 HTTP。

---

## 前置準備

1. **VPS**：Ubuntu 22.04 LTS，4GB RAM 起（跑得動 Rails + Postgres + Nginx）
2. **網域**：例如 `quickey.com`，已加入 Cloudflare DNS
3. **本機**：`backend/config/master.key` 的內容（Rails credentials 解密用）

---

## Step 1：伺服器初始化

```bash
# SSH 進 VPS
ssh root@<VPS_IP>

# 建非 root user（之後都用這個 user 操作）
adduser quickey
usermod -aG sudo quickey

# 安裝 Docker
curl -fsSL https://get.docker.com | sh
usermod -aG docker quickey

# 防火牆：只開 22 / 80
ufw allow 22
ufw allow 80
ufw enable

# 切到 quickey user
su - quickey
```

> **進階**：若要防止繞過 Cloudflare 直攻 VPS，將 ufw 的 80 port 改為只放行 Cloudflare IP 段。清單見 https://www.cloudflare.com/ips/。

---

## Step 2：Cloudflare 設定

| 項目 | 設定值 |
|---|---|
| DNS A record | `@` → VPS IP，**Proxy status 打開（橘色雲）** |
| SSL/TLS → Overview | **Flexible**（最快上線）或 **Full**（進階） |
| SSL/TLS → Edge Certificates → Always Use HTTPS | 開 |

**Flexible vs Full 差別**：

- **Flexible**：瀏覽器 ↔ Cloudflare 用 HTTPS，Cloudflare ↔ VPS 用 HTTP。零設定，但 Cloudflare 到 VPS 這段流量不加密。
- **Full（strict）**：全程加密，需要 VPS 上有憑證。Cloudflare 可免費發 Origin Certificate（15 年效期），裝在 Nginx 的 443 port。

**MVP 建議先 Flexible 上線，之後再升 Full。**

---

## Step 3：Clone repo + 建 .env

```bash
cd ~
git clone <repo-url> quickey
cd quickey
cp .env.production.example .env

# 編輯 .env 填值：
# - POSTGRES_SUPERUSER_PASSWORD：openssl rand -base64 32
# - BACKEND_DATABASE_PASSWORD：   openssl rand -base64 32
# - RAILS_MASTER_KEY：            本機 cat backend/config/master.key 的內容
vim .env
```

---

## Step 4：拉起全部 service

```bash
docker compose -f compose.prod.yml up -d --build
```

首次會做幾件事：
1. Pull `postgres:16-alpine` + `nginx:1.27-alpine` + `node:20-alpine`
2. Build `backend`（Rails Dockerfile）、`web`（frontend/Dockerfile）
3. `init-db.prod.sh` 自動建 `backend` user 跟 4 個 production DB
4. Rails `docker-entrypoint` 自動跑 `db:prepare`（建 schema + 跑 migration）

---

## Step 5：驗證

```bash
# 看 container 狀態
docker compose -f compose.prod.yml ps

# 看 log
docker compose -f compose.prod.yml logs -f backend
docker compose -f compose.prod.yml logs -f web

# 本機測試（繞過 Cloudflare）
curl -I http://localhost/           # 應回 200，有 index.html
curl -I http://localhost/up          # Rails health check
curl    http://localhost/api/...     # 任一既有 API

# 瀏覽器
# https://quickey.com → 進得了前端
# https://quickey.com/up → 看到 Rails 的 health 頁面
```

## 更新流程（CI/CD 之前的手動版）

```bash
cd ~/quickey
git pull
docker compose -f compose.prod.yml up -d --build
```

Rails migration 會由 `docker-entrypoint` 自動跑。前端會重新 build。

> **自動化**：GitHub Actions push to main → SSH deploy，等實際上線穩定後再做（見 `docs/技術選型.md` §14）。

## 常用運維命令

| 動作 | 命令 |
|---|---|
| 看所有 service log | `docker compose -f compose.prod.yml logs -f` |
| 進 Rails console | `docker compose -f compose.prod.yml exec backend bin/rails c` |
| 進 psql | `docker compose -f compose.prod.yml exec db psql -U backend quickey_production` |
| 重啟後端 | `docker compose -f compose.prod.yml restart backend` |
| 停全部 | `docker compose -f compose.prod.yml down`（**不會**刪 volume） |
| 備份 DB | `docker compose -f compose.prod.yml exec db pg_dumpall -U postgres > backup-$(date +%F).sql` |

## 常見坑

**Q：改前端程式碼後重新 deploy 看不到變更？**
A：Service Worker 快取。瀏覽器開 DevTools → Application → Service Workers → Unregister，或重新整理幾次等 PWA 自動更新。

**Q：Cloudflare 顯示 521 / 522 error？**
A：VPS 沒聽到 80，或 ufw 擋掉 Cloudflare。檢查 `docker compose ps` 跟 `ufw status`。

**Q：Rails 一直連不上 DB？**
A：確認 `.env` 的 `BACKEND_DATABASE_PASSWORD` 跟 Postgres 初始化時建立的 user 密碼一致。如果中途改過，要 `docker compose down -v` 清掉 volume 讓 init script 重跑（**會清空資料**）。

**Q：怎麼看真實使用者 IP？**
A：Nginx 已設 Cloudflare real IP header 還原，Rails log 的 `remote_addr` 就是真實 IP。
