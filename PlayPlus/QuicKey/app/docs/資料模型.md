# QUICKEY 資料模型

> 對應 PRD：`docs/產品規格文件.md`、`docs/sitemap.md`
> 對應分工決策：`docs/產品延伸分工討論.md`
> 命名以領域概念為主，欄位名採 camelCase（前端 TS）；後端 DB 對應 snake_case 由 ORM 自動處理。

---

## 一、決策摘要

**代墊款請款（Reimbursement）與 支出（Expense）採用兩個獨立 model，不合併。**

理由：

1. **業務語意不同**
   - Expense：公司對**外部廠商**付款（採購、訂閱、發票）
   - Reimbursement：公司對**內部員工**還錢（員工先自費，事後請款）
2. **生命週期不同**
   - Expense：登錄 → 撥款，通常直接成立、不需簽核
   - Reimbursement：提交 → 審核 → 核准 → 撥款，走 6 狀態機
3. **會計實務就是分開**
   - 應付帳款 (Accounts Payable, 21100) 與 應付員工代墊款 (21400) 傳票科目不同
4. **擴充方向會分岔**
   - Reimbursement 未來可能加：多層簽核、金額分級、預算前置校驗
   - Expense 未來可能加：定期扣款、廠商主檔關聯、發票稅務欄位

**串接方式**：Reimbursement 核准時 → 系統自動 create 一筆 Expense (`source='reimbursement'`)，並雙向關聯（`Reimbursement.expenseId` ↔ `Expense.sourceRefId`）。

## 二、核心模型

### 2.1 Reimbursement（代墊款請款）

### 2.1.1 ReimbursementItem（代墊款品項）

| `name` | text | 品項名稱 |

### 2.4 Attachment（憑證附件）

> 2026-11-03 定案（PRD 規則 18、後續擴充規格 §9）。原本以 base64 存在各紀錄的欄位（Expense／Income／Transfer 的 `attachments` jsonb、Reimbursement 的 `receipt_urls`），改為實體檔案。

**儲存方式**：以 Rails ActiveStorage 存成實體檔案。開發與正式站先存主機硬碟（開發 `backend/storage/`，正式站 `quickey_backend_storage` volume，需納入備份），之後改 GCS 或 R2 只改設定，見 `docs/技術選型.md` §7。檔名、類型、大小記在 ActiveStorage 的資料表，不另建 Attachment 表。

**可掛的紀錄**：支出、收入、資金移轉、代墊款。每筆最多 5 張，單檔 5 MB，JPG／PNG／PDF（沿用原本的限制）。

| 欄位（每張圖檔） | 說明 |
|---|---|
| `id` | 圖檔 ID，刪除單張時使用 |
| `filename` | 原始檔名 |
| `mimeType` | 檔案類型 |
| `byteSize` | 大小（Byte），計算儲存空間用 |
| `url` | 讀取網址，需登入且限同公司，不可公開存取 |

**上傳與暫存**：
- 選擇圖檔後立即上傳，成為暫存檔，還不屬於任何紀錄；儲存紀錄時才掛上。批次匯入憑證、OCR 帶出的頁面同樣先成為暫存檔。
- 取消新增、或移除尚未儲存的圖檔時，暫存檔立即刪除，不需二次確認。
- 關閉頁面等沒能即時刪除的暫存檔，系統每天清除，建立超過 24 小時仍未掛上紀錄者刪除。
- 暫存檔不計入儲存空間。

**刪除已儲存的圖檔（編輯頁）**：二次確認後立即永久刪除，不必按儲存；之後取消編輯也不會恢復。寫入該紀錄的稽核日誌，記 `update`，變更前後列出圖檔檔名。垃圾桶內的紀錄不可編輯，所以不能刪圖；手續費支出的憑證在移轉上，從移轉刪除。適用支出、收入、資金移轉；員工編輯代墊款草稿或駁回單時，移除已存圖檔不需確認，按儲存或送出才生效（2026-11-03 用戶確認維持）。

**跟著紀錄走**：
- 進入垃圾桶：圖檔不動，仍計入儲存空間；還原後圖檔原樣回來。
- 永久刪除：圖檔一併刪除，實體檔案刪除並釋放空間。稽核日誌的完整內容只記檔名、類型、大小，不保存圖檔本身。
- 代墊款核准產生的支出，與代墊款共用同一個檔案，不重複佔用空間。從支出刪圖或永久刪除支出，只從支出拿掉，代墊款保留原圖（代墊款只能作廢，保留簽核證據）。實體檔案在沒有任何紀錄使用時才刪除。

**儲存空間**：公司所有紀錄（含垃圾桶內的紀錄與代墊款）使用的圖檔大小加總，共用的檔案只算一次，暫存檔與資料匯出產生的檔案（§3.7）不算。用量畫面與上限阻擋見後續擴充規格 §7，另開卡。

**讀取權限**：管理員可讀公司內所有圖檔；員工只能讀自己代墊款的圖檔。

**既有資料轉檔**：上線時跑一次，把既有的 base64 圖檔轉成實體檔案、掛回原紀錄，檔名不變；全部轉成功並確認可讀取後，才移除舊欄位。上線前先備份資料庫。系統搬移，不寫稽核日誌。

### 2.7 AuditLog（稽核日誌）

記錄建立、刪除（進入垃圾桶）、還原、永久刪除、編輯、狀態切換、作廢、取消作廢與資料匯出。只能新增，不能修改或刪除。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid | PK |
| `companyId` | uuid → Company | 所屬公司 |
| `targetType` | enum | `'expense'` \| `'income'` \| `'reimbursement'` \| `'account'` \| `'recurring_template'` \| `'category'` \| `'transfer'` \| `'budget'` \| `'data_export'` |
| `targetId` | uuid | 對象 ID，刪除後仍保留 |
| `action` | enum | `'create'` \| `'update'` \| `'delete'` \| `'status_change'` \| `'void'` \| `'revert_void'` \| `'restore'` \| `'purge'` \| `'export'` |
| `before` | jsonb? | 變更前內容 |
| `after` | jsonb? | 變更後內容 |
| `actorUserId` | uuid → User | 操作人 |
| `createdAt` | timestamp | 時間 |

系統自動產生的紀錄（固定收支、資金移轉手續費）與 Excel 匯入不另設 `action`，以內容中的來源標示區分；動作篩選只列上述 9 種，列表再顯示「固定收支自動產生」「Excel 匯入」等字樣。類別的停用與啟用歸 `update`。

稽核日誌列表的「對象」顯示類型＋該筆名稱：支出取賣方、收入取客戶、代墊款取申請人，空白時改用日期＋金額；帳戶、類別、固定收支範本取名稱；資金移轉取「轉出帳戶→轉入帳戶」；預算取「類別名稱＋期間」，例如「交通費 2026/11 月預算」「交通費 2026 年預算」。名稱一律顯示現在的名稱，改名不影響舊紀錄的查找；永久刪除的紀錄從日誌內容取得。已刪除的預算從日誌內容取得期間，類別名稱仍顯示類別現在的名稱，類別已永久刪除時才用日誌內的名稱。篩選只依類型。

**資料匯出**（PRD 第 24 條）：`targetType='data_export'`、`action='export'`、`targetId` 為該次 DataExport（§3.7）的 ID。每次發起匯出寫一筆，不逐筆紀錄各寫；`after` 記範圍、類型、篩選條件、筆數、是否含圖檔。`export` 只用於 `data_export`。下載不寫入。列表「對象」顯示「資料匯出＋範圍」，例如「資料匯出（支出 2026/11/01–2026/11/30）」「資料匯出（收入 全部）」「資料匯出（代墊款 勾選 5 筆）」。

**預算**：只記各期預算（§3.5 Budget），基本預算（BudgetTemplate）只是範本，套用前不影響任何數字，不寫入。
- 設定某一期的預算記 `create`，修改金額記 `update`，清除記 `delete`。預算沒有垃圾桶，清除後資料表即移除該筆，因此 `delete` 的變更前內容記完整內容（比照永久刪除），不只記刪除時間。
- 內容記類別、週期、期間起迄、金額。
- 套用基本預算時，每個受影響的預算各寫一筆（新增記 `create`、金額不同記 `update`、基本預算為 0 或沒有而清除記 `delete`，金額相同不寫），來源標示「套用基本預算」，操作人為套用者。
- 類別停用或進入垃圾桶時連帶清除當期與未來的預算，每筆記 `delete`，來源標示「類別停用或刪除連帶清除」，操作人為停用或刪除類別的人；連帶清除的基本預算不寫入。

### 2.8 RecurringTemplate（固定收支範本）

依週期自動產生待收款或待付款紀錄的範本。產生的紀錄是一般 Income 或 Expense，不屬於範本。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid | PK |
| `companyId` | uuid → Company | 所屬公司 |
| `direction` | enum | `'income'`（固定收入）\| `'expense'`（固定支出）；建立後不可修改 |
| `categoryId` | text → Category | 對應 kind 與 direction 相同的類別 |
| `accountId` | uuid → Account | 產生紀錄的收付帳戶 |
| `name` | text | 項目名稱；產生紀錄時帶入說明 |
| `documentType` | enum | `'invoice'` \| `'receipt'`（發票／收據） |
| `taxRate` | enum | 稅別，與 Expense、Income 相同 |
| `counterparty` | text | 廠商或客戶；產生紀錄時帶入 Expense.vendor 或 Income.customer |
| `taxId` | text? | 統一編號；支出為賣方，文件類型為發票時必填；收入為買方，一律選填（2026-11-10） |
| `amount` | decimal(12,2) | 每期金額（含稅），必須大於 0 |
| `frequency` | enum | `'monthly'`（每月）\| `'yearly'`（每年） |
| `dayOfMonth` | int | 1–31；31 等同月底（較短的月份產生在當月最後一天）；每年週期選到不存在的日期時同樣產生在當月最後一天 |
| `monthOfYear` | int? | 每年週期才需要，1–12 |
| `startMonth` | text | 開始月份，格式 `YYYY-MM`，不早於 2000-01，沒有上限；已產生過紀錄後不可修改，紀錄之後全部刪除仍不可修改 |
| `endMonth` | text? | 結束月份，格式 `YYYY-MM`，不早於 `startMonth`；空白表示持續產生 |
| `lastGeneratedPeriod` | text? | 已產生到的期數（例如 `2026-10`），用於避免重複產生 |
| `resumePeriod` | text? | 內部欄位，不對外回傳。還原、延長或修改週期後，產生期數的起點；此前的期數不補 |
| `deletedAt` | timestamp? | 刪除時間（進入垃圾桶） |
| `createdBy` | uuid → User | 誰建立的 |
| `createdAt` / `updatedAt` | timestamp | — |

**產生規則**
- 每天檢查一次，依 `lastGeneratedPeriod` 之後、且在 `startMonth` 到 `endMonth` 之間、週期日已到的期數產生紀錄；日期以台北時區判斷。
- 同一範本的同一期只能有一筆紀錄，以 `recurringTemplateId` + `recurringPeriod` 唯一，排程重跑不會重複。
- 已刪除（有 `deletedAt`）或已到期的範本不產生。沒有下一期可產生時視為到期；`startMonth` 到 `endMonth` 之間沒有任何一期時不可建立。
- 修改金額、週期、名稱只影響尚未產生的期數。
- 產生的紀錄帶入範本欄位，未稅金額與稅額依金額和稅別計算；發票號碼與附件留空。`date` 為週期日；文件類型為發票時 `invoiceDate` 同 `date`。應付日期比照一般支出，以產生當天為登錄日，依公司付款日規則計算；應收日期同 `date`。
- 開始月份在過去時，建立範本會補齊已過的期數，送出前先提示將補產生幾筆；補齊的紀錄一律待收款、待付款，應付日期以建立範本當天為登錄日。
- 範本從垃圾桶還原、或歷史範本的 `endMonth` 往後延時，不補中間的期數，從當期開始產生；當期週期日已過且尚未產生的，立即產生當期一筆。當期指今天所在的月份，每年週期只有今天所在的月份是週期月份時才有當期。範本使用的類別在垃圾桶或已停用時，兩者都不可執行。
- 修改週期後，已過的期數不補，從當期開始依新週期產生。每年週期改月份時，當年已產生過就從下一年開始。修改週期或週期日後，當期週期日已過且尚未產生時，送出前先提示筆數，儲存時立即產生，不等每日檢查。
- 產生的紀錄 `createdBy` 與稽核日誌操作人為範本建立者，稽核動作標示「固定收支自動產生」。
- 範本永久刪除時，已產生紀錄的 `recurringTemplateId` 清空，`recurringPeriod` 保留。
- 範本明細不含垃圾桶內的紀錄。

### 2.9 Account（帳戶）

公司的收付帳戶。首版只需帳戶名稱與起始金額，不記錄銀行名稱、分行與銀行帳號，只支援新台幣；於後台「系統」群組的「帳戶設定」頁管理。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid | PK |
| `companyId` | uuid → Company | 所屬公司 |
| `name` | text | 帳戶名稱，例如「永豐-總公司」「零用金」；公司內不可重複 |
| `openingAmount` | decimal(12,2) | 起始金額，不可為負，視為起始月份月初的餘額；可修改，需二次確認並寫入稽核日誌 |
| `openingMonth` | date | 起始月份（該月第一天），建立時可選，預設當月，範圍 2000-01 至當月；可修改，需二次確認並寫入稽核日誌；往後調超過已有的收付款時仍可儲存，確認時提示有幾筆會不計入現金流；不可調到垃圾桶外的資金移轉日期之後 |
| `deletedAt` | timestamp? | 刪除時間；已被收支或資金移轉紀錄引用（含垃圾桶內的紀錄），或被固定收支範本使用（含歷史與垃圾桶內的範本）的帳戶不可刪除；垃圾桶內仍佔用名稱 |
| `currency` | text | 首版固定為 `TWD` |
| `createdAt` / `updatedAt` | timestamp | — |

各月的期初、期末不存檔，由起始金額、收付款與資金移轉即時計算，期初等於上月期末。

### 2.10 Transfer（資金移轉）

帳戶之間的資金移轉，不屬於收入或支出，不計入損益、預算與儀表板，只影響帳戶餘額。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid | PK |
| `companyId` | uuid → Company | 所屬公司 |
| `fromAccountId` | uuid → Account | 轉出帳號 |
| `toAccountId` | uuid → Account | 轉入帳號（不可與轉出相同） |
| `amount` | decimal(12,2) | 移轉金額，必須大於 0 |
| `fee` | decimal(12,2) | 手續費，不可為負，預設 0 |
| `transferDate` | date | 移轉日期；不可早於轉出或轉入帳戶的 `openingMonth`，新增、編輯、還原都檢查 |
| `note` | text? | 備註 |
| `attachments` | Attachment[] | 憑證（共用 §2.4 結構） |
| `feeExpenseId` | uuid? → Expense | 手續費目前對應的支出；手續費為 0 時為空 |
| `createdBy` | uuid → User | 誰登錄的 |
| `deletedAt` | timestamp? | 刪除時間（進入垃圾桶） |
| `createdAt` / `updatedAt` | timestamp | — |

**手續費規則**：手續費大於 0 時自動產生一筆支出：`source='transfer_fee'`、`transferId` 指回移轉、類別為系統保留的手續費類別（§3.4）、`date`、`plannedPayoutDate` 與 `paidAt` 為移轉日期、帳戶為轉出帳戶、`payoutStatus='paid'`、`paidBy` 與 `createdBy` 為操作人、`documentType='receipt'`、`taxRate='exempt_0'`、未稅金額等於手續費、稅額 0、`note` 為「資金移轉手續費」，並記錄於 `feeExpenseId`。編輯移轉時同步更新該支出的金額、日期（`date`、`plannedPayoutDate`、`paidAt`）、帳戶；手續費改為 0 時，該支出移入垃圾桶並清空 `feeExpenseId`，再填手續費時產生新的一筆；刪除移轉時，該支出一併移入垃圾桶，還原移轉時一併還原；永久刪除移轉時，所有 `transferId` 指向它的支出一併永久刪除。

`source='transfer_fee'` 的支出只能經由移轉異動，直接呼叫編輯、切換狀態、刪除、還原的 API 一律擋下。例外：`feeExpenseId` 已清空、留在垃圾桶的支出可單獨永久刪除。「上一次使用的帳戶」排除此來源。

**計入現金流的範圍**：垃圾桶外的移轉一律計入。`transferDate` 不會早於兩個帳戶的 `openingMonth`：移轉端擋日期，帳戶端擋起始月份往後調，所有帳戶的合計永遠相抵。

## 三、支援模型

### 3.1 Company（公司）

多家公司共用同一系統，各公司資料以 `companyId` 隔離；每家公司由超級管理員以 Email 註冊建立。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid | PK |
| `name` | text | 公司名（不強制 unique；同名公司真實存在） |
| `companyType` | enum | `'limited'`（有限公司）\| `'corporation'`（股份有限公司）\| `'studio'`（工作室）\| `'individual'`（個人） |
| `taxId` | text? | 統編（選填；工作室/個人可能沒有。若填則需通過 8 碼台灣統編檢核） |
| `plan` | enum | `'free'`（免費版）\| `'team'`（團隊版）\| `'enterprise'`（企業版）。封測期間新公司預設 `'team'`，既有公司一律改為 `'team'`（2026-11-10）。依方案的上限見下方「方案上限」 |
| `payoutDay` | int (1–31) \| null | 每月付款日。1–31；31 等同月底（遇天數少的月份改在該月最後一天）。null = 關閉付款日（應付日期預設為發生日期；待付款仍依應付日期分組）。新公司預設 5。 |
| `createdAt` | timestamp | — |

**方案上限（Company.plan）**（2026-11-10 定案）

| | free | team | enterprise |
|---|---|---|---|
| 員工人數（不含管理員） | 0 | 5 | 10 |
| 每月辨識次數 | 30 | 160 | 500 |
| 儲存空間 | 3 GB | 10 GB | 30 GB |

- 員工人數上限由後端依 `plan` 判斷，API 回傳給前端顯示，前端不寫死數字。
- 每月辨識次數仍存在 `ocrMonthlyQuota`（可個別調整）。封測期間預設改為 160，仍是舊預設 50 的公司一併改為 160，個別調整過的不動；本月已用次數不歸零。
- 儲存空間上限的阻擋另開卡（見 §2.4 儲存空間）；免費版關閉的功能（代墊款請款、人員管理等）與方案切換、付款，待正式收費前再做。

**付款日規則（Company.payoutDay）**

- **用途**：決定 `Expense.plannedPayoutDate`（應付日期）的 snapshot 值——建立支出時從登錄當天（含當天）、代墊款核准產生支出時從核准當天（含當天）往後找最近的一個 `payoutDay`，算一次寫入 `plannedPayoutDate` 與 `autoPlannedPayoutDate`。`payoutDay` 為 null 時兩者分別為 `date` 與 null。（2026-11-05 起；原為「登錄月的下個月 `payoutDay` 號」）
- **範例**：`payoutDay=25`。11/5 登錄 → 11/25；11/25 登錄 → 11/25；11/26 登錄 → 12/25。
- **月底處理**：`payoutDay=31` 或 29/30 遇到該月天數不足時，退到該月最後一天。
- **變更語意（「只影響之後」）**：管理員改 `payoutDay` 時「不動」任何既有支出（含草稿、pending、paid、代墊款）的 `plannedPayoutDate` 與 `autoPlannedPayoutDate`。新規則只套用在之後新登錄 / 核准的支出；若要改既有 pending 支出的應付日期，走「調整應付日期」(adjust-payout-date) 或在編輯畫面修改。此設計避免管理員改一次設定就意外動到行政人員已排好的本月批次。
- **「改回自動排程」還原策略**：以 `Expense.autoPlannedPayoutDate` 為源頭還原 `plannedPayoutDate`，**不**重算快照。這確保同一筆支出的「自動值」是終身不變的屬性：即使中間經歷了手動調整＋改回，拿到的仍是登錄當下的原始自動值，不會因公司規則變動而漂移。
- **不需要歷史表**：因為 `plannedPayoutDate` 已 snapshot 到 Expense 本身，後端只需保存目前的 `payoutDay`；查詢「下一批」「逾期」直接讀欄位、可 index、不用 join。
- **變更紀錄（後端建議建）**：獨立於計算邏輯外的 audit 表，與 `payoutDay` 更新在同一 transaction 內寫入；供管理員追溯歷次變更使用。
  ```
  payout_day_change_log
  ├─ id
  ├─ company_id   uuid → Company
  ├─ changed_at   timestamp
  ├─ from_day     int | null
  ├─ to_day       int | null
  └─ changed_by   uuid → User
  ```
- **「本月」時區**：一律以公司時區（Asia/Taipei）計算，不依使用者裝置時區。

### 3.2 User（帳號）

系統只有兩種帳號：**超級管理員（1 個）** + **員工（≤10 個）**。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid | PK |
| `companyId` | uuid → Company | 所屬公司 |
| `email` | text (unique) | 登入信箱 |
| `passwordHash` | text | bcrypt/argon2 雜湊 |
| `name` | text | 姓名 |
| `role` | enum | `'admin'` \| `'employee'`（`admin` 即超級管理員，一家公司 1 名） |
| `title` | text? | 職稱 |
| `phone` | text? | 聯絡電話 |
| `status` | enum | `'active'` \| `'suspended'` \| `'invited'` \| `'left'` |
| `lastLoginAt` | timestamp? | — |
| `createdAt` / `updatedAt` | timestamp | — |

**約束**：
- 每家公司 `role='admin'` 至少 1 個、目前僅 1 個
- 每家公司 `role='employee' AND status IN ('active','invited')` 的人數上限依 `Company.plan`（§3.1 方案上限：free 0、team 5、enterprise 10）；已達上限不能再邀請，也不能把停用的員工重新啟用；超過上限時不停用既有員工（2026-11-10）

### 3.2.1 SignupToken（註冊 email 驗證 token）

管理員自助註冊流程專用。用戶輸入 email → 產 token → 寄驗證信 → 用戶點連結 →
帶 token 進註冊頁完成公司資料 + 密碼 → 消耗 token 建 Company + admin User。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid | PK |
| `email` | text | 註冊信箱（小寫、trimmed） |
| `tokenDigest` | text (unique) | SHA256(raw token)；raw token 只在寄信時可見 |
| `provider` | enum | `'email'`（本地 email 驗證）\| `'google'`（Google OAuth，Stage D 才用到；預留） |
| `expiresAt` | timestamp | 過期時間（TTL = 30 分鐘） |
| `verifiedAt` | timestamp? | Step 2 GET verify 成功時填入；不代表 token 被消耗 |
| `consumedAt` | timestamp? | Step 3 complete 成功時填入；表示 token 已使用 |
| `createdAt` / `updatedAt` | timestamp | — |

**行為**：
- 每次 `generate_for(email)` 會把該 email 未消耗（`consumedAt IS NULL`）的舊 token 全部標為 `expiresAt = now`，避免用戶手上多封信互相干擾
- Step 2 GET verify 只驗證有效性、不消耗，用戶可重整註冊頁
- Step 3 complete 成功 → `consumedAt = now`；同一 token 不可再用

### 3.3 Invitation（邀請）

超級管理員邀請員工用；email 邀請 token 流程。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid | PK |
| `companyId` | uuid → Company | 邀請所屬公司 |
| `email` | text | 被邀請人信箱 |
| `token` | text (unique) | 隨機字串（32+ chars） |
| `invitedByUserId` | uuid → User | 誰發的邀請 |
| `expiresAt` | timestamp | 過期時間（預設 3 天） |
| `acceptedAt` | timestamp? | 接受時間；null 表示未接受 |
| `revokedAt` | timestamp? | 撤回時間 |
| `lastSentAt` | timestamp | 最後一次寄出邀請信的時間；重新寄送間隔至少 1 分鐘 |

**重新寄送與過期**（2026-11-10 定案）：

## 四、狀態機

### 4.1 Reimbursement.status（6 狀態）

沿用 ExpensePal 時期原設計。

```
                submit
       draft ──────────► in_review
         ▲                  │
         │ resubmit         ├──── approve ────► approved ──── pay ────► paid
         │                  │
         └──── rejected ◄───┘

         approved ──── void ────► voided   （撥款前可作廢）
```

| 狀態 | 中文 | 誰能操作 | 動作 |
|---|---|---|---|
| `draft` | 草稿 | 員工 | 只有員工能看；可編輯、submit、刪除 |
| `in_review` | 簽核中 | 超級管理員 | 可 approve、reject |
| `rejected` | 駁回 | 員工 | 員工可修改後 resubmit（回到 in_review） |
| `approved` | 已核銷（待撥款） | 超級管理員 | 系統已產生 Expense；可標記 paid；可 void |
| `paid` | 已發放 | — | 終態，不可變更 |
| `voided` | 已作廢 | — | 終態；只有 approved 狀態能 void |

**約束**：
- `draft` 狀態的 Reimbursement 只有申請人自己看得到；後台列表、tab 統計、儀表板一律排除
- `paid` 之後不可 void（會計已入帳）

### 4.2 Expense.payoutStatus（2 狀態）

```
pending ──── pay ────► paid
```

- 一般支出（`source='general'`）：建立時可直接 `paid`（若當下已付款）或 `pending`
- 代墊款轉來的（`source='reimbursement'`）：建立時 `pending`，撥款後 `paid`

### 4.3 刪除、還原、作廢、編輯與狀態切換

規則來源見 PRD 第 10、11、18 條，本表為動作對照。

| 動作 | 對象 | 條件 | 留紀錄 |
|---|---|---|---|
| 刪除（進入垃圾桶） | 支出、收入 | 目前為待付款、待收款 | 稽核日誌 |
| 刪除（進入垃圾桶） | 固定收支範本、資金移轉 | 任何時候 | 稽核日誌；移轉的手續費支出一併移入 |
| 刪除（進入垃圾桶） | 類別 | 未被未到期範本使用；不是系統保留類別 | 稽核日誌 |
| 刪除（進入垃圾桶） | 帳戶 | 未被收支、資金移轉或固定收支範本引用 | 稽核日誌 |
| 還原 | 垃圾桶內的支出、收入、類別、帳戶 | 任何時候 | 稽核日誌 |
| 還原 | 垃圾桶內的固定收支範本 | 使用的類別不在垃圾桶且未停用 | 稽核日誌 |
| 還原 | 垃圾桶內的資金移轉 | 移轉日期不早於兩個帳戶的起始月份 | 稽核日誌；手續費支出一併還原 |
| 永久刪除 | 垃圾桶內的支出、收入、固定收支範本、帳戶 | 使用者確認 | 稽核日誌保存完整內容，資料表移除該筆 |
| 永久刪除 | 垃圾桶內的類別 | 使用者確認；未被支出、收入、代墊款、固定收支範本或過往預算使用 | 稽核日誌保存完整內容，資料表移除該筆 |
| 作廢 | 代墊款 | 撥款前 | 簽核歷程；連動支出移入垃圾桶 |
| 取消作廢 | 代墊款 | 已作廢；回到作廢前的狀態 | 歷程；連動支出還原 |
| 永久刪除 | 垃圾桶內的資金移轉 | 使用者確認 | 稽核日誌保存完整內容，資料表移除該筆；指向它的手續費支出一併永久刪除 |
| 編輯 | 所有紀錄（含已付款、已收款） | 任何時候；垃圾桶內的紀錄不可編輯 | 變更前後內容 |
| 刪除圖檔 | 支出、收入、資金移轉的已儲存圖檔 | 編輯頁二次確認後立即永久刪除；垃圾桶內的紀錄不可 | 稽核日誌記 `update`，變更前後列出圖檔檔名；規則見 §2.4 |
| 所有動作 | `source='transfer_fee'` 的支出 | 只能經由移轉異動；`feeExpenseId` 已清空的可單獨永久刪除 | 稽核日誌，標示資金移轉手續費自動產生 |
| 切換收付款狀態 | 支出、收入 | 任何時候，日期可填；切換時資料全部保留 | 從什麼改成什麼、日期、人、時間 |

### 5.1 一般支出登錄
```
行政 → ExpenseFormView
     ├─ 主表單（單筆）：憑證上傳 jpg/png → stub OCR 帶入 → 手動核對／填寫

```

### 5.2 代墊款完整流程
```
員工 → 提交請款 → POST /reimbursements { status: 'draft' }
                → PATCH /reimbursements/:id/submit → in_review

超級管理員 → 審核清單 → PATCH /reimbursements/:id/approve
             ├─ Reimbursement.status = 'approved'
             ├─ CREATE Expense (source='reimbursement', sourceRefId=..., payoutStatus='pending',
             │                  date=incurredAt, invoiceDate=Reimbursement.invoiceDate)
             ├─ 複製 ReimbursementItem → ExpenseItem
             └─ Reimbursement.expenseId = 新 Expense.id
             
             或 → PATCH /reimbursements/:id/reject { reason }

超級管理員 → 撥款清單 → PATCH /expenses/:id/pay { payoutDate, method }
             ├─ Expense.payoutStatus = 'paid'
             └─ 若 source='reimbursement'：連動更新 Reimbursement.status = 'paid'
```

```
超級管理員 → 後台員工管理 → 「邀請」→ 填 email + name
          → CREATE Invitation { token, expiresAt: now + 3d }
          → 寄 email 含連結: https://.../invite/accept?token=xxx

```

### 5.4 Excel 匯入（支出／收入）

> 2026-10-29 確認。首版只解析**標準範本**；之後要支援使用者自己的格式（自動猜欄位 + 使用者調整），所以流程要分段，見本節「擴充設計」。

**範圍**：支出列表與收入列表各有「匯入 Excel」，僅超級管理員可用。只收 `.xlsx`，單檔 ≤ 5 MB、最多 1,000 列（不含標題列）；讀第一個工作表。匯入的紀錄沒有憑證附件，之後可在編輯時補。

**流程（整批匯入）**：
```
管理員 → 匯入視窗 → 下載範本（選用）→ 上傳 .xlsx
      → POST /expenses/import/preview（或 /incomes/import/preview）  ← 只解析，不寫入
         回：每筆的 Excel 列號、內容摘要、狀態（可匯入／補預設值／不計入現金流／不匯入 + 原因）、找不到的類別名稱清單
      → 視窗顯示預覽表 + 類別對應（每個找不到的名稱選「對應到既有類別」或「新增此類別」，預設新增）
      → 按「匯入 N 筆」→ POST /expenses/import  { file, categoryMapping }  ← 後端重新解析同一檔案後寫入
         所有可匯入的紀錄在同一個交易內建立；任一筆寫入失敗就全部不建立
      → 完成畫面：成功筆數、未匯入的列（Excel 列號 + 原因）、補了預設值或需要留意的列（Excel 列號 + 說明）
```
- 完成畫面關閉後不保留清單（2026-10-29 用戶確認：不在列表加「待確認」標記）。
- 每筆照一般新增寫稽核日誌，動作標示來源為 Excel 匯入。匯入時新增類別記 `create`、重新啟用類別記 `update`，同樣標示來源，操作人為匯入者。應付日期、應收日期等自動欄位照手動新增的規則計算。
- 首版不偵測重複匯入。

**範本**：由後端產生（`GET /expenses/import/template`、`GET /incomes/import/template`），和解析共用同一份欄位定義，避免範本標題與解析規則不一致。範本含「填寫說明」工作表，示範多品項、無品項、不填單據編號三種寫法。前端匯入視窗提供「下載範本」按鈕。

| 主檔（同一單據填在第一列） | 發生日期（收據必填）、發票日期（發票必填）、文件類型*、廠商*、統一編號（發票必填）、發票號碼（發票必填）、類別*、稅別、未稅金額、稅額、含稅金額（未稅、含稅至少填一個）、應付日期、付款狀態、實付日期、說明 | 發生日期（收據必填）、發票日期（發票必填）、文件類型*、客戶*、統一編號（選填）、發票號碼（發票必填）、類別*、稅別、未稅金額、稅額、含稅金額（未稅、含稅至少填一個）、應收日期、收款狀態、實收日期、說明 |
| 品項（每列一個） | 品名、數量、單價、小計 | 品名、數量、單價、小計 |

**必填原則**：必填欄位空白或無效，該筆**不匯入**（完成畫面列出 Excel 列號與原因），不再補值後匯入。收據不需要的欄位（統一編號、發票號碼）不必填。

帳戶（§2.9）上線後再加「帳戶」欄，空白時帶入上一次使用的帳戶；找不到或在垃圾桶時，由使用者在預覽畫面選擇帳戶，同一個帳戶名稱選一次，同名的列全部套用（PRD 規則 20）。公司沒有任何帳戶時不能匯入，提示先建立帳戶。實收／實付日期早於帳戶起始月份的列照常匯入，帳戶已確定的列在預覽標示，完成畫面列出不計入現金流的筆數。

**欄位比對**：依**標題名稱**找欄，不依位置（標題去頭尾空白、忽略 `*`）。欄位順序可調換、多出的欄位忽略。缺少**發生日期、發票日期、文件類型、廠商（客戶）、統一編號、發票號碼、類別、未稅金額、含稅金額**任一標題時整份退回，提示「找不到『發生日期』欄，請使用範本」（2026-11-05 改名前的舊標題「日期／開立日／付款日／收款日」不相容，產品尚未上線）；標題必須存在，格子依必填規則判斷。其他標題缺少時視為該欄全空。檔案沒有任何資料列時也整份退回。

**列號**：預覽與完成畫面的列號為 Excel 實際列號（標題列為第 1 列）。

**列出的範圍**：「補預設值並列出」只針對**有填但看不懂**的值；空白套用預設值（例如稅別空白 → 應稅、付款狀態空白 → 待付款）屬正常用法，不列出。例外：已付款／已收款但實付／實收日期空白仍會列出。

**預覽時移除**（2026-10-29 用戶新增）：預覽表每一筆可匯入的單據最右側有「✕」按鈕（icon-only，需 aria-label，例如「移除第 5 列」），點擊後該筆移出本次匯入、不會建立；預覽上方顯示「已移除 N 筆」並可復原。「不匯入」的列不顯示此按鈕。移除後：匯入筆數即時更新；某個找不到的類別名稱若只剩被移除的單據使用，就從類別對應區消失，也不會新增該類別。import API 帶 `excludedRows`（被移除單據的第一列 Excel 列號，最多 1,000 個正整數）；列號對不上任何可匯入單據的第一列時（例如預覽後換了檔案）整次不匯入，提示「檔案內容與預覽不同，請重新預覽」。前端換檔或重新預覽時清空移除清單。完成畫面另顯示「使用者移除 N 筆」。

**匯入按鈕**：可匯入筆數為 0 時按鈕不可按，提示沒有可匯入的資料。

**類別對應補充**：
- 類別對應區只列出**會被匯入**的單據用到的名稱；只被「不匯入」或使用者移除的單據用到的名稱不列出、不要求選擇，也不會新增。
- 類別空白的列在對應區合併成一項「（未填類別）」，由使用者選擇對應到哪個類別（不可選新增）。
- 名稱超過 50 字（類別名稱上限）時不可選新增，只能對應到既有類別。
- 名稱與本公司**停用中**的類別相同時，選項為「重新啟用此類別」（預設）或「對應到既有類別」，不提供新增（類別名稱在公司內不可重複，含停用的）。
- 按下匯入時，若對應到的類別已被停用或刪除，整次不匯入，提示「類別已變更，請重新預覽」。

**分組規則**：
- 單據編號相同的列合併成一筆，每列是一個品項；不需相鄰。單據編號只用來分組，不存入系統。
- 單據編號空白的列自成一筆。
- 主檔欄位以該單據第一列為準；後面的列有填且不同時，以第一列為準並在完成畫面列出。
- 品項欄全空 = 沒有品項。

**值轉換與錯誤分類**：

| 欄位 | 接受的寫法 | 無法判讀時 |
|---|---|---|
| 發生日期 | Excel 日期、`2026/10/29`、`2026-10-29`、民國 `115/10/29`；年份 2000 年到今年 + 1 年。發票空白時帶發票日期 | 收據空白，或有填但無法判讀 → **不匯入** |
| 發票日期 | 同發生日期寫法 | 發票：空白或無法判讀 → **不匯入**。收據：不帶入（有填則列出） |
| 應付日期／應收日期 | 同發生日期寫法；空白時依 PRD 第 23 條預設規則（應付以匯入當天為登錄日依付款日計算，應收為發生日期）。有填且與自動值不同時視為手動修改 | 無法判讀 → 依預設規則並列出 |
| 文件類型 | 發票／收據 | 空白或無法判讀 → **不匯入**（不再依發票號碼推斷，避免漏填號碼的發票被當成收據） |
| 廠商（支出）／客戶（收入） | 不可空白 | 空白 → **不匯入** |
| 統一編號 | 8 碼數字且通過檢查碼 | 支出發票：空白或無效 → **不匯入**。支出收據與所有收入：選填，無效則不帶入並列出（2026-11-10 收入改選填） |
| 發票號碼 | 2 碼英文字母 + 8 碼數字（可有 `-`） | 發票：空白或格式不符 → **不匯入**。收據：不帶入（有填則列出） |
| 類別 | 依名稱比對本公司**啟用中**的同類型類別（支出／收入分開）；停用的類別視為找不到 | 找不到或空白 → 預覽時由使用者對應（每個名稱只問一次） |
| 稅別 | 應稅、應稅5%、5% → 應稅；免稅、0% → 免稅；空白 → 應稅。**收據一律免稅**，與手動新增一致；收據卻填了應稅則改為免稅並列出 | 無法判讀 → 應稅並列出（收據仍為免稅） |
| 未稅金額、含稅金額 | 去除 `NT$`、`$`、`元`、千分位、空白後為 ≥ 0 的數字，最多 2 位小數，上限 9,999,999,999.99（稅額、單價、小計、品項加總同此上限）。**至少填一個**，另一個依稅別推算，算法同手動新增；兩個都填則照填 | 兩個都空白，或任一個有填但無法判讀（即使另一個正確）→ **不匯入**（有品項也不以品項加總代替）；推算出的含稅超過上限 → **不匯入**；應稅發票的未稅大於含稅 → **不匯入**；應稅發票兩個都填但稅額與「未稅 × 5%」相差超過 1 元 → 照填並列出「未稅與含稅不符合 5% 稅率，請確認」；免稅或收據兩個都填但不相等 → 以含稅為準並列出 |
| 稅額 | 空白時：應稅發票 = 含稅 − 未稅；免稅或收據為 0 | 有填但與推算結果不符 → 以推算結果為準並列出 |
| 付款／收款狀態 | 待付款、已付款／待收款、已收款；空白 → 待付款／待收款 | 無法判讀 → 待付款／待收款並列出 |
| 實付日期／實收日期 | 同發生日期寫法；已付款／已收款但空白 → 以發生日期代入並列出（匯入多為歷史資料，不用今天）；待付款／待收款卻有填 → 不帶入並列出 | 無法判讀 → 以發生日期代入並列出 |
| 品項 | 數量空白 → 1；小計空白 → 數量 × 單價；只有小計 → 數量 1、單價 = 小計 | 品名空白、數量為 0 或負數、或算不出小計的品項不匯入，主檔照匯入並列出 |
| 金額 vs 品項加總 | 品項加總等於未稅或含稅任一個即視為一致（發票品項常以未稅列示）；都不相等照匯入（與手動新增一致，不強制相等） | 列出提醒 |

一筆單據任一列造成「不匯入」時，整筆單據都不匯入。

**擴充設計（給之後支援各式格式）**：解析分成五段：讀表 → 欄位對應 → 值轉換 → 檢查 → 產生紀錄。首版的「欄位對應」固定為範本標題；之後替換成「同義詞自動猜 + 使用者在畫面調整 + 記住公司上次的對應」（必要時再以 AI 猜欄位，只送標題與前幾列），其他段落不變。preview／import API 預留選填的 `columnMapping` 參數。

**後端自動化測試重點**：金額推算（未稅／含稅／稅額）、分組、必填欄位不匯入與補預設值的判斷、類別只比對本公司、交易整批回滾。

### 5.5 批次 PDF 匯入（支出／收入）

> 2026-10-29 確認規則。支出、收入都已實作。API 見 `docs/OCR辨識規格.md` §9、`docs/dev/ocr-batch-api.md`。

- 一份 PDF 或圖片可以有多張不同的憑證，一頁也可以有多張；另開 API，不沿用 `/api/ocr/recognize`（該 API 把多個檔案視為同一張憑證）。
- **先找張數，確認後才逐張辨識並扣次**：上傳後只找出每頁每張憑證的位置，結果暫存在後端（30 分鐘後清除），**不辨識內容**；畫面顯示「找到 N 張憑證，確認後最多扣 N 次（剩餘 M 次）」。使用者確認後，每張裁成單張逐張辨識（有電子發票 QR 時以 QR 為準），扣次並帶出內容；取消不扣次。
- **扣次 = 辨識出內容的憑證張數**；確認前顯示的張數是上限，辨識不出內容的那幾張不扣。單筆表單維持每頁扣 1 次。
- 確認時剩餘次數不夠：使用者可依頁碼勾選要帶出的張數，或取消去加購。
- 送出前先檢查剩餘次數 ≥ 1，剩 0 次不辨識。
- 上限：每次最多 **5 頁**、每頁最多 10 張、單檔 20 MB、最多 5 個檔案。找張數與確認後的逐張辨識都同時處理，最慢也在 Cloudflare 的 100 秒時限內。
- 找張數、確認後的辨識各最多 90 秒，逾時的頁或憑證不扣次並提醒使用者重新上傳那幾頁。
- 同一家公司同時只能有一批在辨識，第二批回「上一批憑證還在辨識中，請稍候再試」。
- 帶出後沿用新增支出／收入頁的分頁逐筆核對流程。
- 每筆附上該張憑證所在的那一頁（PDF 拆成單頁；圖片用原圖，HEIC、WEBP 轉 JPEG）；同一頁的多張憑證附同一個檔案。單頁超過 5MB（憑證附件上限）時不附，提醒使用者自己補。
- 確認後扣次就不退：在新增頁刪掉某一筆或整批不建立，都不退次數。
- 收入以賣方為我方：客戶帶辨識出的買方，憑證沒寫買方時客戶留空，由使用者補上才能建立。
- 新增支出／收入頁可用「移除這筆」刪掉不要的一筆（例如框到的不是憑證）。
- 只有超級管理員可用。入口在支出列表、收入列表「⋯」選單「匯入 Excel」下面的「批次匯入憑證」，跟 Excel 匯入是不同的對話框。

## 六、核心查詢對照（對應 PRD/Sitemap）

> 所有列表與統計預設排除 `deletedAt` 有值的紀錄（垃圾桶）。

| 需求 | 查詢 |
|---|---|
| 待審佇列（後台簽核頁） | `Reimbursement WHERE companyId=X AND status IN ('in_review','rejected')` |
| 員工看自己的請款（前台儀表板） | `Reimbursement WHERE employeeId=me` |
| 統一支出列表（後台支出管理） | `Expense WHERE companyId=X ORDER BY date DESC`（可依 source 篩選） |
| 待付款／待收款分組 | 待付款 `Expense WHERE payoutStatus='pending' GROUP BY plannedPayoutDate`、待收款 `Income WHERE collectionStatus='uncollected' GROUP BY plannedCollectionDate`；每組回日期、總金額、筆數；逾期（日期 < 公司時區今天）的紀錄合併成一組排最前，其餘依日期由近到遠。公司關閉付款日時待付款仍分組 |
| 未結清代墊款 KPI（後台儀表板） | `SUM(amount) FROM Expense WHERE source='reimbursement' AND payoutStatus='pending'` |
| 本月支出總計 KPI | `SUM(amount) FROM Expense WHERE date IN this month`（含所有 source） |
| 本月支出筆數 KPI | `COUNT(*) FROM Expense WHERE date IN this month` |
| 近 12 月收支趨勢（儀表板大圖） | 收入 `GROUP BY month(date) FROM Income`、支出 `GROUP BY month(date) FROM Expense`，取近 12 個月，排除垃圾桶 |
| 類別預算執行率 | `SUM(Expense.amount) / Budget.amount WHERE category=X AND date IN period` |
| 本期損益（淨額） | `SUM(Income.amount) − SUM(Expense.amount)`，收入、支出皆以 `date`（發生日期）落在期間內（垃圾桶內的紀錄不計入）|
| 本期現金收支 | 實收日期落在期間內的收入合計 − 實付日期落在期間內的支出合計 |
| 年度逐月損益（損益報表） | 收入、支出皆以 `GROUP BY month(date)`（發生日期）彙總，期間為所選年度，共 12 欄；垃圾桶內的紀錄不計入 |
| 年度逐月現金流（現金流報表） | 收入以 `GROUP BY month(collectedAt)` 取已收款、支出以 `GROUP BY month(payoutDate)` 取已付款，期間為所選年度，共 12 欄；垃圾桶內的紀錄不計入 |
| 資金移轉列表 | `Transfer WHERE companyId=X AND deletedAt IS NULL ORDER BY transferDate DESC`，可依日期區間、轉出帳戶、轉入帳戶篩選，走伺服器端分頁 |
| 單一帳戶的資金移轉（現金流報表） | 垃圾桶外的移轉 `GROUP BY month(transferDate)`，轉入加、轉出減；所有帳戶不查 |
| 資料匯出（全部） | 該列表目前的分頁標籤與篩選條件（發生日期區間選填），支出、收入 `deletedAt IS NULL`；代墊款同「全部紀錄」列表的查詢；不分頁 |
| 匯出檔每日清除 | `DataExport WHERE expiresAt < now` 且仍有檔案者，刪除檔案 |
| 固定收支產生（每日檢查） | 找出 `lastGeneratedPeriod` 之後、已開始且未到期的範本，產生週期日已到的期數並更新 `lastGeneratedPeriod`；已刪除或已到期的範本不產生 |
| 待付款 KPI（儀表板） | `SUM(amount) FROM Expense WHERE payoutStatus='pending' AND deletedAt IS NULL`（含一般支出與代墊款） |
| 待收款 KPI | `SUM(amount) FROM Income WHERE collectionStatus='uncollected' AND deletedAt IS NULL` |
