# QA Checklist — 資金移轉模組

> **驗證對象**：管理員在帳戶之間搬移資金（例如從銀行提領到零用金），以及移轉手續費自動產生的支出，對現金流報表（含單一帳戶的期末現金）、支出列表與統計的影響。
> **前置**：以管理員身分登入後台。公司至少有兩個帳戶（例如「永豐-總公司」、「零用金」），起始月份為當月或更早；部分情境需要已有收入、支出，並到「現金流報表」（帳戶現金以單一帳戶的期末現金核對，帳戶設定列表沒有餘額欄）「帳戶設定」「支出管理」對照數字。
> **規格來源**：PRD 第 18、19、20、21 條（2026-11-03 更新版，commit 19301dc）；Sitemap「資金移轉」「現金流報表」「垃圾桶」；資料模型 §2.10。
> **注意**：本清單只驗證功能流程與規則；顏色、字級等 UI 細節不在此列。**不在本清單**：資金移轉的 Excel 匯入與匯出（首版不做）、稽核日誌獨立頁與永久刪除後的畫面查詢（之後另做）。受影響的其他模組，回歸項目分別補在「帳戶設定」「類別管理」「支出管理」三份清單。

## 1. 進入頁面與列表

- [x] 以管理員登入 → 主選單看得到「資金移轉」，位置在「固定收支」下方
- [x] 員工帳號無法進入此頁（被導回前台）
- [x] 公司還沒有任何移轉 → 列表看到空狀態與「新增資金移轉」按鈕
- [ ] 公司沒有任何帳戶 → 「新增資金移轉」按鈕停用，並提示先建立帳戶，附前往帳戶設定的連結；點連結可到帳戶設定
- [ ] 公司只有一個帳戶 → 「新增資金移轉」按鈕同樣停用，提示至少需要兩個帳戶
- [ ] 垃圾桶內的帳戶不算帳戶：只剩一個正常帳戶、另一個在垃圾桶 → 按鈕停用，提示至少需要兩個帳戶
- [ ] 建立到第二個帳戶後回到資金移轉 → 「新增資金移轉」按鈕可以點，可正常開啟表單
- [x] 列表每筆顯示移轉日期、轉出帳戶、轉入帳戶、金額、手續費、備註
- [x] 列表依移轉日期由新到舊排列
- [x] 筆數多於一頁 → 可換頁，換頁後總筆數正確
- [x] 同頁看得到垃圾桶入口，垃圾桶內為已刪除的移轉
- [x] 手機瀏覽：列表、新增、編輯、刪除都能正常操作（手機只實測新增、編輯，刪除未在手機上操作）

## 2. 新增資金移轉

- [x] 點「新增」→ 出現表單，要填轉出帳戶、轉入帳戶、金額、移轉日期，可選填備註、憑證、手續費
- [x] 手續費不填 → 顯示預設 0
- [x] 填：轉出「永豐-總公司」、轉入「零用金」、金額 10,000、日期今天、手續費 0 → 儲存後列表出現這筆，現金流報表選單一帳戶：轉出帳戶的期末現金減少 10,000、轉入帳戶增加 10,000
- [x] 儲存後，收入、支出列表都沒有出現這筆移轉
- [x] 帳戶下拉選單看不到垃圾桶內的帳戶
- [ ] 新增與編輯資金移轉的表單，轉出、轉入帳戶下拉選單都只能選既有帳戶，沒有「新增帳戶」的選項（依 2026-11-03 規格，帳戶一律在帳戶設定建立）
- [x] 備註、憑證可以不填
- [x] 上傳憑證 → 儲存後開啟這筆移轉，看得到憑證

## 3. 新增與編輯的擋下條件

### 3.1 基本欄位

- [x] 轉出與轉入選同一個帳戶 → 不能儲存，提示兩個帳戶不能相同
- [x] 金額留空 → 不能儲存，提示填寫金額
- [x] 金額填 0 → 不能儲存，提示金額須大於 0
- [x] 試著在金額輸入負數 → 打不出負號，存不了負數
- [x] 試著在手續費輸入負數 → 打不出負號，存不了負數
- [x] 手續費填 0 → 可以儲存，不產生支出
- [x] 轉出帳戶、轉入帳戶、移轉日期任一項留空 → 不能儲存，提示必填
- [x] 轉出帳戶現金不足（例如期末現金 100 轉出 10,000）→ 仍可儲存，不檢查餘額；現金流報表中轉出帳戶的期末現金變成負數

### 3.2 移轉日期早於帳戶起始月份

> 準備：帳戶 A 起始月份為本月；帳戶 B 起始月份為三個月前。

- [x] 移轉日期選上個月、轉出 A、轉入 B → 不能儲存，提示是帳戶 A 的起始月份限制，並告知要先把該帳戶起始月份往前調
- [x] 同樣日期，改成轉出 B、轉入 A → 一樣不能儲存，提示指向帳戶 A
- [x] 兩個帳戶的起始月份都晚於移轉日期 → 不能儲存，提示會點出不符的帳戶；其中一個調好後，仍會提示另一個
- [x] 移轉日期選在帳戶 A 起始月份的當月 1 日 → 可以儲存（起始月份當月算有效）
- [x] 提示出現後，不會產生任何移轉，也不會產生手續費支出
- [x] 編輯既有移轉，把日期改到早於任一帳戶起始月份 → 不能儲存，提示同上；原本的移轉內容不變
- [x] 編輯既有移轉，把帳戶換成另一個起始月份晚於移轉日期的帳戶 → 不能儲存，提示是哪個帳戶（2026-11-02 補測：畫面編輯，把轉入帳戶換成 11 月才起始的帳戶 → 儲存被擋，視窗提示日期早於該帳戶的起始月份並點名帳戶）
- [x] 到「帳戶設定」把帳戶 A 的起始月份與起始金額往前調到上個月之前 → 再回來新增同一筆移轉 → 可以儲存（2026-11-02 補測：畫面把該帳戶起始金額與起始月份往前調（出現二次確認），再回資金移轉用畫面新增 10/20 的移轉 → 儲存成功，現金流兩邊正確）

### 3.3 編輯其他欄位

- [x] 編輯移轉的金額、備註、憑證 → 儲存後列表與現金流報表的帳戶期末現金隨之更新（憑證於 2026-11-02 補測：畫面編輯視窗上傳圖片後儲存，憑證存入）
- [x] 編輯時把轉出與轉入對調 → 儲存後現金流報表兩個帳戶的移轉方向跟著相反
- [x] 編輯已存在的移轉，不改任何內容直接儲存 → 沒有錯誤，內容不變

## 4. 列表篩選

- [x] 依移轉日期區間篩選 → 只剩區間內（含頭尾兩天）的移轉（後端驗證；畫面篩選操作未測）
- [x] 依轉出帳戶篩選 → 只剩該帳戶為轉出的移轉（同上）
- [x] 依轉入帳戶篩選 → 只剩該帳戶為轉入的移轉（同上）
- [x] 日期區間、轉出、轉入同時選 → 結果同時符合三個條件（同上）
- [x] 篩選後換頁，條件保留；筆數正確（2026-11-02 補測：畫面篩選轉出帳戶後換到第 2 頁，條件仍保留、剩 3 筆、共 13 筆）
- [x] 按「清除篩選」→ 回到全部移轉（2026-11-02 補測：畫面按「清除篩選」後回到全部 13 筆）
- [x] 篩選結果為空 → 看到查無資料的提示，不是錯誤畫面（2026-11-02 補測：篩選出沒有結果時顯示「沒有符合條件的移轉」與清除篩選）

## 5. 手續費：建立、同步、歸 0、重填

> 準備：以下以「轉出永豐-總公司、轉入零用金、金額 10,000、日期為本月 5 日」為例。

### 5.1 建立

- [x] 新增移轉時手續費填 30 → 儲存後，到「支出管理」多出一筆支出：類別「手續費」、金額 30、發生日期為移轉日期、帳戶為轉出帳戶
- [x] 這筆支出狀態為已付款，發生日期、應付日期、實付日期都等於移轉日期（日期欄位細節見 `QA_日期欄位.md` 第 14 節）
- [x] 這筆支出在列表的來源標示為「移轉手續費」
- [x] 現金流報表單一帳戶：轉出帳戶期末現金減少 10,030（金額加手續費），轉入帳戶增加 10,000
- [x] 儲存手續費的當下沒有寄出任何通知（檢查通知數量沒有增加）
- [x] 手續費填 0 或不填 → 支出管理沒有多出任何支出

### 5.2 編輯後同步

- [x] 把手續費由 30 改成 50 → 支出管理那筆手續費支出金額變 50，轉出帳戶的期末現金少 20
- [x] 把移轉日期改到同月另一天 → 手續費支出的發生日期、應付日期、實付日期同步改成新日期
- [x] 把移轉日期改到另一個月 → 手續費支出在新月份的統計與現金流出現，舊月份不再計入（日期改到另一月，手續費支出的月份與現金流跟著移動）
- [x] 把轉出帳戶改成另一個帳戶 → 手續費支出的帳戶同步改成新的轉出帳戶，舊轉出帳戶的期末現金恢復
- [x] 只改備註或憑證、不動金額日期帳戶 → 手續費支出沒有變化
- [x] 同時改手續費與日期 → 兩項都同步

### 5.3 歸 0 與重填

- [x] 把手續費由 50 改成 0 → 支出管理看不到原本那筆手續費支出，它出現在支出的垃圾桶；轉出帳戶的期末現金恢復
- [x] 手續費歸 0 後，損益、預算、現金流不再計入那筆手續費（歸 0 後付款合計已不含該筆）
- [x] 手續費歸 0 後再填 80 → 支出管理出現一筆新的手續費支出（金額 80），垃圾桶內舊的那筆仍在垃圾桶，沒有被還原
- [x] 重填後，這筆移轉編輯時再改手續費 → 同步的是新的那筆，不是垃圾桶內舊的那筆
- [x] 反覆「填 → 歸 0 → 填」 → 每次歸 0 都多一筆留在垃圾桶的舊支出，目前有效的永遠只有一筆

## 6. 手續費支出在支出列表

- [x] 支出管理列表可看到手續費支出，來源標示「移轉手續費」
- [x] 來源篩選有「移轉手續費」選項 → 選後只剩手續費支出
- [x] 「移轉手續費」可與日期、類別、關鍵字、狀態篩選並用，結果同時符合
- [x] 開啟手續費支出的詳情 → 看得到金額、日期、帳戶、類別，並有連回原移轉的入口，點了跳到該筆移轉
- [x] 手續費支出的詳情沒有憑證，也不顯示「賣方」；憑證區只有「憑證放在資金移轉上」的提示（2026-11-02 驗證，commit b5e8cf0）
- [x] 一般支出與代墊款支出的詳情不受影響：仍顯示賣方、憑證類型、憑證（代墊款另有對應請款單與申請人）
- [x] 手續費支出無法編輯：沒有編輯入口；若直接進入編輯頁 → 被擋下並提示請到資金移轉修改（畫面沒有編輯入口；直接呼叫編輯被擋下，沒有試網址進編輯頁）
- [x] 手續費支出無法切換狀態：不能「標記為待付款」，也不能再標記已付款
- [x] 手續費支出無法刪除：沒有刪除入口；已付款也不能先切回待付款再刪
- [x] 手續費支出不出現在「待付款」分頁（它永遠已付款）
- [x] 「未填發票號碼」篩選勾選時 → 手續費支出不出現（它是收據類型）
- [x] 手續費支出不屬於固定收支，「固定」來源篩選不會出現它

## 7. 刪除、還原、永久刪除

### 7.1 刪除移轉

- [x] 刪除一筆沒有手續費的移轉 → 移轉進入垃圾桶，兩個帳戶的期末現金恢復
- [x] 刪除一筆有手續費的移轉 → 移轉與已付款的手續費支出一併進入垃圾桶；不需要先把手續費支出切回待付款
- [x] 刪除後，支出管理列表看不到這筆手續費支出，現金流與損益不再計入
- [x] 刪除後，列表總筆數少一筆；垃圾桶多一筆
- [x] 垃圾桶內的移轉不能編輯

### 7.2 還原移轉

- [x] 還原有手續費的移轉 → 移轉回到列表，手續費支出一併回到支出列表，帳戶期末現金與統計恢復
- [x] 移轉在垃圾桶時，到「帳戶設定」把轉出或轉入帳戶的起始月份調到移轉日期之後 → 不被擋下，可以儲存
- [x] 上一條之後還原該筆移轉 → 被擋下，提示是哪個帳戶的起始月份太晚；移轉仍在垃圾桶
- [x] 把該帳戶起始月份調回移轉日期當月或更早，再還原 → 可以還原，手續費支出一併回來
- [x] 手續費曾歸 0、留在垃圾桶的舊支出，在還原移轉時不會被一起還原
- [x] 還原只涉及這筆移轉自己的手續費支出，不影響其他移轉

### 7.3 手續費歸 0 後留在垃圾桶的支出

- [x] 支出垃圾桶看得到歸 0 留下的手續費支出
- [x] 這筆支出沒有「還原」可用；直接要求還原 → 被擋下
- [x] 這筆支出可以單獨永久刪除，刪除後垃圾桶內消失，移轉本身與目前有效的手續費支出都不受影響
- [x] 永久刪除前會有二次確認

### 7.4 移轉在垃圾桶時

- [x] 移轉在垃圾桶時，它的手續費支出在支出垃圾桶不能單獨永久刪除，也不能單獨還原
- [x] 移轉在垃圾桶時，把整筆移轉永久刪除 → 它的手續費支出隨之消失（見 7.5）

### 7.5 永久刪除移轉

- [x] 永久刪除移轉前有二次確認
- [x] 永久刪除有手續費的移轉 → 移轉消失，目前的手續費支出一併永久刪除，支出垃圾桶看不到它
- [x] 永久刪除一筆曾經歸 0 再重填的移轉 → 垃圾桶內舊的與目前的手續費支出全部一併永久刪除
- [x] 永久刪除後，帳戶、其他移轉、其他支出的數字都不變

## 8. 系統保留類別「手續費」

### 8.1 新公司

- [x] 新註冊一家公司 → 到「類別管理」支出類別，已有「手續費」，狀態使用中
- [x] 在這家公司新增一筆含手續費的移轉 → 手續費支出類別是「手續費」

### 8.2 既有公司

- [x] 既有公司原本已有同名的支出類別「手續費」 → 上線後沿用該類別，沒有出現第二個同名類別；原本掛在這個類別下的支出仍在（用實際遷移語法在資料庫交易內模擬後還原）
- [x] 既有公司原本有「手續費」但已停用 → 上線後恢復為使用中（同上）
- [x] 既有公司原本有「手續費」在垃圾桶 → 上線後恢復為使用中、回到類別列表（同上）
- [x] 既有公司原本沒有「手續費」→ 上線後新增一個（同上）
- [x] 以上調整不在稽核日誌新增紀錄（同上）

### 8.3 保留類別的限制

- [x] 「手續費」類別不能停用：嘗試停用 → 被擋下並提示這是系統保留類別（畫面沒有任何停用、刪除按鈕；後端強行嘗試被擋）
- [x] 「手續費」類別不能刪除：嘗試刪除 → 被擋下並提示這是系統保留類別（畫面沒有任何停用、刪除按鈕；後端強行嘗試被擋）
- [x] 「手續費」類別可以選給一般支出（新增支出時下拉看得到、可選）（員工請款下拉看得到；管理員新增支出下拉未逐一點開）
- [x] 一般支出選「手續費」類別 → 來源仍是一般支出，沒有「移轉手續費」標示，可以正常編輯與刪除

### 8.4 改名之後

- [x] 把「手續費」改名成「銀行費用」→ 可以儲存
- [x] 改名後新增含手續費的移轉 → 手續費支出的類別顯示「銀行費用」，沒有重新長出另一個「手續費」類別
- [x] 改名後，過去的手續費支出也顯示新名稱
- [x] 改名後仍不能停用、不能刪除
- [x] 改名成與其他支出類別同名 → 提示名稱重複，比照一般類別規則
- [x] 改名後，新增另一個名叫「手續費」的類別 → 可以（名稱不再被佔用），且它是一般類別，可以停用、刪除

### 8.5 預算

- [x] 為「手續費」類別設定預算 → 可以設定（預算管理頁看得到「手續費」類別）
- [x] 有手續費的移轉儲存後 → 該類別當月預算使用量增加手續費金額
- [x] 手續費歸 0、刪除移轉 → 預算使用量減少；還原移轉 → 預算使用量回來

## 9. 帳戶被移轉引用時不可刪除
