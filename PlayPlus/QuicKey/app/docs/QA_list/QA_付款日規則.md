# QA Checklist — 付款日規則與應付日期

> **驗證對象**：管理員設定每月付款日、以及單筆支出的應付日期調整。
> **前置**：以管理員身分登入後台，進入「支出管理」頁面。資料為全新狀態時，付款日預設為「每月 5 號」。
> **注意**：本清單只驗證「功能流程與規則」；提示文字顏色、按鈕樣式、下拉動畫等 UI 細節由設計規範統一把關，不在此列。

---

## 1. 設定每月付款日（頁面上方「付款日：每月 X 號」）

- [ ] 進入頁面看到目前付款日（新公司預設「每月 5 號」）
- [ ] 點付款日 → 彈出設定視窗，可選 1–31 號；要關閉付款日，按選單右邊的「關閉付款日設定」按鈕
- [ ] 選跟目前相同的值按儲存 → 直接關閉視窗，不出現 toast、資料不變
- [ ] 選不同的值按儲存 → 出現 toast「付款日：每月 X 號」，並說明只影響之後登錄或核准的款項，既有支出不變
- [ ] 按選單右邊的「關閉付款日設定」按鈕（選單顯示「關閉付款日」）後儲存 → 出現已關閉的提示
- [ ] 已關閉付款日時打開設定視窗 → 選單顯示「關閉付款日」，右邊的關閉按鈕不能按
- [ ] 按「取消」或關閉視窗 → 付款日維持不變
- [ ] 重新整理後付款日仍為最後儲存的值

## 2. 新增支出時的應付日期預設

> 規則（2026-11-05 改版）：從登錄當天（**含當天**）往後找最近的付款日；細節見 `QA_日期欄位.md` 第 4 節。

- [ ] 付款日設 5 號，今天 11/3 新增支出 → 應付日期預設 11/5
- [ ] 今天 11/5（付款日當天）新增 → 應付日期預設 11/5（含當天）
- [ ] 今天 11/6 新增 → 應付日期預設 12/5
- [ ] 今天 12/20 新增 → 應付日期預設隔年 1/5
- [ ] 新增時若公司已關閉付款日 → 應付日期預設為發生日期（不是空白）
- [ ] 直接選「已付款」建立支出 → 仍有應付日期（必填欄位），另有實付日期，兩者互不連動
- [ ] 付款日設 31 遇到當月只有 30 天（例：11 月）→ 應付日期落在該月最後一天（11/30）
- [ ] 付款日設 31 遇到 2 月 → 應付日期落在 2/28（平年）或 2/29（閏年）

## 3. 代墊款核准後自動建立的支出

- [ ] 管理員核准員工的代墊款 → 支出列表多一筆（來源：代墊款）
- [ ] 這筆支出的應付日期為「核准當天」（含當天）往後最近的付款日（**不是**代墊款的發生日期、也**不是**員工提交時間）
- [ ] 核准時公司已關閉付款日 → 應付日期等於這筆支出的發生日期（員工填的發生日期）

## 4. 變更付款日的影響範圍（只影響之後）

**前置**：準備多筆支出橫跨幾個月份，包含本月、上月、以前月份，有待付款也有已付款。

- [ ] 把付款日從 5 號改成 10 號 → 儲存成功
- [ ] 所有**既有**支出（待付款、已付款、代墊款，不分月份）→ 應付日期**全部維持不變**
- [ ] 手動調整過的支出 → 應付日期**不被覆蓋**
- [ ] 改完後**新登錄**的支出 → 依新的付款日算應付日期
- [ ] 改完後**新核准**的代墊款 → 依新的付款日算應付日期
- [ ] 想改既有待付款支出的應付日期 → 用「調整應付日期」或在編輯畫面修改
- [ ] 關閉付款日 → 既有支出的應付日期不變；之後新登錄的支出，應付日期等於發生日期
- [ ] 曾經手動調整、在公司改付款日後按「改回自動排程」→ 回到當初登錄時算出的日期，不是依新付款日重算

## 5. 單筆調整應付日期

- [ ] 待付款的支出有「調整應付日期」入口（單筆列選單、或多筆勾選後批次操作）；編輯畫面也能直接改應付日期
- [ ] 進入視窗 → 看到該筆目前的應付日期（預填）
- [ ] 選一個日期按儲存 → 應付日期改為選擇的值
- [ ] 這筆支出之後若公司變更付款日 → **不會被覆蓋**
- [ ] 判斷是否手動調整過：開調整視窗有「改回自動排程」，或改發生日期時應付日期不跟著變；詳情的應付日期旁顯示「（已手動調整）」
- [ ] 手動調整過的支出，調整視窗與編輯畫面出現「改回自動排程」；按下後應付日期回到當初登錄（或核准）時算出的日期，按鈕消失
- [ ] 沒手動調整過的支出 → 沒有「改回自動排程」
- [ ] 登錄（或核准）當下公司已關閉付款日的支出 → 新增畫面、編輯畫面、調整視窗都沒有「改回自動排程」，要改回就直接改應付日期
- [ ] 登錄當時有付款日、之後才關閉付款日的支出，手動改過 → 仍有「改回自動排程」，回到當時算出的日期
- [ ] 應付日期不可清空（必填）

## 6. 多筆批次調整

- [ ] 勾選多筆待付款支出 → 可以一次「調整應付日期」
- [ ] 批次設定後，每一筆的應付日期都是所選日期，且都視為手動調整過（再單筆開調整視窗出現「改回自動排程」，改發生日期時應付日期不跟著變）
- [ ] 勾選多筆調整 → 視窗只能選新日期，不論選取中有沒有手動調整過的，都沒有「改回自動排程」；要改回只能一筆一筆處理

## 7. 不能調整的情境

- [ ] 已付款的支出 → 列表與詳情**沒有**「調整應付日期」入口（要改請進編輯畫面）
- [ ] 已作廢（如適用）的支出 → **沒有**「調整應付日期」入口
- [ ] 資金移轉產生的手續費支出 → **沒有**調整入口
- [ ] 若透過其他方式嘗試用「調整應付日期」改已付款支出 → 操作被擋

## 8. Dashboard 與列表的連動

**後台儀表板**
- [ ] 「下次付款」顯示的是所有待付款支出中、最近未到期（含今天）的應付日期
- [ ] 「逾期未付」顯示應付日期早於今天、狀態仍為待付款的支出（應付日期是今天的不算逾期）
- [ ] 「未來 7 天付款額」依每一天的應付日期彙總

**支出管理列表**
- [ ] 篩選「待付款」時，支出依應付日期分組（每組顯示日期、總金額、筆數），逾期的紀錄合併成一組排最前，其餘由近到遠
- [ ] 關閉付款日後，待付款仍依應付日期分組（應付日期等於發生日期）
- [ ] 變更付款日後、重新開啟列表，既有支出的分組不變

## 9. 跨時區／跨日邊界

- [ ] 台北時間接近午夜（例：23:50、00:10）新增支出 → 「登錄當天」以**台北時間**為準，應付日期不因伺服器時區偏移而差一天
- [ ] 台北時間月底最後一天晚上新增、付款日為 31 → 應付日期為當天，不會跳到下個月
- [ ] 同一時間點「逾期」判定也以台北時間的今天為準

## 10. 資料保留

- [ ] 設定付款日、調整單筆、改回自動排程後，重新整理頁面 → 狀態仍在
- [ ] 關閉瀏覽器再打開 → 狀態仍在

## 已知不覆蓋（out of scope）

- 歷次付款日變更紀錄的瀏覽介面（目前僅後端保留審計資料，前台無頁面）
- 多公司／多工作區情境
- 以日曆方式一次指定多個「不規則付款日」（例：5 號 + 20 號雙付款日）
- 付款日變更的 Email / 通知推播
