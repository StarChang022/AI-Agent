# QA Checklist — 收支日期欄位改版

> **驗證對象**：管理員在支出、收入、固定收支、Excel 匯入、憑證辨識、資金移轉手續費中，各種日期欄位的名稱、預設值、自動帶入與統計歸屬是否正確。
> **依據**：PRD 第 10 條、第 23 條。
> **前置**：以管理員身分登入後台。公司付款日先設為「每月 5 號」（各節另有指定時除外）。「今天」皆指測試當天（台北時間），範例日期請依測試當天換算；需要模擬「今天」不同的情境，請洽工程師協助調整日期。
> **注意**：本清單只驗證「功能流程與規則」；標籤顏色、字級、浮層樣式等 UI 細節由設計規範統一把關，不在此列。
> **日期一覽**：
> - 發生日期：生意完成或費用發生的日子，決定計入哪個月的損益。
> - 發票日期：發票上印的日期，只有發票才有，不影響損益與現金流。
> - 應收日期／應付日期：預計何時收到或付出，用來排待收付與判斷逾期。
> - 實收日期／實付日期：錢真正進出的日子，決定計入哪個月的現金流。

---

## 1. 名稱

> 逐頁確認舊名稱都已消失，不應再看到「預計付款日」「付款日」（指實際付款）「收款日」「開立日」「交易日期」「消費日」「費用日」「費用日期」。

- [ ] 支出列表、支出詳情、新增支出、編輯支出 → 日期欄位名稱為「發生日期」「發票日期」（發票才有）「應付日期」「實付日期」（已付款才有）
- [ ] 收入列表、收入詳情、新增收入、編輯收入 → 日期欄位名稱為「發生日期」「發票日期」（發票才有）「應收日期」「實收日期」（已收款才有）
- [ ] 支出列表與詳情的「調整付款日」入口 → 名稱為「調整應付日期」
- [ ] 現金流報表的待收款、待付款清單 → 日期欄位標示為「應收日期」「應付日期」
- [ ] 標記已收款、已付款的確認視窗 → 日期標示為「實收日期」「實付日期」
- [ ] 公司付款日設定（每月 X 號）的名稱不變，仍叫「付款日」
- [ ] 員工前台請款表單、後台審核、請款紀錄與明細 → 日期欄位名稱都是「發生日期」（發票另有「發票日期」），不再出現「交易日期」「消費日」「費用日」「費用日期」（詳見第 17 節）
- [ ] 稽核日誌中日期相關欄位的名稱也使用新名稱

## 2. 發票日期：何時出現、是否必填

- [ ] 新增支出，文件類型選「發票」→ 出現「發票日期」欄位，標示必填
- [ ] 新增支出，文件類型選「收據」→ 沒有「發票日期」欄位
- [ ] 新增收入，同上兩條規則相同
- [ ] 發票的發票日期留空按儲存 → 不能儲存，提示請填發票日期
- [ ] 收據的發生日期留空按儲存 → 不能儲存，提示必填
- [ ] 發票已填發票日期、發生日期維持預設 → 可以儲存，兩個日期各自存下
- [ ] 把已存的發票改成收據並儲存 → 發票日期欄位消失；再改回發票時，發票日期欄位為空白、必須重新填寫；發生日期兩次都維持原值
- [ ] 把已存的收據改成發票 → 出現空白的發票日期欄位，需填寫才能儲存；發生日期不變
- [ ] 文件類型改來改去但沒按儲存 → 取消後原紀錄的日期完全不變
- [ ] 支出、收入的列表或詳情，發票才顯示發票日期；收據不顯示

## 3. 發票日期自動帶入發生日期

> 新增畫面中，發生日期預設為今天。規則：改發票日期時，發生日期若與「修改前的發票日期」同一天就跟著改，不同天就不動。新增與編輯都適用，手動輸入或憑證辨識都算。

### 新增
- [ ] 新增發票，發生日期保持預設的今天，第一次填入發票日期 10/20（今天不是 10/20）→ 發生日期自動變成 10/20
- [ ] 接上一條，再把發票日期改成 10/25 → 發生日期跟著變成 10/25
- [ ] 新增發票，先手動把發生日期改成 10/10，再填發票日期 10/20 → 發生日期維持 10/10，不被覆蓋
- [ ] 新增發票，填了發票日期 10/20（發生日期帶入 10/20）後，手動把發生日期改成 10/10，再改發票日期為 10/25 → 發生日期維持 10/10，不動
- [ ] 新增發票，先手動把發生日期改成 10/10 後又改回今天，再填發票日期 → 發生日期維持今天（原本就與發票日期不同天，不動）
- [ ] 新增發票，發票日期剛好填成今天 → 發生日期仍是今天，沒有異常
- [ ] 改發生日期，發票日期不會跟著變（只從發票日期帶到發生日期，不反向）

### 憑證辨識認錯日期
- [ ] 上傳發票辨識，發票日期帶入 10/20、發生日期一併帶入 10/20，發現認錯，把發票日期改正為 10/02 → 發生日期一起變成 10/02
- [ ] 辨識後先手動把發生日期改成別天，再修正發票日期 → 發生日期不動

### 清空發票日期
- [ ] 發票日期 10/20、發生日期 10/20，把發票日期清空 → 發生日期維持 10/20
- [ ] 接上一條，再填入發票日期 10/05 → 發生日期變成 10/05（以清空前的 10/20 比對，原本同一天所以跟著改）
- [ ] 發票日期 10/20、發生日期 10/10（不同天），清空發票日期後再填 10/05 → 發生日期維持 10/10

### 編輯既有紀錄
- [ ] 編輯既有發票，發生日期與發票日期同一天（皆 10/20），把發票日期改成 10/25 → 發生日期跟著變成 10/25
- [ ] 編輯既有發票，發生日期 10/10、發票日期 10/20（不同天），改發票日期 → 發生日期維持 10/10
- [ ] 編輯既有紀錄，把收據改成發票後填發票日期 → 發生日期不變（收據沒有發票日期可比對）
- [ ] 編輯時改了發票日期、發生日期跟著變，但按取消不儲存 → 原紀錄日期完全不變

### 連動應收／應付日期
- [ ] 發生日期因發票日期變動而跟著改時，若應收日期（或應付日期）原本跟著發生日期，也一併跟著變
- [ ] 應付日期原本是手動指定的，發生日期因發票日期而改變 → 應付日期維持手動值
- [ ] 規則與「發生日期手動修改時應收／應付日期的連動」一致（見第 4、5 節）

### 收入
- [ ] 收入新增、編輯，上述各條規則相同

## 4. 應付日期預設值（支出）

> 公司付款日設為「每月 5 號」。新增時應付日期欄位預先帶入，可修改。

### 有設定付款日
- [ ] 今天 11/3，新增支出 → 應付日期預設 11/5（本月付款日還沒到）
- [ ] 今天 11/5（剛好是付款日），新增支出 → 應付日期預設 11/5（含當天）
- [ ] 今天 11/6，新增支出 → 應付日期預設 12/5（本月付款日已過，找下個月）
- [ ] 今天 12/20，新增支出 → 應付日期預設隔年 1/5（跨年）
- [ ] 發生日期填很久以前（例如 8/10），今天 11/6 → 應付日期仍依「今天」算為 12/5，不是依發生日期算
- [ ] 付款日設為 31、今天 11/10 → 應付日期預設 11/30（短月份落在月底）
- [ ] 付款日設為 31、今天 11/30（月底當天）→ 應付日期預設 11/30（含當天）
- [ ] 付款日設為 31、今天 2 月中 → 應付日期預設 2/28（閏年為 2/29）
- [ ] 付款日設為 31、今天 1/31 → 應付日期預設 1/31

### 關閉付款日
- [ ] 公司關閉付款日，新增支出，發生日期 10/20 → 應付日期預設 10/20（等於發生日期）
- [ ] 接上一條，改發生日期為 10/22（應付日期尚未手動改）→ 應付日期跟著變成 10/22

### 代墊款核准
- [ ] 付款日每月 5 號，今天 11/6，核准一筆員工代墊款（發生日期 10/15）→ 產生的支出應付日期為 12/5（從核准當天往後找，不看請款的發生日期、不看員工提交日）
- [ ] 今天剛好是付款日當天核准 → 應付日期為當天
- [ ] 公司關閉付款日時核准 → 應付日期等於該筆支出的發生日期（即請款的發生日期）
- [ ] 代墊款核准後，支出的發生日期等於請款的發生日期；若為發票，支出的發票日期等於請款的發票日期（詳見第 17 節）

### 與發生日期的關係
- [ ] 由付款日算出的應付日期（例：12/5），之後在新增畫面改發生日期 → 應付日期不變
- [ ] 新增時應付日期欄位可直接修改；修改後再改發生日期 → 應付日期維持手動值
- [ ] 公司之後改了付款日 → 已存在的支出應付日期都不被改動（只影響之後新登錄的）

## 5. 應收日期預設值與跟隨（收入）

- [ ] 新增收入，發生日期預設今天 → 應收日期預設為今天（等於發生日期）
- [ ] 新增收入，把發生日期改成 10/20 → 應收日期跟著變成 10/20
- [ ] 公司有設定付款日 → 收入的應收日期仍等於發生日期，不受付款日影響
- [ ] 新增收入，先手動把應收日期改成 11/30，再改發生日期 → 應收日期維持 11/30，不再跟著變
- [ ] 新增收入後儲存時，應收日期與發生日期相同 → 之後編輯改發生日期，應收日期仍會跟著變（與發生日期不同才算手動改過）
- [ ] 新增發票收入，填發票日期帶入發生日期 → 應收日期也跟著變成同一天
- [ ] 編輯既有收入，應收日期等於發生日期（從未手動改過）→ 改發生日期，應收日期跟著變
- [ ] 編輯既有收入，應收日期曾手動改過 → 改發生日期，應收日期不變
- [ ] 收入沒有「改回自動排程」按鈕，應收日期直接在編輯畫面改
- [ ] 應收日期留空按儲存 → 不能儲存，提示必填

## 6. 支出編輯畫面的應付日期與改回自動排程

- [ ] 開啟任一待付款支出的編輯畫面 → 看得到應付日期欄位，顯示目前值
- [ ] 已付款支出的編輯畫面 → 同樣看得到應付日期（實付日期也顯示），可編輯
- [ ] 在編輯畫面改應付日期並儲存 → 列表與詳情顯示新日期，待付款分組也移到新日期那組
- [ ] 應付日期留空按儲存 → 不能儲存，提示必填
- [ ] 從未手動改過的支出 → 編輯畫面**沒有**「改回自動排程」按鈕；列表、詳情的調整視窗也沒有
- [ ] 改了應付日期並儲存後再開編輯畫面 → 出現「改回自動排程」按鈕；列表與詳情的調整視窗也出現
- [ ] 按「改回自動排程」→ 應付日期回到「當初登錄（代墊款為核准）那天」依付款日算出的日期，不是依現在的付款日重算；按鈕隨之消失
- [ ] 登錄（或代墊款核准）當下公司已關閉付款日的支出，手動改過應付日期後 → 新增畫面、編輯畫面、列表與詳情的調整視窗都**沒有**「改回自動排程」；要改回就直接把應付日期改成發生日期
- [ ] 接上一條，應付日期改成與發生日期同一天儲存 → 之後改發生日期，應付日期又會跟著變
- [ ] 登錄當時有付款日、手動改過、之後公司才關閉付款日的支出 → 仍顯示「改回自動排程」，按下後回到登錄當時算出的日期
- [ ] 勾選多筆調整 → 視窗只能選新日期，不論選取中有沒有手動調整過的，都沒有「改回自動排程」；要改回只能一筆一筆處理
- [ ] 公司在支出登錄後改了付款日，手動改過的支出按「改回自動排程」→ 仍回到登錄當時算出的日期，不受新付款日影響
- [ ] 在編輯畫面把應付日期改成與目前自動值相同的日期 → 不算手動調整，不出現「改回自動排程」
- [ ] 列表勾選一筆或多筆待付款支出「調整應付日期」→ 選日期後儲存，每筆的應付日期都改成所選日期，且再單筆開調整視窗，這幾筆（原本有付款日者）出現「改回自動排程」；改這幾筆的發生日期時，應付日期不再跟著變
- [ ] 手動調整過應付日期的支出，詳情的應付日期旁顯示「（已手動調整）」；沒手動調整過、或按了「改回自動排程」之後就不顯示
- [ ] 單筆調整視窗按「改回自動排程」（只在手動調整過的那一筆提供）→ 該筆回到自己的自動值
- [ ] 實付日期欄位的修改不會影響應付日期，反之亦然
- [ ] 規則適用範圍：一般支出、固定支出產生的紀錄、代墊款核准產生的支出相同；移轉手續費支出為唯讀，不可調整

## 7. 實收／實付日期

### 預設與互不連動
- [ ] 新增支出時付款狀態選「已付款」→ 出現實付日期，預設今天，必填，可修改
- [ ] 新增收入時收款狀態選「已收款」→ 出現實收日期，預設今天，必填，可修改
- [ ] 新增時應付日期為 12/5、實付日期預設今天 → 兩者不同，互不影響
- [ ] 改應付日期（應收日期）→ 實付日期（實收日期）不會跟著變；反之亦然
- [ ] 待付款（待收款）的紀錄，編輯畫面看不到實付（實收）日期欄位，也沒有付款人欄位（支出）
- [ ] 已付款支出的實付日期留空按儲存 → 不能儲存，提示必填

### 標記已收款、已付款
- [ ] 在列表對單筆待付款支出標記已付款 → 跳出確認視窗，顯示將記錄的實付日期，預設今天，可修改；按取消 → 維持待付款，沒有任何變化
- [ ] 在視窗改日期為 11/2 後按確認 → 支出變已付款，實付日期為 11/2
- [ ] 在詳情畫面標記已付款 → 同樣先跳出確認視窗，規則相同
- [ ] 待收款的收入標記已收款 → 規則同上（實收日期）
- [ ] 應付日期為 12/5、今天 11/6，標記已付款 → 視窗預設實付日期為今天 11/6，不是 12/5
- [ ] 應付日期早已過期的支出標記已付款 → 預設仍為今天
- [ ] 代墊款來源的支出標記已付款 → 同一個視窗中同時有發放方式與實付日期；選好發放方式並確認後，兩者都正確
- [ ] 代墊款撥款後，後台請款詳情與員工前台的發放日，等於實付日期
- [ ] 已付款的代墊款來源支出，在編輯畫面改實付日期 → 後台請款詳情與員工前台的發放日跟著變

### 改回待收付後再標記
- [ ] 已付款支出（實付日期 10/28）改回待付款 → 列表與詳情看不到實付日期與付款人；應付日期維持原值，沒有因此改變
- [ ] 接上一條，再標記已付款 → 確認視窗預設帶回原本的 10/28（不是今天），可改；確認後實付日期為視窗中的日期
- [ ] 接上一條，確認前把日期改成今天 → 以修改後的為準
- [ ] 已收款收入改回待收款再標記已收款 → 規則同上，預設帶回原本的實收日期
- [ ] 一直沒標記過的待付款支出標記已付款 → 預設為今天
- [ ] 改回待付款、待收款的日期與付款人資料仍可在稽核日誌看到

### 批次標記
- [ ] 勾選多筆待付款支出（應付日期各不相同）批次標記已付款 → 只跳出一個確認視窗，顯示一個實付日期，預設今天
- [ ] 在視窗改日期為 11/2 後確認 → 每一筆的實付日期都是 11/2
- [ ] 勾選的多筆中，有曾經標記過又改回待付款的 → 批次標記仍全部使用視窗中的同一個日期，不各自帶回原值
- [ ] 批次標記待收款的收入 → 規則相同
- [ ] 批次視窗按取消 → 全部維持待付款

### 與帳戶起始月份
- [ ] 實付（實收）日期早於所選帳戶的起始月份 → 選完日期（或帳戶）就出現不計入現金流的提示，仍可儲存或確認（詳見帳戶設定清單 5.1）
- [ ] 待付款、待收款的紀錄不受這個提示影響

## 8. 待收款、待付款依日期分組與逾期

> **前置**：準備待付款支出，應付日期涵蓋：昨天、前天、今天、明天、下週；其中某一天有兩筆以上。收入也各備一組應收日期相同的資料。

- [ ] 支出列表切到「待付款」→ 依應付日期分組；每組標題顯示日期、該組總金額、筆數
- [ ] 同一天兩筆以上 → 歸在同一組，總金額與筆數正確
- [ ] 所有逾期的紀錄（日期早於今天）合併成**一組「逾期」**，排在最前面；其餘依日期由近到遠排列
- [ ] 逾期組顯示的總金額與筆數，是所有逾期紀錄的合計（昨天、前天各一筆 → 一組、2 筆）
- [ ] 逾期組標題不顯示日期，只有「逾期未收款／逾期未付款」、總金額與筆數；各筆的日期看組內列表。今天或未來的分組標題仍顯示日期（收入、支出兩頁，桌機與手機寬度都一樣）
- [ ] 應付日期是今天的紀錄 → **不算逾期**，自成「今天」那一組，排在逾期組之後
- [ ] 應付日期是昨天的紀錄 → 歸入「逾期」組
- [ ] 收入列表切到「待收款」→ 依應收日期分組，顯示與排序規則相同，逾期規則相同
- [ ] 公司關閉付款日 → 待付款仍依應付日期分組（應付日期等於發生日期）
- [ ] 在編輯畫面或調整視窗把一筆從今天改到昨天 → 回到列表後該筆移到「逾期」組
- [ ] 把一筆逾期的支出標記已付款 → 離開待付款分組；逾期組只剩這筆時整組消失
- [ ] 逾期與否以台北時間判斷：接近午夜（台北 23:50、00:10）時，今天的判定不因伺服器時區而提早或晚一天（洽工程師協助）
- [ ] 儀表板、現金流報表的待收款、待付款清單 → 依應收／應付日期呈現；逾期判斷同上，當天不算逾期
- [ ] 已付款、已收款的紀錄不出現在待收付分組
- [ ] 勾選「未填發票號碼」篩選時，待收付分組改為一般列表（既有行為不變）

## 10. 憑證辨識（OCR）

> 對象：新增支出、新增收入的拍照、文件上傳，以及批次匯入憑證。

- [ ] 上傳**發票**並辨識 → 日期帶入「發票日期」欄位；再依第 3 節規則，發生日期（仍是預設今天時）自動帶入同一天
- [ ] 上傳**收據**並辨識 → 日期帶入「發生日期」欄位；畫面沒有發票日期欄位
- [ ] 發票辨識完成後，手動改發生日期，再重新辨識（覆蓋）→ 發票日期更新為新結果；發生日期依「是否被手動改過」判斷，被改過的不被覆蓋
- [ ] 辨識出的發票日期早於 2000 年、晚於明年、格式錯誤或不存在 → 發票日期留空，由使用者自行填寫，發票仍必填
- [ ] 收據辨識出的日期無效 → 發生日期維持預設今天，不帶入無效日期
- [ ] 辨識後把文件類型從發票改成收據 → 發票日期欄位隱藏；發生日期維持目前值
- [ ] 辨識為發票，之後改成收據再改回發票 → 發票日期欄位為空白，須重新填寫
- [ ] 民國年（115/10/15）、西元（2026/10/15）寫法 → 都正確帶入
- [ ] 同張圖片有多張發票、需選其中一張時 → 選定後，該張的日期帶入發票日期
- [ ] 批次匯入憑證：每張憑證一個分頁，發票的日期在發票日期欄、收據的日期在發生日期欄；各分頁各自獨立判斷「發生日期是否被手動改過」
- [ ] 批次匯入憑證確認後新增，各筆的應付日期（支出）或應收日期（收入）依第 4、5 節預設規則計算
- [ ] 員工前台請款拍照辨識 → 發票的日期帶入發票日期、收據的日期帶入發生日期，規則與收支相同（詳見第 17 節）

## 11. Excel 匯入新欄位

> 支出、收入各跑一次。收入的「應付日期」「實付日期」改為「應收日期」「實收日期」。

### 範本
- [ ] 下載支出範本 → 標題包含「發生日期」「發票日期」「應付日期」「付款狀態」「實付日期」，不再有「日期」「付款日」
- [ ] 下載收入範本 → 標題包含「發生日期」「發票日期」「應收日期」「收款狀態」「實收日期」，不再有「開立日」「收款日」
- [ ] 標題標示：發生日期為「收據必填」、發票日期為「發票必填」；應付／應收日期為選填

### 缺標題
- [ ] 缺少「發生日期」或「發票日期」標題 → 整份退回，提示「找不到『發生日期』欄，請使用範本」（各自分開測）
- [ ] 缺少「應付日期」（收入為「應收日期」）、「實付日期」（收入為「實收日期」）標題 → 不退回，視為該欄全空
- [ ] 使用舊版範本（標題是「日期」「付款日」）上傳 → 整份退回，提示找不到「發生日期」欄

### 發生日期與發票日期
- [ ] 發票：發票日期有填、發生日期空白 → 匯入，發生日期帶入發票日期
- [ ] 發票：兩者都有填且不同 → 各自存下，不互相覆蓋
- [ ] 發票：發票日期空白 → 該筆不匯入，預覽顯示「不匯入」與原因（即使發生日期有填）
- [ ] 發票：發票日期讀不出的文字（如「下週」）→ 該筆不匯入
- [ ] 收據：發生日期空白 → 該筆不匯入
- [ ] 收據：發生日期讀不出 → 該筆不匯入
- [ ] 收據：發票日期欄有填 → 不帶入，匯入的收據沒有發票日期；完成畫面「需要留意」清單列出該列
- [ ] 日期年份早於 2000 年或晚於明年 → 該筆不匯入
- [ ] 日期接受 Excel 日期格式、`2026/10/29`、`2026-10-29`、民國 `115/10/29`
- [ ] 多品項單據中任何一列的日期造成不匯入 → 整張單據都不匯入

### 應付日期／應收日期
- [ ] 支出：應付日期空白，付款日每月 5 號、匯入當天 11/6 → 應付日期為 12/5（以匯入當天為登錄日），不列入「需要留意」
- [ ] 支出：公司關閉付款日、應付日期空白 → 應付日期等於發生日期
- [ ] 收入：應收日期空白 → 應收日期等於發生日期
- [ ] 應付日期（應收日期）有填且與預設值不同 → 以填的為準，視為手動調整，之後在編輯畫面出現「改回自動排程」（支出）
- [ ] 應付日期有填但與預設值剛好相同 → 不視為手動調整
- [ ] 應付日期讀不出的內容 → 依預設規則計算，並在完成畫面「需要留意」清單列出
- [ ] 同一單據的日期只填在第一列 → 後面列留空不造成錯誤；後面列填了不同日期 → 以第一列為準，完成畫面列出該狀況

### 實付日期／實收日期
- [ ] 狀態「已付款」、實付日期有填 → 以填的為準
- [ ] 狀態「已付款」但實付日期留空 → 以**發生日期**代入（不是今天），並列在「需要留意」
- [ ] 狀態「已付款」、實付日期讀不出 → 以發生日期代入，並列出
- [ ] 狀態「待付款」（含空白）卻填了實付日期 → 日期不帶入，並列出
- [ ] 收入的已收款、待收款，規則同上
- [ ] 實付（實收）日期早於帳戶起始月份 → 照常匯入，預覽與完成畫面依帳戶規則標示不計入現金流

### 匯入後結果
- [ ] 匯入完成的紀錄，列表上各日期欄位與 Excel 一致
- [ ] 匯入的待付款紀錄，依應付日期出現在對應的分組
- [ ] 稽核日誌標示來源為 Excel 匯入
