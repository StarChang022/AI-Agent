# QA Checklist — 固定收支模組

> **驗證對象**：管理員建立、管理固定收入與固定支出範本，以及範本自動產生的收入、支出紀錄，各種情境下的行為與規則是否正確。
> **前置**：以管理員身分登入後台，進入「收支管理 > 固定收支」。公司至少要有一個帳戶、支出類別與收入類別各一個。
> **規格來源**：PRD 第 17、18、21 條。
> **注意**：本清單只驗證「功能流程與規則」；顏色、字級、按鈕樣式等 UI 細節由設計規範統一把關，不在此列。
> **範圍**：
> - 帳戶刪除限制與類別刪除、停用限制的完整檢查，分別放在 `QA_帳戶設定.md`、`QA_類別管理.md`，本份只驗與範本相關的連動。
> - 代墊款流程不在此份；本份只驗「固定收支與代墊款互不相干」。
> - 「每天自動檢查」的檢查時間點無法手動觸發時，由工程師協助調整日期或手動執行一次檢查後再驗。以下「今天」皆指測試當天，範例日期請依測試當天換算。

---

## 1. 固定收支頁面與列表

- [ ] 進入「固定收支」→ 固定支出、固定收入都能各自看到進行中與歷史的範本，並顯示各自的數量
- [ ] 新增、到期、刪除、還原範本後，顯示的數量即時跟著更新
- [ ] 列表顯示：名稱、類別、帳戶、金額、週期、開始月份、結束月份、已產生到第幾期
- [ ] 結束月份留空的範本，結束月份欄顯示為持續（不是空白或錯誤）
- [ ] 還沒產生過任何紀錄的範本，「已產生到第幾期」顯示為尚未產生
- [ ] 沒有任何範本時，顯示引導訊息與「建立」按鈕
- [ ] 固定支出分頁看不到固定收入的範本，反之亦然

## 2. 建立範本

### 2.1 基本流程

- [ ] 點「建立固定支出」→ 出現表單，欄位有：名稱、類別、帳戶、文件類型、稅別、廠商、統一編號、金額、週期、開始月份、結束月份
- [ ] 點「建立固定收入」→ 欄位相同，但「廠商」改為「客戶」，類別只列收入類別
- [ ] 固定支出的類別下拉只出現支出類別、固定收入的類別下拉只出現收入類別
- [ ] 類別、帳戶下拉都只出現使用中的項目，已停用或在垃圾桶內的不會出現
- [ ] 填完所有必填欄位按儲存 → 範本建立成功，出現在列表
- [ ] 按「取消」或關閉表單 → 不建立任何範本
- [ ] 公司沒有任何帳戶 → 不能建立固定收支範本，提示先建立帳戶並有前往帳戶設定的連結；表單裡沒有當場新增帳戶的選項

### 2.2 必填與格式

- [ ] 名稱留空 → 出現錯誤提示，無法儲存
- [ ] 類別、帳戶、廠商（或客戶）、金額、週期、開始月份任一留空 → 出現錯誤提示，無法儲存
- [ ] 結束月份留空 → 可儲存，表示持續產生
- [ ] 金額輸入 0 或負數 → 出現錯誤提示，金額必須大於 0
- [ ] 文件類型選「發票」→ 統一編號必填，留空無法儲存
- [ ] 文件類型選「收據」→ 統一編號可留空
- [ ] 統一編號格式不是 8 碼數字 → 出現格式錯誤提示
- [ ] 開始月份最早只能選到 2000 年 1 月，更早的月份不能選
- [ ] 結束月份選得比開始月份早 → 出現錯誤提示，無法儲存
- [ ] 結束月份與開始月份相同 → 可儲存（只產生一期）
- [ ] 開始月份、結束月份選很遠的未來（例如 10 年後）→ 可儲存，沒有上限限制

### 2.3 週期設定

- [ ] 選「每月」→ 可選每月幾號（1 到 31）
- [ ] 選「每年」→ 可選幾月幾日
- [ ] 切換「每月」與「每年」時，表單會顯示或隱藏對應欄位，不影響已填的其他欄位

### 2.4 金額與稅別

- [ ] 稅別選「5% 營業稅」、金額（含稅）輸入 10,500 → 預覽或產生的紀錄未稅金額為 10,000、稅額為 500
- [ ] 稅別選「免稅」、金額輸入 10,000 → 產生的紀錄未稅金額 10,000、稅額 0
- [ ] 金額一律視為含稅金額，不會再加一次稅

## 3. 週期與月底

> 情境：公司每月 31 號付款，但 2 月、4 月、6 月沒有 31 號。

- [ ] 每月 31 號的範本，31 天的月份 → 紀錄日期為當月 31 號
- [ ] 每月 31 號的範本，30 天的月份（4、6、9、11 月）→ 紀錄日期為當月 30 號
- [ ] 每月 31 號的範本，2 月 → 紀錄日期為當月最後一天（平年 28 號、閏年 29 號）
- [ ] 每月 30 號的範本，2 月 → 紀錄日期為當月最後一天
- [ ] 每月 29 號的範本，平年 2 月 → 紀錄日期為 2 月 28 號；閏年 2 月 → 紀錄日期為 2 月 29 號
- [ ] 每月 15 號的範本，每個月都在 15 號，不受月份天數影響
- [ ] 每年 2 月 29 號的範本，平年 → 紀錄日期為 2 月 28 號；閏年 → 紀錄日期為 2 月 29 號
- [ ] 每年 4 月 31 號（該月不存在的日期）→ 可以設定；產生的紀錄日期為 4 月 30 號（當月最後一天）
- [ ] 每年 2 月 30 號 → 可以設定；平年產生在 2 月 28 號，閏年產生在 2 月 29 號
- [ ] 每年 3 月 15 號的範本，一年只在 3 月產生一筆，其他月份不產生

## 4. 週期日當天才產生

> 情境：假設今天是 11 月 10 號。

- [ ] 建立「每月 20 號」範本，開始月份為本月 → 今天不產生本月紀錄，「已產生到第幾期」仍為尚未產生；範本留在「進行中」
- [ ] 到了本月 20 號當天（工程師協助調整日期並執行檢查）→ 產生一筆本月紀錄，日期為 20 號
- [ ] 同一天重複執行檢查 → 不會再多產生一筆
- [ ] 建立「每月 10 號」範本（今天剛好是週期日）、開始月份為本月 → 建立後立即產生本月一筆（當天算已過）
- [ ] 建立「每月 5 號」範本（週期日已過）、開始月份為本月 → 建立後立即產生本月一筆
- [ ] 建立「每月 20 號」範本、開始月份為下個月 → 今天不產生任何紀錄
- [ ] 產生紀錄的日期一律以台灣時間判斷；台灣時間的週期日當天，不會因為時區差異而提早或晚一天產生
- [ ] 每年週期的範本，只有當年的週期日（幾月幾日）當天才產生，其他日子不產生
- [ ] 範本的帳戶、類別、金額在週期日當天產生時，帶入的是當時範本上的內容
- [ ] 一次跳過好幾天沒有檢查（例如系統停機後恢復）→ 恢復後補產生漏掉且週期日已過的期數，不重複、不漏

## 5. 補齊過去期數與送出前提示

> 情境：今天是 11 月 10 號，新增「每月 5 號」的固定支出，開始月份選 8 月。

- [ ] 儲存前出現提示，說明將補產生 4 筆紀錄，需使用者確認才會建立
- [ ] 提示中的筆數正確：開始月份到本月之間，週期日已到的期數才算
- [ ] 同樣情境但週期日是 20 號（本月尚未到）→ 提示補產生 3 筆，不含本月
- [ ] 同樣情境但週期日是 10 號（今天剛好）→ 提示補產生 4 筆，含本月
- [ ] 在提示按「取消」→ 不建立範本，也不產生任何紀錄
- [ ] 在提示按「確認」→ 建立範本，並產生提示中的筆數，日期各為該月週期日
- [ ] 補齊的紀錄一律為「待付款」（固定收入為「待收款」），即使日期已經過了很久
- [ ] 補齊的支出，應付日期以建立範本當天為登錄日，依公司付款日規則計算（與一般支出新增的算法相同）
- [ ] 補齊的紀錄不會被自動標為已付款或已收款
- [ ] 開始月份就是本月且週期日已過（只補 1 筆）→ 同樣出現送出前提示
- [ ] 開始月份在未來，或開始月份是本月且週期日還沒到 → 不會補任何過去期數，儲存時不出現補齊提示
- [ ] 開始月份在很久以前（例如 2 年前、每月）→ 提示筆數正確（約 24 筆以上），確認後全部產生
- [ ] 補齊時各月日期遇到月底規則（例如每月 31 號）→ 各月日期依第 3 節規則

## 6. 一期都沒有時不可建立

- [ ] 每年 6 月 15 號、開始月份 2026 年 1 月、結束月份 2026 年 5 月 → 範圍內沒有任何一期（6 月不在範圍），儲存被擋，提示開始月份到結束月份之間沒有任何一期
- [ ] 每年 6 月 15 號、開始月份 2026 年 7 月、結束月份 2027 年 5 月 → 同樣被擋
- [ ] 每年 6 月 15 號、開始月份 2026 年 6 月、結束月份 2026 年 6 月 → 剛好一期，可建立
- [ ] 每月週期、開始與結束月份相同 → 一定有一期，可建立
- [ ] 被擋時表單的內容保留，修改月份後可再次送出

## 7. 產生的紀錄內容

- [ ] 固定支出產生的是「支出」、固定收入產生的是「收入」，都出現在原本的支出列表、收入列表
- [ ] 狀態為「待付款」（支出）或「待收款」（收入）
- [ ] 發生日期為週期日（遇到短月份為當月最後一天）；文件類型為發票時，發票日期同發生日期（日期欄位細節見 `QA_日期欄位.md` 第 13 節）
- [ ] 類別、帳戶、文件類型、稅別、統一編號、金額與範本相同
- [ ] 廠商（支出）或客戶（收入）帶入範本的廠商或客戶
- [ ] 說明（備註）欄帶入範本名稱
- [ ] 未稅金額與稅額依金額和稅別正確計算
- [ ] 發票號碼為空白，沒有附件
- [ ] 支出的應付日期，以產生當天為登錄日，從當天（含）往後找最近的付款日；公司關閉付款日時等於發生日期。收入的應收日期等於發生日期
- [ ] 產生的支出出現在「待付款」相關清單與逾期提醒的判斷中，行為與一般支出一致
- [ ] 產生紀錄時，管理員與員工都沒有收到新通知；逾期後仍依既有的逾期付款提醒規則通知

## 8. 產生的紀錄可編輯、切換狀態、刪除

- [ ] 開啟產生的紀錄 → 可修改金額、日期、類別、廠商、說明等，與一般紀錄相同
- [ ] 發票號碼維持空白直接儲存 → 可成功儲存，不會被要求必填
- [ ] 之後補填發票號碼 → 可成功儲存
- [ ] 修改這一筆的金額 → 只影響這一筆，範本與其他期的紀錄不變
- [ ] 在列表把紀錄標記為已付款（或已收款）→ 與一般紀錄相同，日期與帳戶規則相同
- [ ] 已付款的固定支出紀錄改回待付款 → 資料保留，與一般紀錄相同
- [ ] 待付款（或待收款）的紀錄可刪除 → 進入垃圾桶；已付款（或已收款）需先改回待狀態才能刪除
- [ ] 刪除某一期的紀錄後，到了下次檢查**不會**因此重新產生同一期
- [ ] 把垃圾桶內的那筆紀錄還原 → 回到列表，仍帶「固定」標示
- [ ] 把垃圾桶內的那筆紀錄永久刪除 → 之後也不會重新產生同一期
- [ ] 改了這筆紀錄的帳戶為另一個帳戶 → 儲存成功，範本上的帳戶不變

## 9. 「固定」標示與篩選

- [ ] 支出列表中，由固定支出產生的紀錄在「來源」欄顯示「固定」；一般支出、代墊款不顯示
- [ ] 收入列表中，由固定收入產生的紀錄同樣顯示「固定」
- [ ] 支出列表可依「來源」篩選出「固定」，結果只剩固定支出產生的紀錄
- [ ] 收入列表也可篩選出「固定」
- [ ] 篩選出「固定」後，搭配日期、類別、狀態等其他條件仍正確
- [ ] 產生的紀錄的詳情中，可看出它來自哪個範本（或至少可辨識為固定產生）
- [ ] 將範本**永久刪除**後 → 先前產生的紀錄仍顯示「固定」標示，也仍能篩選得到，只是不再連回範本
- [ ] 範本只是**進垃圾桶**（尚未永久刪除）→ 紀錄的「固定」標示不變
- [ ] 手動新增的一般支出、一般收入從不會出現「固定」標示

### 9.1 「未填發票號碼」篩選

> 情境：固定收支產生的紀錄發票號碼是空白的，管理員想一次找出還沒補號碼的發票。支出、收入列表的篩選區都有這個勾選。

- [ ] 支出列表篩選區有「未填發票號碼」勾選；收入列表也有
- [ ] 勾選後 → 只列出「文件類型為發票、且發票號碼空白」的紀錄，固定產生的與手動新增的都會出現（不限固定收支）
- [ ] 文件類型是「收據」的紀錄 → 不出現（收據本來就沒有發票號碼）
- [ ] 已填發票號碼的發票 → 不出現
- [ ] 發票號碼只有空格、沒有實際內容的紀錄 → 視為未填，會出現
- [ ] 在篩選結果中打開一筆，補上發票號碼並儲存 → 回到列表後這筆從篩選結果消失，其他筆不受影響
- [ ] 取消勾選 → 回到全部紀錄，剛補上號碼的那筆仍在
- [ ] 與付款狀態（或收款狀態）並用 → 兩個條件都符合的才出現
- [ ] 與類別並用 → 同上
- [ ] 與日期範圍並用 → 同上
- [ ] 與關鍵字搜尋並用 → 同上
- [ ] 與「來源：固定」並用 → 只剩固定產生、且未填號碼的紀錄
- [ ] 勾選後筆數很多 → 分頁正確，總筆數與實際相符
- [ ] 支出列表在「待付款」分頁（依應付日期分組顯示）勾選此項 → 改為一般列表呈現篩選結果；取消勾選後回到依應付日期分組
- [ ] 按「清除篩選」→ 此勾選一併取消，列表回到全部紀錄
- [ ] 切換篩選條件後，原先勾選的列表項目選取被清空（與其他篩選相同）
- [ ] 未填發票號碼的紀錄，仍可標記為已付款（收入為已收款），不會被要求先補號碼
- [ ] 已付款（已收款）且未填號碼的紀錄，勾選後仍會出現，補號碼後才消失
- [ ] 垃圾桶畫面 → 沒有「未填發票號碼」勾選
- [ ] 被刪除進垃圾桶的未填號碼紀錄 → 不出現在勾選後的一般列表
- [ ] 手機畫面也能勾選此項，結果相同

## 10. 修改範本

### 10.1 只影響尚未產生的週期

- [ ] 修改金額 → 已產生的紀錄金額不變；下一次產生的紀錄使用新金額
- [ ] 修改週期日（例如 5 號改 20 號）→ 已產生的紀錄不變；之後的期數依新週期日
- [ ] 從「每月」改成「每年」（或反之）→ 已產生的紀錄不變；之後依新週期
- [ ] 修改名稱 → 已產生的紀錄說明不變；之後產生的使用新名稱
- [ ] 修改類別、帳戶、稅別、廠商（客戶）、統一編號、文件類型 → 已產生的紀錄不變；之後產生的使用新內容
- [ ] 修改本月週期日（從 20 號改成 5 號）而本月已產生 → 不會再多產生一筆
- [ ] 週期日從 20 號改成 25 號（今天 11 號、本月尚未產生）→ 本月到 25 號才產生
- [ ] 週期日從 20 號改成 5 號（今天 11 號、本月尚未產生）→ 按儲存後，送出前先提示將產生 1 筆紀錄，確認後儲存並立即產生本月一筆（日期為 5 號），不用等隔天
- [ ] 上述提示按「取消」→ 範本沒有被修改（週期日仍是 20 號），也沒有產生任何紀錄
- [ ] 上述提示確認並產生後，再開啟範本不改內容直接儲存（或再存一次）→ 不再出現提示，也不會重複產生同一期
- [ ] 週期日改了，但本月週期日仍未到、或本月已有這一期的紀錄 → 儲存時不出現提示，也不產生
- [ ] 修改後儲存成功 → 出現已更新的提示，列表顯示新內容

### 10.2 開始月份限制

- [ ] 範本尚未產生過任何紀錄 → 可以修改開始月份
- [ ] 範本已經產生過紀錄 → 開始月份欄位無法修改（鎖定，並有說明原因）
- [ ] 範本曾經產生過紀錄、但那些紀錄之後都被刪除（進垃圾桶）或永久刪除 → 開始月份仍不可修改
- [ ] 尚未產生過紀錄的範本，開始月份改到過去 → 比照建立，儲存前提示將補產生幾筆，確認後補齊（發生日期、狀態、應付日期規則同第 5 節）
- [ ] 上述提示按「取消」→ 開始月份沒有被修改，也沒有產生任何紀錄
- [ ] 尚未產生過紀錄的範本，開始月份從過去改到未來 → 不補產生，等到開始月份的週期日才產生

### 10.3 結束月份限制

- [ ] 結束月份改成比開始月份早 → 出現錯誤提示，無法儲存
- [ ] 結束月份可改成比「已產生的期數」早（例如已產生到 11 月，把結束月份改成 9 月）→ 可儲存；已產生的紀錄（含 10、11 月）保留不動
- [ ] 上述情況儲存後，範本不再產生新紀錄，並移至「歷史」
- [ ] 結束月份由空白改成某月 → 該月之後不再產生
- [ ] 結束月份由某月改成空白 → 回到持續產生

### 10.1.1 修改週期的銜接

- [ ] 每年 3 月 15 號已產生當年一筆，11 月改成每月（11 月週期日已過、尚未產生）→ 送出前先提示將產生 1 筆；確認後不補 4 到 10 月，只立即產生 11 月一筆，之後依新週期產生
- [ ] 上述提示按「取消」→ 週期維持原樣，不產生任何紀錄
- [ ] 每月已產生到 10 月，11 月改成每年 12 月 15 號 → 不補任何期數；今年 12 月 15 號照常產生
- [ ] 每年 3 月 15 號，3 月已產生；6 月把週期月份改成 8 月 → 當年已產生過，今年 8 月**不再**產生，從明年 8 月開始
- [ ] 每年 3 月 15 號，3 月尚未產生（例如 2 月）改成 8 月 → 儲存時不提示（當期不是 8 月、沒有已過未產生的期），今年 8 月 15 號照常產生一筆
- [ ] 每年週期改月份後，同一年不會產生兩筆

### 10.4 其他

- [ ] 編輯固定支出（或固定收入）範本 → 收支方向無法修改，並有說明；要換方向需另建範本
- [ ] 範本在垃圾桶內 → 不可編輯

## 11. 到期與歷史

- [ ] 結束月份為 12 月、每月 15 號，12 月 15 號產生最後一筆紀錄後 → 範本自動移到「歷史」，歷史數量 +1
- [ ] 範本到期當天仍在「進行中」，直到最後一期的紀錄產生才移到歷史
- [ ] 結束月份為本月、週期日還沒到 → 範本仍在「進行中」，週期日產生後才移到歷史
- [ ] 每年 6 月 15 號、結束月份在 7 月 → 6 月 15 號產生後即到期，移到歷史（之後再無下一期）
- [ ] 到期的範本不再產生新紀錄
- [ ] 歷史範本的列表欄位與進行中相同，可查看它產生的紀錄
- [ ] 歷史範本可以編輯（例如改名稱、結束月份）

### 11.1 把歷史範本的結束月份往後延

> 情境：範本到 10 月到期，現在是 11 月 20 號，想繼續到明年 6 月。

- [ ] 把結束月份延到明年 6 月 → 範本回到「進行中」，歷史數量 -1
- [ ] 範本週期日是 15 號（本月已過）、本月尚未產生 → 按儲存後，送出前先提示將產生 1 筆，確認後儲存並立即產生本月（11 月）一筆
- [ ] 上述提示按「取消」→ 結束月份沒有被延長，範本仍在「歷史」，不產生紀錄
- [ ] 範本週期日是 25 號（本月未到）→ 儲存時不提示、不產生，等 25 號才產生
- [ ] 中間漏掉的期數（範本到期後到上個月）**不會**補產生
- [ ] 延長後，本月若已經有這一期的紀錄（例如先前就產生過）→ 不會重複產生
- [ ] 延長後下個月起，依週期逐月產生，直到新的結束月份

### 11.2 延長但類別在垃圾桶或已停用

- [ ] 歷史範本使用的類別目前在垃圾桶內 → 嘗試把結束月份往後延 → 被擋，提示先還原類別，或改選其他類別
- [ ] 歷史範本使用的類別目前已停用 → 嘗試把結束月份往後延 → 同樣被擋，提示先解除停用類別，或改選其他類別
- [ ] 先到類別管理還原（或解除停用）該類別後，再延長結束月份 → 可成功
- [ ] 延長結束月份的同一次編輯中，把類別換成使用中的其他類別 → 可成功延長，之後產生的紀錄使用新類別
- [ ] 同一次編輯換類別時，下拉只列使用中類別，不出現垃圾桶或已停用的類別

## 12. 刪除、垃圾桶、還原、永久刪除

### 12.1 刪除（進垃圾桶）

- [ ] 進行中的範本點「刪除」→ 出現確認視窗，確認後範本從列表消失，到「垃圾桶」可找到
- [ ] 歷史範本同樣可以刪除進垃圾桶
- [ ] 範本已產生過紀錄、甚至有已付款（已收款）紀錄 → 仍可刪除（任何時候都能刪除）
- [ ] 刪除範本後，已產生的紀錄不受影響：仍在支出、收入列表，狀態與金額不變，仍有「固定」標示
- [ ] 刪除範本後，到了週期日不再產生新紀錄
- [ ] 垃圾桶內的範本不計入「進行中」「歷史」的數量
- [ ] 垃圾桶中的範本顯示刪除時間與操作人
- [ ] 垃圾桶中的範本不可編輯

### 12.2 還原

> 情境：範本每月 15 號。10 月 20 號刪除，11 月 20 號還原。

- [ ] 從垃圾桶還原 → 範本回到列表（還有下一期可產生 → 進行中；沒有下一期 → 歷史）
- [ ] 垃圾桶期間（刪除後到還原前）的期數**不會**補產生
- [ ] 還原當月週期日已過、且當月尚未產生 → 還原後立即產生當月一筆
- [ ] 還原當月週期日還沒到 → 還原後不產生，等週期日才產生
- [ ] 還原當月已經有這一期的紀錄（例如刪除前已產生）→ 不重複產生
- [ ] 還原時範本已沒有下一期可產生（已到期）→ 還原後在「歷史」，不產生任何紀錄
- [ ] 範本使用的類別目前在垃圾桶 → 範本不可還原，提示先還原類別
- [ ] 範本使用的類別目前已停用 → 範本同樣不可還原，提示先解除停用類別
- [ ] 先還原（或解除停用）類別後，再還原範本 → 可成功
- [ ] 範本使用的帳戶不可能在垃圾桶（有範本使用的帳戶不可刪除），因此還原範本不會遇到帳戶問題

### 12.2.1 還原與「當期」

> 「當期」指今天所在的月份。每年週期只有在今天所在的月份剛好是週期月份時才有當期。

- [ ] 每年 3/15 的範本，2 月刪除、11 月還原 → 11 月不是週期月份，沒有當期，還原後不產生；下一期是明年 3 月
- [ ] 每年 3/15 的範本，3 月 20 號（週期日已過、當期尚未產生）還原 → 立即產生當年 3 月一筆
- [ ] 每月 15 號的範本，11 月 20 號還原 → 立即產生 11 月一筆（見 12.2）

### 12.3 永久刪除

- [ ] 垃圾桶中點「永久刪除」→ 出現確認視窗，確認後範本從垃圾桶消失
- [ ] 永久刪除後，原本產生的紀錄仍在支出、收入列表，且仍顯示「固定」標示
- [ ] 永久刪除後，篩選「固定」仍可找到那些紀錄
- [ ] 永久刪除後，那些紀錄不再連得回範本（原範本已不存在）
- [ ] 範本被永久刪除後，原本被它占用的帳戶、類別（若沒有其他引用）才可被刪除、永久刪除

## 13. 範本明細（查看產生的紀錄）

- [ ] 點範本進入明細 → 列出該範本已產生的所有紀錄，顯示日期、金額、狀態
- [ ] 明細中的紀錄依日期排序（新到舊或舊到新，一致即可）
- [ ] 明細中的紀錄**不包含**垃圾桶內的紀錄
- [ ] 把某一期紀錄刪除（進垃圾桶）→ 明細少一筆；還原後明細又出現
- [ ] 把某一期紀錄標為已付款 → 明細中該筆狀態更新
- [ ] 還沒產生任何紀錄的範本 → 明細顯示尚無紀錄的空狀態
- [ ] 點明細中的紀錄 → 可開啟該筆紀錄的詳情

## 14. 與帳戶、類別的連動

### 14.1 帳戶

- [ ] 帳戶被「進行中」的範本使用（即使還沒產生任何紀錄）→ 到帳戶設定刪除該帳戶 → 被擋，出現不可刪除提示
- [ ] 帳戶被「歷史」範本使用 → 同樣不可刪除
- [ ] 帳戶被「垃圾桶內」的範本使用 → 同樣不可刪除
- [ ] 把使用該帳戶的範本永久刪除（且該帳戶沒有任何收支、資金移轉引用）→ 帳戶才能刪除
- [ ] 範本改用另一個帳戶後，原帳戶（若沒有其他引用）可刪除
- [ ] 範本產生的紀錄，使用範本上的帳戶；產生的待付款紀錄不影響帳戶餘額與現金流，標為已付款後才計入
- [ ] 產生的紀錄日期早於該帳戶起始月份、且是待付款（待收款）→ 不受影響；標為已付款（已收款）時，實收／實付日期早於帳戶起始月份，才依帳戶規則出現「不計入現金流」提示

### 14.2 類別

- [ ] 類別被「進行中」範本使用 → 到類別管理刪除、停用 → 都被擋，提示該類別正被固定收支使用
- [ ] 類別被「歷史」範本使用 → 可停用、可刪除進垃圾桶
- [ ] 類別被歷史或垃圾桶內的範本使用 → 類別即使在垃圾桶，也不可永久刪除
- [ ] 範本使用的類別被改名 → 範本與之後產生的紀錄顯示新名稱
- [ ] 類別在垃圾桶或已停用期間，歷史範本無法延長、垃圾桶範本無法還原（見第 11.2、12.2 節）

## 15. 上一次使用的帳戶不受影響

> 情境：管理員手動新增支出時，預設帶入的是「自己上一次新增的帳戶」。

- [ ] 管理員手動新增一筆支出，選帳戶 A → 再新增一筆時預設帶入帳戶 A
- [ ] 這時固定收支自動產生了一筆使用帳戶 B 的紀錄 → 管理員再新增支出，預設仍是帳戶 A（不變成 B）
- [ ] 建立範本時當場補齊多筆使用帳戶 B 的紀錄 → 之後手動新增的預設帳戶仍是自己上一次手動用的
- [ ] 把固定產生的某筆紀錄編輯、改了帳戶 → 不影響「上一次使用的帳戶」
- [ ] Excel 匯入帳戶欄留空時，備用的帳戶同樣不受固定產生的紀錄影響
- [ ] 範本被永久刪除後，原本產生的紀錄仍不影響「上一次使用的帳戶」

## 16. 稽核日誌與通知

- [ ] 建立、編輯、刪除、還原、永久刪除範本，每個動作都寫入稽核日誌（操作人、時間、變更前後內容）
- [ ] 範本自動產生的紀錄，稽核日誌動作標示為「固定收支自動產生」
- [ ] 上述自動產生的稽核紀錄，操作人記為「範本建立者」，不是系統或當下登入者
- [ ] 建立範本當下補齊的多筆紀錄，每一筆都有對應的稽核紀錄，同樣標示「固定收支自動產生」
- [ ] 還原範本或延長歷史範本時當場產生的紀錄，同樣標示「固定收支自動產生」
- [ ] 產生的紀錄之後被人工編輯、切換狀態、刪除，稽核日誌各自記錄，操作人為實際操作者
- [ ] 範本永久刪除後，該範本的稽核紀錄仍保存完整內容
- [ ] 自動產生紀錄時，沒有 Email 或站內通知寄出

## 17. 代墊款

- [ ] 固定收支只能產生一般收入、一般支出，**不會**產生代墊款
- [ ] 代墊款轉成的支出在列表的來源仍為「代墊款」，不會出現「固定」
- [ ] 代墊款流程（作廢、取消作廢）不受固定收支影響，代墊款仍只能作廢、不能刪除
- [ ] 固定產生的支出沒有「代墊款」相關操作（作廢連動、連帶作廢選項）

## 18. 公司間資料隔離與權限

- [ ] 公司 A 的範本不會出現在公司 B 的列表、歷史、垃圾桶
- [ ] 公司 A 的範本不會替公司 B 產生紀錄
- [ ] 範本只能選用本公司的類別與帳戶
- [ ] 員工無法進入固定收支頁面，也無法新增、編輯、刪除範本
- [ ] 員工在前台看不到固定產生的紀錄的任何管理入口（員工只看得到自己的請款）
