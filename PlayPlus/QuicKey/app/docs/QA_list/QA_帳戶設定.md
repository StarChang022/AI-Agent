# QA Checklist — 帳戶設定模組

> **驗證對象**：管理員管理公司收付帳戶，以及收入、支出、代墊款如何使用帳戶。
> **前置**：以管理員身分登入後台，進入「系統 → 帳戶設定」。部分情境需要已有收入／支出資料，或有員工提交的代墊款。
> **規格來源**：PRD 第 18、20、21、22 條（2026-11-03 更新版）；Sitemap「帳戶設定」「垃圾桶」。
> **注意**：本清單只驗證功能流程與規則；顏色、字級等 UI 細節不在此列。**不在本清單**：資金移轉本身的項目（另列於資金移轉 QA，第 14 節只放回歸項目）、固定收支產生的紀錄（另列於固定收支 QA）、稽核日誌獨立頁與永久刪除後的畫面查詢（之後另做）。

---

## 1. 帳戶列表

- [ ] 進入「帳戶設定」→ 列表顯示每個帳戶的名稱、起始金額、起始月份
- [ ] 公司帳戶都被刪除、列表為空 → 顯示一般的空白畫面（沒有「建立第一個帳戶」的提示），從「新增帳戶」按鈕可開啟新增視窗
- [ ] 員工帳號無法進入此頁（被導回前台）
- [ ] 手機瀏覽：列表與新增、編輯功能都能正常操作

## 2. 新增帳戶

- [ ] 點「新增帳戶」→ 出現視窗，要填帳戶名稱、起始金額，並可選起始月份
- [ ] 新增視窗沒有「類型」欄位（不再區分銀行帳戶或現金）
- [ ] 起始月份預設為當月
- [ ] 填入名稱「永豐-總公司」、起始金額 100,000、起始月份用預設 → 儲存後出現在列表，金額與起始月份正確
- [ ] 起始月份選過去的月份（例如本月之前）→ 可建立
- [ ] 起始月份可選的範圍是 2000 年 1 月到當月；選 2000 年 1 月 → 可建立
- [ ] 起始月份無法選擇未來月份（也無法選 2000 年 1 月以前）
- [ ] 編輯帳戶時，起始月份同樣只能選 2000 年 1 月至當月
- [ ] 起始月份留空或清掉 → 提示請選擇起始月份
- [ ] 起始金額填 0 → 可建立
- [ ] 名稱留空儲存 → 提示請填寫名稱，視窗不關
- [ ] 起始金額留空 → 提示請填寫起始金額
- [ ] 名稱與現有帳戶相同（不分大小寫、忽略前後空格）→ 提示名稱重複，不能建立
- [ ] 名稱與「垃圾桶內」的帳戶相同 → 一樣提示名稱重複，不能建立（垃圾桶內的帳戶仍佔用名稱）；永久刪除該帳戶後才能使用該名稱
- [ ] 另一家公司已有同名帳戶 → 不受影響，可正常建立
- [ ] 按「取消」或關閉視窗 → 不建立任何帳戶
- [ ] 沒有幣別選項，金額一律為新台幣

### 2.1 收支表單不能當場新增帳戶

- [ ] 公司已有帳戶時，在新增支出或新增收入的帳戶下拉選單 → 只能選既有帳戶，沒有「新增帳戶」的選項
- [ ] 要多一個帳戶 → 只能到帳戶設定新增，新增後回到收支表單，下拉選單看得到新帳戶
- [ ] 固定收支範本表單、資金移轉表單的帳戶下拉選單 → 同樣沒有「新增帳戶」的選項

## 3. 編輯帳戶

- [ ] 點「編輯」→ 出現預填好的視窗，可改名稱、起始金額與起始月份
- [ ] 編輯視窗沒有「類型」欄位，只能改名稱、起始金額與起始月份
- [ ] 只改名稱後儲存 → 已使用此帳戶的收入、支出、代墊款顯示新名稱
- [ ] 改成與其他帳戶相同的名稱 → 提示名稱重複
- [ ] 沒有做任何修改直接儲存 → 不會誤判為重複，可正常關閉
- [ ] 名稱清空儲存 → 提示請填寫名稱
- [ ] 儲存成功 → 出現已更新提示，列表立即反映

## 4. 修改起始金額與起始月份（二次確認與稽核）

- [ ] 把起始金額從 100,000 改成 120,000 後儲存 → 先出現二次確認視窗，說明原金額與新金額
- [ ] 在二次確認按「取消」→ 起始金額維持原值，不寫入
- [ ] 在二次確認按「確認」→ 起始金額更新，列表顯示新金額
- [ ] 把起始月份從 8 月改成 6 月後儲存 → 先出現二次確認視窗，說明原月份與新月份；確認後列表顯示新月份
- [ ] 起始月份二次確認按「取消」→ 起始月份維持原值
- [ ] 只改名稱、起始金額與起始月份都沒動 → **不會**跳出二次確認
- [ ] 同時改名稱與起始金額（或起始月份）→ 會跳出二次確認；確認後全部更新
- [ ] 修改起始金額後，該帳戶的餘額與各月期初一併反映新金額（起始月份當月的期初等於新起始金額）
- [ ] 稽核紀錄可查到：誰、什麼時間、起始金額由多少改為多少
- [ ] 稽核紀錄可查到：誰、什麼時間、起始月份由哪月改為哪月
- [ ] 修改名稱同樣留下稽核紀錄（變更前後的名稱）

## 5. 起始月份與期初

- [ ] 在 8 月建立帳戶，起始月份選 8 月、起始金額 50,000 → 8 月的期初等於 50,000
- [ ] 查看 1～7 月（現金流報表、帳戶餘額）→ 該帳戶**不顯示**，也不計入這幾個月的合計
- [ ] 8 月以後的各月，期初等於上月期末
- [ ] 起始月份選 3 月（過去月份）建立 → 3 月起就看得到該帳戶，3 月期初等於起始金額
- [ ] 現金流報表切到下一年度 → 該帳戶 1 月的期初現金等於上年 12 月期末，不需手動輸入

### 5.1 實收／實付日期早於起始月份

- [ ] 帳戶起始月份為 8 月，新增一筆「已付款」支出、實付日期在 5 月並選此帳戶 → **可以儲存**；選完日期（或選完帳戶）當下，畫面就提示這筆不計入現金流
- [ ] 同上情境，收入的「已收款」、實收日期在 5 月 → 同樣可以儲存並出現提示
- [ ] 上述紀錄儲存後：該帳戶的現金流與餘額**不計入**這筆
- [ ] 上述紀錄儲存後：損益報表**照常**計入（以發生日計）
- [ ] 待付款／待收款的紀錄（尚無實收／實付日期）→ 不受影響，不出現這類提示
- [ ] 待付款切換為已付款，實付日期填 5 月（早於起始月份）→ 可以儲存並出現不計入現金流的提示；填 8 月以後 → 不提示
- [ ] 先選好日期再改選帳戶（或反之）→ 任一項改動後提示都會即時更新：換到起始月份較早的帳戶 → 提示消失；換回 → 提示出現
- [ ] 實收／實付日期剛好在起始月份當月 → 不提示、正常計入
- [ ] 想把這些 5 月紀錄計入 → 把該帳戶起始月份與起始金額往前調（需二次確認）後，這些紀錄開始計入該帳戶現金流與餘額
- [ ] 憑證辨識的核對畫面、代墊款撥款：實收／實付日期早於所選帳戶起始月份 → 一樣可以儲存，選完日期或帳戶就有不計入現金流的提示
- [ ] Excel 匯入預覽、批次匯入畫面：實收／實付日期早於所選帳戶起始月份的那一筆，在該筆旁標示不計入現金流
- [ ] 代墊款批次通過畫面：通過時還沒有實付日期，所以**不標示**不計入現金流（撥款時才依實付日期提示）
- [ ] 列表上對待付款支出按「標記已付款」，填的實付日期早於該帳戶起始月份 → 視窗內提示不計入現金流，仍可儲存
- [ ] 列表上對待收款收入按「標記已收款」，填的實收日期早於該帳戶起始月份 → 同樣提示，仍可儲存
- [ ] 標記已付款／已收款的日期在起始月份當月或之後 → 不提示
- [ ] 代墊款撥款視窗，實付日期早於該筆所用帳戶的起始月份 → 提示不計入現金流，仍可撥款
- [ ] Excel 預覽中，帳戶是由使用者當場選擇對應（檔內帳戶名稱找不到或在垃圾桶）的那幾列 → 預覽時**不標示**
- [ ] Excel 匯入完成畫面 → 列出本次有幾筆不計入現金流（包含上一點那些當場選帳戶的列）；筆數與實際相符
- [ ] 全部都計入現金流時，完成畫面不出現這類筆數提示

### 5.2 起始月份往後調

- [ ] 帳戶 3～7 月已有已收／已付紀錄，把起始月份從 3 月改到 8 月 → 二次確認視窗提示有幾筆紀錄會不計入現金流（筆數與實際相符）
- [ ] 確認後可以儲存；那些紀錄仍在列表，只是不再計入該帳戶現金流與餘額
- [ ] 損益報表不因此改變
- [ ] 起始月份往後調但沒有任何紀錄受影響 → 二次確認仍出現，但不顯示筆數提示
- [ ] 提示的筆數只算已收款、已付款；待收款、待付款不列入

### 5.3 修改舊紀錄後期初跟著變

- [ ] 去年有一筆已付款支出；現金流報表切到今年 → 今年 1 月的期初現金等於去年 12 月的期末
- [ ] 把去年那筆支出的金額改小 → 回到今年報表，1 月期初現金跟著變（多出差額），不需任何手動處理
- [ ] 把去年的一筆已收款改回待收款 → 今年 1 月期初現金跟著減少該筆金額
- [ ] 修改帳戶起始金額或起始月份 → 之後各月、各年度報表上的期初與期末現金都跟著變
- [ ] 以上改動都**不會**另外在稽核日誌多出紀錄（只會有被改的那筆收支／帳戶本身的編輯紀錄）

## 6. 刪除帳戶

### 6.1 被引用 → 不可刪除

- [ ] 帳戶下有任一筆收入或支出（含待收款、待付款、已收款、已付款）→ 點「刪除」→ 出現不可刪除的提示，說明因已有收支使用，帳戶仍留在列表
- [ ] 帳戶只被「垃圾桶內」的收支使用 → 同樣不可刪除，出現不可刪除的提示
- [ ] 把那些垃圾桶內的收支永久刪除後，帳戶才能刪除
- [ ] 帳戶被代墊款轉成的支出使用 → 同樣不可刪除
- [ ] 帳戶被進行中的固定收支範本使用（即使尚未產生任何紀錄）→ 不可刪除，出現不可刪除的提示
- [ ] 帳戶被已到期（歷史分頁）的範本使用，即使沒有任何收支紀錄 → 同樣不可刪除
- [ ] 帳戶被垃圾桶內的範本使用 → 同樣不可刪除
- [ ] 把使用該帳戶的範本永久刪除，且該帳戶沒有其他收支、資金移轉引用 → 帳戶才可刪除
- [ ] 範本改用另一個帳戶後，原帳戶（沒有其他引用）可刪除

### 6.2 未被引用 → 進入垃圾桶

- [ ] 剛建立、尚無任何收支的帳戶點「刪除」→ 出現確認視窗，確認後該帳戶從列表消失
- [ ] 刪除後到「垃圾桶」→ 看得到該帳戶，並有刪除時間與操作人
- [ ] 刪除不會動到其他帳戶或任何收支資料
- [ ] 已刪除的帳戶不再出現在新增收支的帳戶下拉選單
- [ ] 已刪除的帳戶不計入帳戶合計與現金流報表

### 6.3 垃圾桶：還原

- [ ] 在垃圾桶點帳戶的「還原」→ 帳戶回到帳戶設定列表，名稱、起始金額、起始月份與刪除前相同
- [ ] 還原後可再次出現在新增收支的帳戶下拉選單
- [ ] 垃圾桶內的帳戶仍佔用名稱，因此還原時不會發生名稱撞名
- [ ] 垃圾桶中的帳戶不可編輯

### 6.4 垃圾桶：永久刪除與稽核

- [ ] 在垃圾桶點「永久刪除」→ 出現確認視窗，確認後帳戶從垃圾桶消失
- [ ] 建立、編輯、刪除、還原、永久刪除每個動作都寫入稽核日誌（操作人、時間、變更前後內容）
- [ ] 過去（移除類型之前）建立的帳戶稽核紀錄，仍能看到當初的類型（銀行帳戶／現金），不會消失或顯示空白
- [ ] 永久刪除的那一筆稽核紀錄保存帳戶完整內容（名稱、起始金額、起始月份）；畫面上怎麼查詢之後另做，不在此驗

## 7. 新增支出／收入時選擇帳戶

- [ ] 新增支出時有「帳戶」欄位，且為必填；不選就儲存 → 提示請選擇帳戶，不能存
- [ ] 新增收入時同樣必填
- [ ] 狀態為「待付款」的支出也必須選帳戶，不能略過
- [ ] 狀態為「待收款」的收入也必須選帳戶，不能略過
- [ ] 第一次新增（從未用過）→ 帳戶預設為空，需自行選擇
- [ ] 自己最新建立的一筆是支出、用了「零用金」→ 下次新增支出，帳戶預設帶出「零用金」，可更改
- [ ] 自己最新建立的一筆是收入、用了「永豐-總公司」→ 下次新增支出，預設也帶出「永豐-總公司」（支出與收入共用同一個「上一次使用」）
- [ ] 只算自己建立的：管理員 A 剛用過「零用金」，管理員 B 新增時不會被帶入「零用金」，而是帶 B 自己最新一筆用的
- [ ] 帶入後改選別的帳戶存檔 → 下次預設帶出新選的帳戶
- [ ] 以「建立時間」找自己最新的一筆：先建立 A（用零用金），再建立 B（用永豐）→ 預設帶永豐
- [ ] 編輯較早建立的 A，把日期改成最新、或改了其他欄位 → 不影響順序，預設仍然帶 B 的帳戶（永豐）
- [ ] 最新一筆在垃圾桶內 → 不算，改帶再上一筆（未在垃圾桶）的帳戶；都沒有才是空白
- [ ] 把最新一筆從垃圾桶還原 → 又回到它是最新一筆，預設帶它的帳戶
- [ ] 最新一筆的帳戶事後被改過（編輯換成別的帳戶）→ 預設帶入該筆「目前」的帳戶，不是當初建立時選的
- [ ] 預設帶入的帳戶不會是已刪除（垃圾桶內）的帳戶
- [ ] 公司只有一個帳戶 → 仍須在欄位中確認或預設帶入該帳戶（依規格）
- [ ] 編輯既有的支出或收入時，可更改帳戶，任何狀態（待付款、已付款、待收款、已收款）都可以
- [ ] 更改帳戶後，詳情中的歷程可看到帳戶由哪個改為哪個
- [ ] 把待付款切換為已付款時，帳戶沿用原本選的，不需重選，仍可更改

## 8. Excel 匯入的帳戶

- [ ] 匯入檔可有「帳戶」欄；該列有填帳戶名稱 → 該筆使用檔內指定的帳戶
- [ ] 該列帳戶欄空白 → 帶入上一次使用的帳戶（自己最新建立的一筆收支所用帳戶）
- [ ] 同一份檔案中，有填與空白的列混合 → 各列分別依上述規則處理
- [ ] 檔內填的帳戶名稱在公司內找不到 → 預覽畫面列出這個名稱，由使用者從現有帳戶中選擇對應；選完才能匯入
- [ ] 檔內填的帳戶名稱對應的帳戶在垃圾桶 → 同上，預覽畫面請使用者選擇，不會自動還原或使用垃圾桶內的帳戶
- [ ] 預覽畫面中有任一個帳戶名稱尚未選好對應 → 不能完成匯入
- [ ] 同一個帳戶名稱只需選一次：檔內有 5 列都填「中信」，選好對應後這 5 列全部套用，不需逐列處理
- [ ] 檔內有兩個不同的找不到名稱（例如「中信」「玉山」）→ 各自選擇，互不影響
- [ ] 把某個名稱改選別的帳戶 → 填同樣名稱的所有列一起更新；其他名稱的列不受影響
- [ ] 帳戶欄空白的列不受名稱對應影響，仍帶上一次使用的帳戶
- [ ] 公司沒有任何帳戶 → 不能匯入 Excel，提示先建立帳戶，並有前往帳戶設定的連結
- [ ] 公司沒有任何帳戶時，新增支出／收入不能使用，入口提示先建立帳戶，並有前往帳戶設定的連結；表單裡沒有當場新增帳戶的選項（見 2.1）
- [ ] 在帳戶設定建立第一個帳戶後，回到新增支出／收入 → 可以正常新增，也能選到該帳戶
- [ ] 匯入成功後，每一筆新增的紀錄都有帳戶

## 9. 憑證辨識與批次匯入的帳戶

- [ ] 拍照或上傳憑證辨識後，辨識結果**不會**自動帶入帳戶
- [ ] 在核對步驟，帳戶欄位預設為上一次使用的帳戶，使用者可更改
- [ ] 沒選帳戶就按儲存 → 提示請選擇帳戶
- [ ] 批次匯入多張憑證逐筆核對時，每一筆都要有帳戶才能儲存；切換到下一張時，帳戶預設帶上一張所選
  （「上一張」指剛核對儲存的那一張，而非跨使用者）
- [ ] 其中一張改了帳戶，只影響該張，不影響其他張
- [ ] 批次匯入時移除其中一張 → 不影響其餘張的帳戶設定

## 10. 代墊款與帳戶

- [ ] 員工提交代墊款時，**不需要**也看不到帳戶欄位
- [ ] 管理員核准代墊款時，必須指定帳戶；未指定不能核准
