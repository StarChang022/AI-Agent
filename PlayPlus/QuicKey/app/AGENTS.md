# AGENTS.md

## Git Branch And Modification Rules

在進行任何程式碼修改前，必須先判斷本次需求應歸類在哪一個分支，並告知我判斷結果與原因。未經我確認前，不要直接修改程式碼。

如果我提出的是問題、需求討論、UI/UX 討論或不確定是否需要修改的事項，應先與我分析可行方案與影響範圍。只有在我明確確認要執行修改後，才可以開始修改。

### 分支規則

- `main`
  - 工程師正式開發使用。
  - 用於正式功能、API 串接、後端邏輯與最終整合版本。
  - 不要直接修改或自行合併，除非我明確要求。

- `fix/ui`
  - 僅處理「既有功能」的 UI / UX、版面、元件外觀與樣式調整。
  - 不新增功能。
  - 不修改 API、資料流程或核心業務邏輯。
  - 修改完成後由我自行決定是否合併回 `main`。
  - 若發生 conflict，再交由工程師協助處理。

- `feature/ui`
  - 用於「新功能」的前端 Prototype、UI 與操作流程驗證。
  - 可以使用 Mock Data。
  - 不需要處理正式 API 串接與後端邏輯。
  - Prototype 確認後，由工程師接手正式整合、API 串接並合併回 `main`。

### 修改前流程

準備在 `fix/ui` 或 `feature/ui` 開始修改前，應優先確認是否已同步最新的 `main`，盡量從最新版本開始修改，避免版本差異與 conflict 累積。

### 執行原則

收到需求時，依照以下順序處理：

1. 判斷需求屬於「討論」還是「要求執行修改」。
2. 判斷應使用 `main`、`fix/ui` 或 `feature/ui`。
3. 說明判斷原因，以及預計修改的範圍。
4. 如果只是討論，不修改任何程式碼。
5. 如果需要修改，先等待我確認。
6. 我確認執行後，才開始進行修改。
7. 不要因為需求看起來很明確，就跳過上述確認流程直接修改。
