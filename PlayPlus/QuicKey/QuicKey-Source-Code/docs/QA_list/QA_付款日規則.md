# QA Checklist — 付款日規則與預計付款日

> **驗證對象**：管理員設定每月付款日、以及單筆支出的預計付款日調整。
> **前置**：以管理員身分登入後台，進入「支出管理」頁面。資料為全新狀態時，付款日預設為「每月 5 號」。
> **注意**：本清單只驗證「功能流程與規則」；提示文字顏色、按鈕樣式、下拉動畫等 UI 細節由設計規範統一把關，不在此列。

---

## 1. 設定每月付款日（頁面上方「付款日：每月 X 號」）

- [ ] 進入頁面看到目前付款日（新公司預設「每月 5 號」）
- [ ] 點付款日 → 彈出設定視窗，可選 1–31 號或「關閉自動付款批次」
- [ ] 選跟目前相同的值按儲存 → 直接關閉視窗，不出現 toast、資料不變
- [ ] 選不同的值按儲存 → 出現 toast「付款日：每月 X 號」+「M 月登錄或核准的款項起生效，上月以前已排定的批次不變」
- [ ] 關閉自動付款批次後儲存 → toast 顯示「已關閉自動付款批次」
- [ ] 按「取消」或關閉視窗 → 付款日維持不變
- [ ] 重新整理後付款日仍為最後儲存的值

## 2. 新增支出時「自動排入付款批次」

- [ ] 當月（例：10 月）**20 號之後**新增一筆支出、付款日設 5 號 → 預計付款日自動為「下個月 5 號」（例：11/5）
- [ ] 當月**付款日之前**（例：10/3）新增一筆支出、付款日設 5 號 → 預計付款日自動為「本月 5 號」（例：10/5）
- [ ] 新增時若公司已關閉自動付款批次 → 預計付款日欄位為空
- [ ] 若直接勾選「已付清」建立支出 → 不會有預計付款日（已實際付款、不需排程）
- [ ] 付款日設 31 遇到當月只有 30 天（例：11 月） → 預計付款日落在該月最後一天（11/30）
- [ ] 付款日設 31 遇到 2 月 → 預計付款日落在 2/28（平年）或 2/29（閏年）

## 3. 代墊款核准後自動建立的支出

- [ ] 管理員核准員工的代墊款 → 支出列表多一筆（來源：代墊款）
- [ ] 這筆支出的預計付款日為「核准當下」依公司當時付款日算出的日期（**不是**代墊款填的實際發生日、也**不是**員工提交時間）
- [ ] 核准時公司已關閉自動付款批次 → 預計付款日為空

## 4. 變更付款日的影響範圍（「本月為界」）

**前置**：準備多筆支出橫跨幾個月份，包含本月、上月、以前月份。

- [ ] 把付款日從 5 號改成 10 號 → 看到 toast 顯示影響本月款項的提示
- [ ] 檢查**本月**新增、且狀態為「待付款」的支出 → 預計付款日改成新規則算出的日期（例：10/5 → 10/10）
- [ ] 檢查**上月以前**新增的支出，不論狀態 → **預計付款日維持不變**（這批是「已排定、要付的這批」）
- [ ] 檢查**已付款**（本月或任何月份）的支出 → 預計付款日**不受影響**（已實際付款、歷史不改）
- [ ] 檢查**本月被鎖定（手動調整過）**的支出 → 預計付款日**不被覆蓋**
- [ ] 關閉自動付款批次 → 本月待付款且未鎖定的支出，預計付款日變成空

## 5. 單筆調整預計付款日

- [ ] 待付款的支出有「調整付款日」入口（單筆列選單、或多筆勾選後批次操作）
- [ ] 進入視窗 → 看到該筆目前的預計付款日（已有的話預填、否則為空）
- [ ] 選一個日期按儲存 → 預計付款日改為選擇的值
- [ ] 這筆支出之後若公司變更付款日 → **不會被覆蓋**（已鎖定）
- [ ] 已鎖定的支出在列表上有可辨識的方式（例：圖示或 tooltip 區分）
- [ ] 清空日期後儲存（或按「改回自動排程」） → 預計付款日用「當前付款日」重新算一次，鎖定解除
- [ ] 解除後再變更公司付款日 → 這筆**會跟著重算**

## 6. 多筆批次調整

- [ ] 勾選多筆待付款支出 → 可以一次「調整付款日」
- [ ] 批次設定後，每一筆都變成已鎖定狀態
- [ ] 批次清空後，每一筆都解除鎖定、各自用「當前付款日」+「各自的登錄日」重新算（**不是**全部變成同一天）

## 7. 不能調整的情境

- [ ] 已付款的支出 → **沒有**「調整付款日」入口
- [ ] 已作廢（如適用）的支出 → **沒有**「調整付款日」入口
- [ ] 若透過其他方式嘗試改已付款支出的預計付款日 → 操作被擋

## 8. Dashboard 與列表的連動

**後台儀表板**
- [ ] 「下次付款」顯示的是所有待付款支出中、最近未到期的預計付款日
- [ ] 「逾期未付」顯示預計付款日已過今天但狀態仍為待付款的支出
- [ ] 「未來 7 天付款額」依每一天的預計付款日彙總

**支出管理列表**
- [ ] 篩選「待付款」時，支出依預計付款日分組（「10/5 付款批次」「10/10 付款批次」等），逾期的獨立成一組
- [ ] 關閉自動付款批次後，分組顯示關閉、恢復單一列表
- [ ] 變更付款日後、重新開啟列表，分組立即反映新日期

## 9. 跨時區／跨日邊界

- [ ] 在接近午夜時操作「變更付款日」 → 「本月」的判定以**台灣時間**為準，不會因為伺服器時區偏移而把前一分鐘新增的支出算成上個月
- [ ] 在接近月初（例：10/1 00:30）變更付款日 → 10/1 當天新增的支出算「本月」要跟著重算；9/30 新增的算「上月」不動

## 10. 資料保留

- [ ] 設定付款日、調整單筆、解除鎖定後，重新整理頁面 → 狀態仍在
- [ ] 關閉瀏覽器再打開 → 狀態仍在

## 已知不覆蓋（out of scope）

- 歷次付款日變更紀錄的瀏覽介面（目前僅後端保留審計資料，前台無頁面）
- 多公司／多工作區情境
- 以日曆方式一次指定多個「不規則付款日」（例：5 號 + 20 號雙付款日）
- 付款日變更的 Email / 通知推播
