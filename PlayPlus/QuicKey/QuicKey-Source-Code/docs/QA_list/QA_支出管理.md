# QA Checklist — 支出管理（刪除時連動作廢來源代墊款）

> **驗證對象**：管理員在支出管理刪除支出時，與「來源代墊款」之間的連動規則（規格第 12 條）。本份清單目前只涵蓋此情境，支出管理的其他功能之後再補。
> **前置**：以管理員身分登入後台。需準備：（A）一筆手動登錄的一般支出；（B）一筆由員工代墊款核准後併入的支出（來源是代墊款），狀態為待付款；（C）另一筆來源是代墊款、狀態為已付款的支出；（D）另一筆仍在「簽核中」的代墊款，用來觀察側邊欄簽核數字。
> **注意**：本清單只驗證「功能流程與規則」；顏色、字級、按鈕樣式等 UI 細節由設計規範統一把關，不在此列。

---

## 1. 一般支出移至垃圾桶

- [ ] 對一般支出（A）按刪除 → 確認視窗只詢問是否移至垃圾桶，**沒有**「同時作廢來源代墊款」的選項
- [ ] 確認後 → 該筆支出從列表消失，出現在垃圾桶

## 2. 代墊款來源的支出移至垃圾桶

- [ ] 對來源是代墊款的支出（B）按刪除 → 確認視窗出現「同時作廢來源代墊款」的選項，**預設沒有勾選**
- [ ] 不勾選直接確認 → 支出移至垃圾桶；到請款記錄看來源代墊款，狀態**維持原樣**（沒有被作廢）
- [ ] 勾選「同時作廢來源代墊款」→ 出現必填的「作廢原因」欄位
- [ ] 勾選但不填原因就確認 → 被擋下並提示請填寫原因，支出仍留在列表、代墊款不變
- [ ] 勾選並填入原因後確認 → 支出移至垃圾桶，來源代墊款狀態變成「已作廢」
- [ ] 打開該代墊款詳情看歷程 → 看得到這次作廢紀錄與填寫的原因、操作人與時間
- [ ] 取消或關閉視窗 → 支出與代墊款都不變

## 3. 代墊款來源的支出永久刪除

- [ ] 在垃圾桶對來源是代墊款、且代墊款尚未作廢的支出按永久刪除 → 確認視窗說明會同時作廢來源代墊款，**沒有勾選項**（一律同時作廢），並出現必填的「作廢原因」欄位
- [ ] 不填原因就確認 → 被擋下並提示請填寫原因，支出仍在垃圾桶、代墊款不變
- [ ] 填原因後確認 → 支出永久刪除，來源代墊款變成「已作廢」，歷程看得到原因
- [ ] 取消或關閉視窗 → 支出與代墊款都不變
- [ ] 一般支出永久刪除 → 沒有作廢選項

## 4. 來源代墊款已作廢時

- [ ] 來源代墊款已作廢（例如先在請款記錄作廢，支出隨之進垃圾桶），再對該支出永久刪除 → **不再詢問**是否作廢，直接走一般的永久刪除確認

## 5. 從請款記錄作廢／取消作廢

- [ ] 在請款記錄對**已核准**的代墊款按作廢並填原因 → 代墊款變成「已作廢」，對應的支出自動進入垃圾桶，支出列表看不到
- [ ] 對**簽核中**的代墊款作廢 → 變成「已作廢」，支出列表沒有任何變化（尚未產生支出）
- [ ] 對**簽核中**的代墊款取消作廢 → 回到「簽核中」，側邊欄簽核數字 +1
- [ ] 對**駁回**的代墊款作廢後取消作廢 → 回到「駁回」
- [ ] 對**已核准**的代墊款作廢後取消作廢 → 回到「已核准」，對應的支出自動從垃圾桶回到支出列表
- [ ] 取消作廢後打開代墊款歷程 → 看得到作廢與取消作廢兩筆紀錄
- [ ] 對已核准的代墊款作廢後，把垃圾桶裡的對應支出永久刪除，再回請款記錄取消作廢 → 被擋下，提示請申請人重新提交；代墊款仍是「已作廢」
- [ ] 已撥款（已付款）的代墊款 → 沒有作廢選項

## 6. 從垃圾桶還原

- [ ] 來源代墊款已作廢的支出，在垃圾桶按還原 → 被擋下，提示需先到請款記錄取消作廢；支出仍在垃圾桶
- [ ] 到請款記錄對該代墊款按「取消作廢」→ 代墊款恢復作廢前的狀態，對應支出自動回到支出列表
- [ ] 回到垃圾桶 → 該支出已不在垃圾桶
- [ ] 來源代墊款**沒有**被作廢的支出（例如第 2 節不勾選的情況）在垃圾桶按還原 → 可直接還原回列表
- [ ] 一般支出在垃圾桶按還原 → 可直接還原

## 7. 已付款的支出不能刪

- [ ] 對已付款的支出（C）按刪除 → 被擋下，提示需先切回待付款才能刪除，不會出現作廢選項
- [ ] 先把該支出切回待付款，再按刪除 → 可進入第 2 節的流程

## 8. 側邊欄簽核數字

- [ ] 記下側邊欄「簽核」目前的數字（含簽核中的代墊款 D）
- [ ] 刪除並作廢來源代墊款（第 2 節勾選流程）→ 簽核數字**不變**（該代墊款已核准、不在待簽核中；仍在簽核中的 D 照常計入）
- [ ] 作廢後切到其他頁面再回來 → 數字仍正確
- [ ] 在請款記錄對 D 做核准、駁回或作廢 → 簽核數字立即減少 1
- [ ] 員工送出新請款後，管理員切換頁面或切回此分頁 → 簽核數字增加

## 9. 編輯支出時切換付款狀態

- [ ] 代墊款來源、待付款的支出，打開編輯頁把付款狀態改成「已付款」→ 出現「發放方式」（匯款／現金），預設選匯款
- [ ] 改選「現金」後儲存 → 儲存成功，支出變「已付款」
- [ ] 到請款記錄看該代墊款 → 狀態變「已發放」，發放方式是「現金」，與剛才選的相同
- [ ] 一般支出（非代墊款）在編輯頁改成「已付款」→ **不會**出現發放方式，可直接儲存
- [ ] 原本就是已付款的代墊款支出，打開編輯頁 → 看得到目前的發放方式，只能看不能改，畫面說明要先改回待付款並儲存，再重新標記已付款
- [ ] 儲存失敗（例如這筆支出已被別人刪除）→ 看到中文說明（如「更新支出失敗，請稍後再試」），不是英文或系統代碼；停留在編輯頁，輸入內容還在
- [ ] 代墊款來源的支出改成已付款後，請款記錄的詳情看得到發放方式，與當時選的一致
- [ ] 同一筆，員工前台的請款詳情也看得到發放方式，與當時選的一致
- [ ] 把該支出改回待付款後，請款記錄詳情與員工前台詳情都不再顯示發放方式

## 10. 標記已付款的付款日

> **前置**：準備幾筆待付款支出，預計付款日各不相同，其中有已到或已過的、也有還在未來的；另備一筆沒有預計付款日的支出（例如公司關閉自動付款批次後新增的）。代墊款來源與一般支出各備一組。

### 付款日等於預計付款日
- [ ] 在支出列表的選單對一筆標記為已付款 → 不會跳出日期選擇，付款日等於該筆的預計付款日，不是今天
- [ ] 在詳情抽屜標記已付款 → 同上，付款日等於預計付款日
- [ ] 預計付款日還沒到的支出，直接標記已付款 → 不會跳日期選擇，付款日等於預計付款日（未來的那一天）
- [ ] 一次勾選多筆（預計付款日各不相同）批次標記已付款 → 每一筆的付款日各自等於自己的預計付款日（不是全部同一天）
- [ ] 沒有預計付款日的支出標記已付款 → 付款日是當天

### 標記已付款的確認視窗
- [ ] 一般支出點「標記為已付款」→ 跳出確認視窗，寫明「付款日為預計付款日 YYYY/MM/DD」（日期就是該筆的預計付款日）
- [ ] 在確認視窗按取消 → 支出維持待付款，沒有任何變化
- [ ] 在確認視窗按確認 → 支出變已付款，付款日就是視窗上寫的那一天
- [ ] 沒有預計付款日的支出點標記已付款 → 確認文字寫「付款日為今天」；確認後付款日是當天
- [ ] 代墊款來源的支出點標記已付款 → 同一個確認視窗裡同時有「發放方式」與付款日說明；選好發放方式並確認後，發放方式與付款日都正確
- [ ] 批次勾選多筆標記已付款 → 確認視窗說明付款日為各筆的預計付款日；確認後每一筆的付款日各自等於自己的預計付款日
- [ ] 在詳情抽屜標記已付款 → 同樣先跳出確認視窗，內容規則與列表相同

### 想用今天當付款日
- [ ] 對預計付款日不是今天的支出，先用「調整付款日」把預計付款日改成今天，再標記已付款 → 付款日是今天

### 編輯頁
- [ ] 把待付款改成已付款 → 付款日欄位預先帶入預計付款日
- [ ] 手動改掉付款日再儲存 → 付款日以手動填的為準，不被預計付款日蓋掉

### 再次標記與代墊款
- [ ] 待付款支出標記已付款後，在編輯頁把付款日改成別的日期，再改回待付款 → 預計付款日變成剛剛改過的那個付款日
- [ ] 接上一條，再標記已付款 → 確認視窗顯示的日期就是改過的付款日，確認後付款日也是它，不是最早的預計付款日
- [ ] 標記已付款後付款日沒改過，直接改回待付款 → 預計付款日維持不變
- [ ] 建立時就選已付款的支出，改回待付款 → 預計付款日等於原本的付款日
- [ ] 代墊款來源的支出標記已付款，且預計付款日還沒到 → 發放方式照常要選，不會多出日期選擇；付款日等於預計付款日
- [ ] 代墊款來源的支出標記已付款後，到請款記錄看該代墊款 → 發放日與支出的付款日一致
- [ ] 員工前台看同一筆請款 → 發放日也與付款日一致
- [ ] 已付款的代墊款來源支出，在編輯頁把付款日改成別的日期並儲存 → 後台請款詳情與員工前台請款詳情的發放日，都跟著變成新的付款日

### 通過
- 第 1 節：一般支出刪除的確認視窗沒有作廢選項，確認後支出進垃圾桶。
- 第 2 節：
  - 代墊款來源的支出有「同時作廢來源代墊款」，預設未勾。
  - 不勾選刪除後，代墊款維持「已核准」。
  - 勾選未填原因被擋，提示「請填寫作廢原因」。
  - 填原因後代墊款變「已作廢」，歷程看得到原因。
- 第 3 節：
  - 代墊款尚未作廢時，永久刪除沒有勾選項，直接要求填作廢原因。
  - 不填原因被擋，視窗不關。
  - 填原因後支出永久刪除，代墊款變「已作廢」，歷程有原因。
- 第 4 節：已作廢代墊款的支出永久刪除時不再詢問，直接刪除。
- 第 5 節：
  - 已核准作廢後，支出進垃圾桶。
  - 簽核中作廢，支出列表不變。
  - 簽核中、駁回、已核准取消作廢，各自回到作廢前狀態。
  - 已核准取消作廢後，支出回到列表。
  - 歷程有作廢與取消作廢兩筆紀錄。
  - 支出已永久刪除時取消作廢被擋，畫面顯示「對應的支出已永久刪除，無法取消作廢，如需撥款，請申請人重新提交請款。」
- 第 6 節：
  - 來源已作廢的支出在垃圾桶不能還原，被擋下。
  - 取消作廢後支出回到列表。
  - 來源未作廢的支出可直接還原。
- 第 7 節：已付款的支出刪除被擋，提示需先切回待付款。
- 第 8 節：
  - 核准、退回後側邊欄簽核數字立刻減少（3→2→1→0）。
  - 作廢已核准代墊款，數字不變。
  - 換頁後數字正確。
  - 有新請款送出後，切換頁面數字增加。

### 補核對（2026-10-28，前端 dc94d62）
- 簽核中的請款單在詳情抽屜有「作廢」按鈕：
  - 不填原因被擋，按取消則狀態不變。
  - 填原因後變「已作廢」，簽核數字立即減 1（2→1）。
  - 取消作廢回到「簽核中」，簽核數字加 1（1→2）。
- 第 2 節「取消或關閉視窗 → 都不變」：勾選作廢後按取消，支出與代墊款都不變。
- 第 7 節：已付款支出刪除被擋，切回待付款後可刪，出現作廢選項。
- 第 3 節「一般支出永久刪除沒有作廢選項」：確認視窗只問是否永久刪除，按下後支出從垃圾桶消失。

### 第 9 節核對（前端 #11）
- 通過：
  - 代墊款來源支出改已付款，出現「發放方式」，預設匯款。改選現金儲存後，代墊款變「已發放」，發放方式為現金。
  - 一般支出改已付款不出現發放方式，可直接儲存。
  - 已付款代墊款的編輯頁顯示目前發放方式（現金），只能看，並說明要先改回待付款再重新標記。
  - 儲存失敗（支出已被刪除）時顯示「更新支出失敗，請稍後再試。」，停留在編輯頁且輸入保留。
- 與原清單不同：發放方式預設已選匯款，沒有「未選」狀態，所以原本「不選就儲存被擋」那條已刪。
- 失敗訊息偏籠統（「請稍後再試」），沒有說明是支出已不存在；是否可接受請規劃決定。

### 第 9 節核對（前端 #12）
- 通過：
  - 代墊款來源支出改成已付款（選現金）後，後台請款詳情與員工前台請款詳情都顯示發放方式「現金」，與當時選的一致。
  - 把該支出改回待付款後，兩邊都不再顯示發放方式。
