# QA Checklist — 新手導覽

> **驗證對象**：admin 首次登入後台自動觸發 11 步新手導覽、員工首次登入前台自動觸發 4 步新手導覽、可隨時關閉、可從使用者選單重跑；桌機與手機皆需完整支援。
> **前置**：請工程師先清空瀏覽器 localStorage（key `quickey.onboarding.v1`），或改用另一個未跑過導覽的測試帳號。
> **測試帳號**：[admin@example.com](mailto:admin@example.com)（管理員）、[ming@example.com](mailto:ming@example.com)（員工）；密碼皆為 `password123`。
> **注意**：本清單只驗證「功能流程與規則」；顏色、字級、按鈕樣式等 UI 細節由設計規範統一把關,不在此列。

---

## 1. 首次觸發

- [x] 以未跑過導覽的管理員登入 → 進入儀表板後,畫面自動彈出導覽提示卡,標題為「歡迎使用 Quickey」;開場後會自動跳到「支出管理」頁做第 1 步定位
- [x] 以未跑過導覽的員工登入 → 進入前台首頁後,畫面自動彈出導覽提示卡,標題為「歡迎使用 Quickey」;開場後會自動跳到「新增代墊款」頁做第 1 步定位
- [x] 已完成導覽的使用者再度登入 → 進入首頁不會彈出導覽
- [x] 已完成的使用者重整瀏覽器 → 仍然不會再彈出導覽
- [x] 員工登入前台看到的是員工版導覽（4 步），不會出現管理員版本的內容
- [x] 管理員登入後台看到的是管理員版導覽（11 步），不會出現員工版本的內容



## 2. 管理員導覽（11 步）流轉

- [ ] 步驟 1（歡迎使用 Quickey）：頁面自動切到「支出管理」→ 打亮「新增支出」按鈕；sidebar「支出管理」打亮；提示卡描述提到接下來 11 步
- [ ] 步驟 2（填寫支出內容）：按「下一步」→ 頁面切到「新增支出」→ 打亮憑證上傳與辨識區塊
- [ ] 步驟 3（查看支出列表）：按「下一步」→ 頁面切回「支出管理」→ 打亮支出表格
- [ ] 步驟 4（查看請款記錄）：按「下一步」→ 頁面切到「請款記錄」→ 打亮請款清單
- [ ] 步驟 5（簽核代墊款）：按「下一步」→ 頁面切到「簽核」→ 打亮待簽核清單；手機／平板下清單會自動水平捲到最右,讓「通過／駁回」按鈕可見
- [ ] 步驟 6（發放核銷款項）：按「下一步」→ 頁面切到「發放」→ 打亮待發放清單；手機／平板下清單會自動水平捲到最右,讓「標記已付款」按鈕可見
- [ ] 步驟 7（設定費用類別）：按「下一步」→ 頁面切到「類別管理」→ 打亮「新增類別」按鈕
- [ ] 步驟 8（建立第一筆預算）：按「下一步」→ 頁面切到「預算管理」→ 打亮整個預算頁面（PageHeader + 表格）,頁面標題未被切掉
- [ ] 步驟 9（邀請員工）：按「下一步」→ 頁面切到「人員管理」→ 打亮「邀請員工」按鈕
- [ ] 步驟 10（儀表板）：按「下一步」→ 頁面切到「儀表板」→ 打亮整個儀表板區塊（含「本月支出／未結清代墊款」KPI 與圖表）,頁面標題未被切掉
- [ ] 步驟 11（新手導覽）：按「下一步」→ 停在儀表板頁 → 右上角使用者選單自動展開 → 打亮「新手導覽」選項；按鈕文字變成「完成」
- [ ] 點「完成」→ 使用者選單自動收起、導覽關閉、sidebar 打亮效果同步消失、使用者停留在「儀表板」頁
- [ ] 每一步的提示卡右下角顯示「第 X 步 / 共 11 步」進度文字
- [ ] 手機（375px）執行任一步時,sidebar 藏在 drawer 內看不到打亮效果,頁面內 target 仍照常打亮
- [ ] 任一步按「上一步」→ 回到前一步的頁面 + target,不會停在原頁只顯示中央提示卡；從步驟 11 按「上一步」→ 使用者選單會自動收起,再顯示步驟 10 的儀表板打亮



## 3. 員工導覽（4 步）流轉

- [ ] 步驟 1（歡迎使用 Quickey）：頁面自動切到「新增代墊款」→ 打亮憑證上傳區塊(拍照／選擇檔案／開始辨識按鈕整組)；頁面標題「新增代墊款」未被切掉；提示卡描述提到接下來 4 步
- [ ] 步驟 2（追蹤代墊款進度）：按「下一步」→ 頁面切到「歷史記錄」→ 打亮清單(若無資料則提示卡顯示在畫面中央)
- [ ] 步驟 3（首頁一覽）：按「下一步」→ 頁面切到首頁 → 打亮整個首頁(問候語 + 待收款／已發放 KPI + 最近請款紀錄)
- [ ] 步驟 4（新手導覽）：按「下一步」→ 停在首頁 → 右上角使用者選單自動展開 → 打亮「新手導覽」選項；按鈕文字變成「完成」
- [ ] 點「完成」→ 使用者選單自動收起、導覽關閉,使用者停留在「首頁」
- [ ] 每一步的提示卡右下角顯示「第 X 步 / 共 4 步」進度文字
- [ ] 任一步按「上一步」→ 回到前一步的頁面 + target；從步驟 4 按「上一步」→ 使用者選單會自動收起,再顯示步驟 3 的首頁打亮



## 4. 隨時關閉

- [ ] 任一步右上角有「結束導覽」文字按鈕(不是 X icon)
- [ ] 在第 3 步按「結束導覽」→ 導覽立刻關閉、使用者停留於當前頁；若當時使用者選單為開啟狀態(第 11 / 4 步),選單會一併收起
- [ ] 關閉後重整頁面 → 不會再自動彈出導覽
- [ ] 按鍵盤 Esc → 效果等同按「結束導覽」(關閉並記為完成,選單也會收起)
- [ ] 點提示卡以外的畫面遮罩區 → 導覽**不會**被關閉,仍停留於當前步驟



## 5. 重跑導覽

- [ ] 管理員後台右上角頭像展開的選單,由上至下順序為：新手導覽、修改密碼、登出
- [ ] 員工前台右上角頭像展開的選單,順序同上
- [ ] 管理員選單點「新手導覽」→ 導頁到儀表板 → 開場後自動跳到「支出管理」開始第 1 步
- [ ] 員工選單點「新手導覽」→ 導頁到首頁 → 開場後自動跳到「新增代墊款」開始第 1 步
- [ ] 管理員在「人員管理」頁點「新手導覽」→ 會先跳回儀表板才啟動,不是原地啟動
- [ ] 管理員已在儀表板時點「新手導覽」→ 不會因為 remount 疊出兩層遮罩或兩張提示卡
- [ ] 員工已在首頁時點「新手導覽」→ 同上,不會疊層



## 6. Per-user 隔離

- [ ] 管理員 A 完成導覽後登出 → 換 B 帳號登入 → B 仍會被觸發導覽
- [x] 員工 X 完成導覽後登出 → 換另一位員工 Y 登入 → Y 仍會被觸發導覽
- [x] 管理員完成後台導覽 → 之後以員工帳號登入前台 → 員工仍會被觸發前台導覽(兩種角色的完成狀態互不干擾)



## 7. 損毀資料容錯

- [x] 用開發者工具把 localStorage `quickey.onboarding.v1` 改成非法內容(例如 `not-json`)→ 重新載入不會白畫面,導覽會被視為未完成
- [x] 以隱私模式(不允許 localStorage)登入 → 導覽仍會彈出、按完可正常關閉、但下次瀏覽器重開又會彈(此為預期行為)



## 8. 桌機版驗收（1440px 或更寬）

- [ ] 執行管理員 11 步 → 每步 target 被完整打亮,提示卡不重疊主內容
- [ ] 執行員工 4 步 → 每步 target 被完整打亮,提示卡不重疊主內容
- [ ] 提示卡側邊自動選擇合適方向(有時在上、有時在下),不會固定死於單一方向
- [ ] 尾步(第 11 / 4 步)使用者選單展開時,選單本身處於灰色遮罩下,只有「新手導覽」項目被挖亮



## 9. 手機版驗收（375px viewport）

> 使用 Chrome DevTools 切裝置模擬 → 選 iPhone SE (375px) 或類似機型；若手邊有 iOS 裝置,另以真實 Safari 走一次。

- [ ] 執行管理員 11 步：每步 target 被自動捲到視窗中央 → 提示卡完整顯示、未被視窗邊緣截切
- [ ] 管理員第 5、6 步（簽核／發放）：清單自動水平捲到最右,「通過／駁回」與「標記已付款」按鈕出現在畫面內,且捲動有平滑動畫、不會延遲 1 秒才捲
- [ ] 管理員第 11 步：使用者選單展開後,「新手導覽」項目被打亮且完整顯示於畫面內
- [ ] 執行員工 4 步：每步同上驗收
- [ ] 員工第 1 步(新增代墊款)：憑證上傳區塊被打亮,頁面標題「新增代墊款」仍可見,不會因捲動被推出畫面
- [ ] 員工第 4 步：使用者選單展開後,「新手導覽」項目被打亮且完整顯示於畫面內
- [ ] 提示卡未被 iOS 底部主頁指示器擋住



## 10. 樣式與無障礙

- [ ] 提示卡圓角與 Quickey 其他卡片風格一致(非 driver.js 預設樣式)
- [ ] 「下一步」/「完成」按鈕使用 Trust Blue 主色
- [ ] 用鍵盤 Tab 移到提示卡按鈕時,按鈕顯示可見的 focus outline
- [ ] 用 Enter 鍵可以觸發「下一步」按鈕
- [ ] 螢幕閱讀器(VoiceOver / TalkBack)可讀出提示卡的標題與說明文字
- [ ] 手機版提示卡內文字級不超過 14px



## 11. 已知限制

- [ ] 導覽進度不會續跑：跑到第 5 步關閉,下次「重跑導覽」仍從第 1 步開始
- [ ] 導覽以 localStorage per user id 記錄完成狀態,換裝置登入需重跑一次(後端接完後才能跨裝置同步)
- [ ] 若某頁的 target 因未來重構被移除,該步的提示卡會顯示於畫面中央(無挖空遮罩),不會 crash
