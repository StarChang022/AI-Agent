# 文章重點架構

## 1. AI 快速摘要（對應 `.blog-summary-card`）

- **摘要格式**：固定撰寫 3 點文章快速摘要（置於內文開頭、封面圖正下方的「摘要卡片」區塊），每點由「**6～10 字粗體小標題**：」加上「**40～60 字具體摘要段落**」組成。
- **三點結構與 AEO 獨立性**：每點皆須包含明確主詞與結論（避免代名詞指涉不明，方便 AI 搜尋引擎直接擷取引用），依序涵蓋：
  1. **核心觀念或隱形營運痛點**：一針見血點出企業常見的管理盲點或無效成本。
  2. **標竿案例、專家觀點或趨勢啟示**：提煉國內外知名標竿產品、產業領袖或趨勢文章的核心洞見。
  3. **數據實證價值或關鍵行動結論**：結合權威統計數據或具體落地步驟，點出可衡量的商業紅利。

## 2. 基本設定（對齊 HTML MetaTag 與頁面標頭規格）

- **文章主標題（H1）與備選標題**：定義具備吸引力、融入核心關鍵字且直擊企業營運迷思或商業紅利的 H1 主標題，並額外提供 2 個不同切角的備選標題。標題嚴禁使用破折號（`—` / `——`）與「不是…而是…」句型。
- **SEO `<title>` 與列表簡短標題（`name`）**：將核心目標關鍵字前置，主標題長度控制在 **25～30 個中文字**內（完整 `<title>` 後綴 ` | 知識筆記 | PlayPlus 普魯士國際`），確保 `<title>`、H1、URL Slug 與 Meta Description 四者主題高度一致。
- **Meta Description（`description`）**：控制在 **70～85 個中文字**，自然融入核心與次要關鍵字。**直接告訴讀者本文的核心結論、實證數據與商業價值**，嚴禁出現「本文將…」、「深入探討」、「本篇將為您剖析…」等預告式廢話。
- **分類標籤（`tags`）**：嚴格依據 `部落格標籤.md` 挑選 **1 至 3 個**最契合的標籤（僅限：`系統開發`、`網頁設計`、`UI/UX`、`數位轉型`、`需求規劃`、`預算報價`、`AI 與工具`、`案例趨勢`），並簡述選用理由。
- **導讀描述（Lead，`.blog-detail-lead`）**：約 **80～150 字**，放置於 H1 標題與分類標籤下方，開門見山點出企業常見盲點、標竿／數據啟示與本文核心主張（零時代背景廢話）。
- **發佈日期、檔案 ID 與路徑（Slug）**：設定發佈日期（`YYYY/MM/DD`）、文章唯一 ID（`{YYYYMMDD}-{english-slug}`）、對應 HTML 路徑 `blog/{id}.html` 與封面圖路徑 `images/blog/{id}/cover.webp`。若有參考外部原文，須明確列出原文標題、媒體／作者與外部連結（對應 `.blog-source-link`）。
- **撰寫語氣**：理性、務實且具啟發性的數位科技與 UI/UX 顧問語氣（可適度結合價值投資的「資本配置效率、安全邊際與階段性回報驗證」商業視角），將國際研調數據、具名專家引述與第一線專案輔導經驗轉化為決策者聽得懂的商業語言。

## 3. 文章目的

明確定義發布此篇知識筆記的核心商業價值、資訊增益與流量目標：

- **獨特資訊增益（Information-Gain Gate）**：用一句話明確定義本文提供了什麼現有搜尋結果前 10 名沒有的獨特顧問價值（例如：可直接套用的流程體檢問句、結構化評估對比表、五年 TCO 成本視角或第一線防呆實務）。
- **提升自然流量與 AI 引用（SEO / AEO / GEO）**：爭取決策評估長尾詞與轉型痛點詞的傳統搜尋排名，並透過「首段直答塊＋結構化對比表＋具名數據引述」設計，極大化 ChatGPT、Perplexity、Claude 與 Google AI Overviews 的引用與推薦機率。
- **建立專業顧問心智**：展現 PlayPlus「先理解商業流程、再設計 UI/UX、後分階段開發」的顧問高度，與傳統「照單全收寫程式」的外包代工廠商拉開明確差距。
- **破解經營迷思**：針對中小企業決策者的慣性盲點（如：把糟糕流程直接數位化、誤以為轉型必須一次砸數百萬翻新全公司、認為功能能動就不需優化 UI/UX 等），提供具數據與案例支撐的務實解答。
- **導向低阻力諮詢轉換**：卸下企業主對高昂預算與系統改版的恐懼，於內文第 3 大段及文末總結自然引導預約 PlayPlus 一對一顧問諮詢。

## 4. 目標受眾（對齊 `目標受眾.md` 決策者輪廓）

鎖定讀者輪廓與買家心理階段，確保文章深淺度與說服路徑精準對位：

- **受眾身分与客群分類**：明確對應 `目標受眾.md` 中的決策者職位（10～150 人中小企業負責人、COO、二代接班人、特助或部門主管）與典型客群（客群 A【套版軟體受害者】、客群 B【手工與 Excel 極限者】或客群 C【體驗與整合追求者】）。
- **目前狀態（Current Discomfort）**：具體描繪受眾當前的真實營運場景（如：跨部門重複登打 Excel、紙本跑腿簽核、舊系統介面繁瑣導致新人培訓困難、官網頁面重複雜亂卻無詢問轉換），讓讀者一讀就產生「這說的就是我們公司」的共鳴。
- **受眾痛點與決策恐懼**：點出受眾遲遲不敢行動的顧慮（對應四大恐懼：怕溝通不良雞同鴨講、怕系統做出來員工不用、怕時程延宕預算黑箱、怕上線後變系統孤兒）。
- **理想行動（Path to Action）**：讀完後能打破既有盲點，掌握分階段、高安全邊際的具體推進步驟，並願意聯繫 PlayPlus 顧問團隊進行初步需求訪談與流程梳理。

## 5. 文章主題定義

界定分析範圍，聚焦核心商業與設計邏輯並防範內容發散：

- **核心主題**：明確界定本次探討的數位轉型、系統開發、網頁架構或 UI/UX 商業價值命題。
- **主要問題（對齊 AEO / GEO 自然語言提問）**：列出本篇負責解答的 1～2 個決策者核心疑問（須採用決策者向 Google 或 AI 助理提問的自然語言句型）。
- **不處理的範圍**：劃定明確的內容邊界（例如：聚焦於商業決策邏輯、流程體檢指標與分步落地策略，不涉入艱澀的底層程式碼語法細節或無關的組織政治理論），確保全文緊湊不失焦。
- **內部連結與延伸閱讀佈局（Internal Linking）**：
  - **站內核心服務／諮詢頁連結**：規劃於內文第 3 大段及總結自然嵌入的 1～2 個核心頁面路徑（如 `../services/enterprise-system.html`、`../services/web-design.html`、`../services/app-development.html`、`../services/chatbot-development.html` 與 `../contact.html`），並設計**具體描述性錨點文字**（嚴禁使用「點擊這裡」、「這篇文章」）。
  - **文末「更多文章」推薦**：從 `playplus2026/blog/` 現有文章中，挑選 **3 則過去日期**且主題高度關聯的知識筆記（完整列出發佈日期、文章標題、檔案路徑與分類標籤）。

## 6. 搜尋意圖與關鍵字規劃（對齊 `關鍵字.md`）

針對企業決策者評估轉型與搜尋知識時的行為進行 SEO / AEO / GEO 佈局：

- **切入角度**：結合第一線輔導客戶常聽到的真實原話（VoC）破題，串聯國際權威研調數據、具名專家原話與標竿案例，將抽象的技術或設計概念轉化為算得出的營運紅利。

## 7. 文章核心觀點（融合 Princeton GEO 權威引用法則）

列出文章的靈魂主張，觀點必須建立在「商業效益邏輯」與「實務經驗驗證」基礎上。**嚴守證據紀律：所有數據與引述必須來自參考資料或真實事實，若缺數據請標註 `[NEED: 補充真實數據/案例]`，嚴禁捏造假數據或假故事**：

- **主要觀點**：條列 1 至 3 點貫穿全文、具備鮮明顧問立場的核心主張（需通過「競品替換測試 Swap Test」與「畫面感測試」）。

## 8. 內容大綱（嚴格對齊官網知識筆記 HTML 標準結構）

我追求的不是「每篇文章文字千篇一律」，而是「每篇知識筆記的思考脈絡、AEO 擷取結構與說服路徑一致」。每個段落都必須有具體觀點、數據引用、案例推論或執行建議，嚴禁重複描述同一概念，並徹底排除 `通用規範.md` 與 `digital-marketing.md` 所列之 AI 寫作破綻（禁用「不是…而是…」、禁用「不用 X、不用 Y、不用 Z」、減少「從…到…」與「解析」、標題零破折號、消除空洞形容詞）。

文章大綱必須嚴格具備以下六大標準區塊（對齊 `blog/20260724-ui-ux-system-optimization-value.html`、`blog/20261123-b2b-website-clear-navigation-trust.html` 與 `blog/20261124-dont-digitize-bad-process-start-small.html` 標準結構）：

1. **一、文章標頭區塊（Hero Header）**：
   - 包含麵包屑導航（`首頁` / `知識筆記` / `文章標題`）、H1 文章大標題、1～3 個分類標籤（`.blog-tag-item`）、80～150 字導讀描述（`.blog-detail-lead`）、發佈日期與社群分享列（FB / LinkedIn / Threads / 複製連結），以及側邊目錄（`.blog-toc`）。
2. **二、封面圖與摘要卡片（`.blog-summary-card`）**：
   - 置於內文最開頭（封面圖 `cover.webp` 正下方），固定包含 3 點重點摘要，每點由 `<strong>6～10 字粗體小標題</strong>` 搭配 `<p>40～60 字具體摘要段落</p>` 組成。
3. **三、前言**：
   - 置於摘要卡片下方、第一個 H2 標題之前。由 **2 至 3 個段落**組成，依序為：
     - **第 1 段**：以第一線真實情境或客戶常說的話破題，點出企業常見盲點與焦慮。
     - **第 2 段**：引入國際權威研調數據、專欄文章或具名專家觀點佐證，點出問題本質。
     - **第 3 段**：結合商業投資報酬與風險控管視角，說明本文將帶給決策者的核心啟發。（若有參考外部文章，於前言下方附上 `.blog-source-link` 參考原文連結）。
4. **四、H2 與 H3 主體段落架構（3 大邏輯遞進 H2 段落）**：
   - 將核心論述分為 **3 個邏輯遞進的 H2 大段落**，依序為：
     - **H2 段落一：標竿案例／核心痛點診斷與觀念破除**（為什麼傳統做法會失效？問題本質是什麼？）
     - **H2 段落二：數據實證與商業營運紅利**（改採正確策略能為企業帶來哪三大具體商業回報？）
     - **H2 段落三：企業落地的三個實用建議**（決策者如何分步驟低風險推動？如何結合外部顧問團隊？）
   - **H2 總起導言（AEO 直答塊）**：每個 H2 標題下方，必須先寫 **1 段 80～120 字的總起導言**，首句直接回答該 H2 的核心問題，使其具備被 AI 搜尋引擎獨立擷取為精選摘要的完整語意。
   - **3 個主張句型 H3 子標題**：每個 H2 導言下方，細分為 **3 個具完整主張句型的 H3 子標題**（H3 本身即為明確觀點句，而非空泛名詞）。每個 H3 下方規劃 1～2 段具體論述（穿插真實場景、具名引述、統計數據或 `<ol>` 檢核清單）。
   - **結構化對比表格（`.blog-comparison-table`）**：於 H2 段落一或段落二結尾，規劃一個涵蓋 4～5 個評估維度的對比表格，直觀對照錯誤迷思與正確策略。
