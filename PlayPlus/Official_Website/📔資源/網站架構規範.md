# 二、 檔案與資料夾命名、放置與編碼規範

1. **列表頁與分類內頁資料夾結構**：
   - 凡具備「列表頁 ＋ 內頁」的架構，列表頁放置於根目錄（如 `services.html`、`portfolio.html`、`blog.html`），內頁則統一收納於對應的**單數英文分類資料夾**內：
     - 專業服務內頁：`/services/{service-slug}.html`
     - 作品集內頁：`/portfolio/{case-slug}.html`
     - 知識筆記內頁：`/blog/{YYYYMMDD}-{article-slug}.html`
2. **URL 與檔名命名準則（SEO-Friendly Slug）**：
   - 一律使用**全小寫英文單字**，單字間以半形連字號 `-`（Hyphen）連接，嚴禁使用底線 `_`、空白或中文檔名。
   - 檔名須提煉自該頁核心英文關鍵字（控制在 3～6 個實義單字內，去除無意義介系詞），使搜尋引擎與 AI 爬蟲僅看 URL 即可理解頁面主題（例如：`20260724-ui-ux-system-optimization-value.html`、`mitac-meeting-room-booking-system.html`）。
3. **圖片放置與格式規範（`images/`）**：
   - 全站圖片一律放置於根目錄 `images/` 資料夾內。
   - 內頁專屬圖片須依「分類資料夾 ➔ 頁面名稱資料夾」分層收納，主視覺封面統一命名為 `cover.webp`：
     - 知識筆記內頁圖片：`/images/blog/{YYYYMMDD}-{article-slug}/cover.webp`（內文配圖可依序命名或具語意命名如 `figure-01.webp`）。
     - 作品集內頁圖片：`/images/portfolio/{case-slug}/cover.webp`。
     - 專業服務內頁圖片：`/images/services/{service-slug}/cover.webp`。
   - 為兼顧載入效能（Core Web Vitals - LCP），照片與點陣圖一律轉檔壓縮為 `.webp` 格式，圖示與向量插畫採用 `.svg` 或 Lottie `.json`。
4. **樣式與腳本放置規範（`css/` & `js/`）**：
   - CSS 檔案一律放置於 `/css/` 資料夾內（包含 Tailwind 編譯輸出之 `tailwind.css`、全站共用 `style.css` 及各頁面專屬樣式表）。
   - JavaScript 檔案一律放置於 `/js/` 資料夾內。
5. **共用組件（Partials）與轉址（Redirects）維護規範**：
   - 全站共用的 `<header>` 與 `<footer>` 原始碼統一維護於 `partials/header.html` 與 `partials/footer.html`。
   - 各 HTML 頁面內透過 `<!-- @partial:header --> ... <!-- @/partial:header -->` 與 `<!-- @partial:footer --> ... <!-- @/partial:footer -->` 標記區塊，修改共用組件或新增內頁後，可執行 `npm run build:partials` 自動同步並處理子目錄相對路徑（`../`）。
   - 若有舊網址異動，須登記於 `scripts/redirects.json` 並執行 `npm run build:redirects` 產生含 `<link rel="canonical">` 之靜態轉址頁，避免權重流失與 404 錯誤。
6. **程式碼縮排規範**：
   - HTML / CSS 調整縮排一律使用 **Tab（Tab Size 4）**，不要使用空白鍵（Spaces）縮排。

# 三、 SEO / GEO / AEO 網站架構與內部連結策略（Topic Clusters）

現代搜尋引擎與 AI 檢索引擎透過「內部連結拓撲（Internal Linking Topology）」來理解網站的主題權威度（Topical Authority）：

1. **支柱頁與叢集內容雙向互連（Hub-and-Spoke Model）**：
   - **支柱頁（Hub / Pillar）**：`services/enterprise-system.html`、`services/web-design.html`、`services/app-development.html`、`services/chatbot-development.html`。
   - **叢集頁（Spoke / Cluster）**：`blog/*.html`（知識筆記）與 `portfolio/*.html`（作品集案例）。
   - **連結規則**：每一篇新增的「知識筆記」或「作品集案例」，在內文或文末必須包含 **1～2 個指向對應「專業服務支柱頁」或「聯絡諮詢頁（`contact.html`）」的內部連結**，以及 **2～3 篇同主題的「延伸閱讀」文章連結**，嚴禁產生無連出或無連入的孤島頁面（Orphan Pages）。
2. **描述性錨點文字（Descriptive Anchor Text）**：
   - 建立內部連結時，避免僅使用「點擊這裡」、「了解更多」、「這篇文章」等無語意字詞。
   - 應將目標頁面的核心關鍵字自然融入錨點文字中（例如：使用 `<a href="../services/enterprise-system.html">客製化企業管理系統設計與流程梳理服務</a>`），幫助搜尋引擎與 AI 模型精確建立語意關聯。
3. **扁平化檢索深度（Crawl Depth ≤ 3）**：
   - 全站任何一篇知識筆記或作品集內頁，從首頁出發的點擊深度（Click Depth）皆不超過 2～3 次點擊（`首頁 ➔ 知識筆記列表 ➔ 文章內頁`），確保爬蟲預算（Crawl Budget）與頁面權重高效傳遞。
