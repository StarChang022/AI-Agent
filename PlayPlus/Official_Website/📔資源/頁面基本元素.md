# PlayPlus 官網頁面基本元素規範（SEO / GEO / AEO 標準）

全站所有頁面（包含根目錄頁面與 `services/`、`portfolio/`、`blog/` 子目錄內頁）皆須具備以下基礎追蹤碼、SEO Meta 參數、JSON-LD 結構化資料與語意化內容元素。

# 二、 SEO 與社群 Meta 基礎參數

全部頁面的根標籤皆須宣告台灣繁體中文語系：`<html lang="zh-Hant-TW">`。
`<head>` 內部須依序配置以下區塊（子目錄內頁之本地靜態資源路徑請加上 `../` 前綴）：

## 1. Basic（基礎檢索與正規網址）

```html
	<meta charset="UTF-8">
	<meta name="viewport" content="width=device-width, initial-scale=1">
	<meta name="robots" content="index, follow">
	<meta name="author" content="PlayPlus 普魯士國際">
	<link rel="canonical" href="https://playplus.com.tw/{PagePath}">
```

- **Canonical 規範**：必須為自我參照（Self-referencing）的完整絕對網址（例如首頁為 `https://playplus.com.tw/`，企業管理系統頁為 `https://playplus.com.tw/services/enterprise-system`，知識筆記內頁為 `https://playplus.com.tw/blog/{YYYYMMDD}-{slug}.html`）。

## 2. Page Information（搜尋結果呈現核心）

```html
	<title>{PageTitle} | PlayPlus 普魯士國際</title>
	<meta name="description" content="{PageDescription}">
	<meta name="keywords" content="{PageKeywords}">
```

- **Title 撰寫規範（SEO & CTR 關鍵）**：
  - 總長度控制在 **25～30 個中文字（約 50～60 字元）** 內，避免在桌面與行動版 SERP 被截斷。
  - 核心關鍵字置於最前方，內頁可加上分類層級，例如：`{頁面核心標題} | {分類名稱} | PlayPlus 普魯士國際`。
- **Meta Description 撰寫規範（SEO & AEO 摘要）**：
  - 長度控制在 **70～85 個中文字（約 140～160 字元）**。
  - 須直接濃縮該頁面的**「目標受眾痛點＋PlayPlus 具體解方／核心觀點＋行動呼籲（CTA）」**，不僅提升人類點擊率（CTR），也方便 AI 搜尋引擎快速抓取頁面主旨。
- **Meta Keywords 撰寫規範**：
  - 挑選 6～10 個與該頁面高度相關的主力關鍵字、長尾詞與語意實體詞，以半形逗號加空白 `, ` 分隔（最後一詞固定包含 `PlayPlus 普魯士國際`）。

## 3. Meta Information（Open Graph 社群與 AI 預覽）

```html
	<meta property="og:title" content="{PageTitle} | PlayPlus 普魯士國際">
	<meta property="og:description" content="{PageDescription}">
	<meta property="og:url" content="https://playplus.com.tw/{PagePath}">
	<meta property="og:image" content="images/og/playplus.webp">
	<meta property="og:type" content="{website 或 article}">
	<meta property="og:locale" content="zh_TW">
	<meta property="og:site_name" content="PlayPlus 普魯士國際">
```

- **`og:type` 規則**：一般主頁與服務頁設為 `website`；知識筆記（`blog/`）與作品集案例內頁（`portfolio/`）設為 `article`。
- **`og:image` 規則**：通用頁面預設使用 `images/og/playplus.webp`；服務頁、作品集或知識筆記若有專屬封面圖，則指向對應封面路徑（如 `images/blog/{slug}/cover.webp`）。建議尺寸為 `1200 x 630 px` 之 `.webp` 檔案。

## 4. Setting（Icon、字型預連與 CSS）

```html
	<link rel="icon" href="images/favicon.webp" type="image/webp">
	<link rel="apple-touch-icon" href="images/favicon.webp">
	<link rel="preload" href="images/logo/Logo-Light.webp" as="image">
	<link rel="preload" href="images/logo/Logo-Dark.webp" as="image">
	<link rel="preconnect" href="https://fonts.googleapis.com">
	<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
	<link href="https://fonts.googleapis.com/css2?family=Anta&family=Montserrat:ital,wght@0,100..900;1,100..900&family=Noto+Sans+TC:wght@300;400;500;700;900&display=swap" rel="stylesheet">
	<link rel="stylesheet" href="css/tailwind.css">
	<link rel="stylesheet" href="css/style.css">
```
*(註：位於 `blog/`、`portfolio/`、`services/` 子資料夾內的頁面，上述 `images/` 與 `css/` 路徑須改為 `../images/` 與 `../css/`。)*

# 三、 JSON-LD 結構化資料規範（GEO 實體圖譜 & AEO 問答核心）

結構化資料（Schema.org）是 Google AI Overviews、ChatGPT Search、Perplexity 等生成式引擎辨識品牌實體（Entity Clarity）與擷取直接答案（AEO）的最重要信號。請依頁面類型埋設對應的 JSON-LD：

## 1. 一般主頁面（首頁、服務總覽、聯絡我們等）

```html
	<script type="application/ld+json">
	[
		{
			"@context": "https://schema.org",
			"@type": "WebPage",
			"inLanguage": "zh-Hant-TW",
			"url": "https://playplus.com.tw/{PagePath}",
			"name": "{PageTitle} | PlayPlus 普魯士國際",
			"description": "{PageDescription}",
			"telephone": "+886-2-27111223",
			"address": {
				"@type": "PostalAddress",
				"streetAddress": "忠孝東路四段270號7樓",
				"addressLocality": "台北市",
				"addressRegion": "大安區",
				"postalCode": "106",
				"addressCountry": "TW"
			},
			"logo": "https://playplus.com.tw/images/logo/Logo-Light.webp",
			"sameAs": [
				"https://www.facebook.com/PlayPlus.International",
				"https://www.threads.com/@playplus_webdesign"
			]
		}
	]
	</script>
```

## 2. 知識筆記與觀點文章內頁（`blog/*.html`）

文章內頁必須使用 `BlogPosting` Schema，明確宣告發佈／更新日期、作者與發佈機構（強化 E-E-A-T 訊號）；若文末含有常見問答（FAQ），可於同一陣列中並聯 `FAQPage` Schema：

```html
	<script type="application/ld+json">
	[
		{
			"@context": "https://schema.org",
			"@type": "BlogPosting",
			"inLanguage": "zh-Hant-TW",
			"headline": "{文章 H1 標題}",
			"description": "{PageDescription}",
			"image": "https://playplus.com.tw/images/blog/{ArticleSlug}/cover.webp",
			"datePublished": "{YYYY-MM-DD}",
			"dateModified": "{YYYY-MM-DD}",
			"author": {
				"@type": "Organization",
				"name": "PlayPlus 普魯士國際顧問團隊",
				"url": "https://playplus.com.tw/about-playplus"
			},
			"publisher": {
				"@type": "Organization",
				"name": "PlayPlus 普魯士國際",
				"url": "https://playplus.com.tw/",
				"logo": {
					"@type": "ImageObject",
					"url": "https://playplus.com.tw/images/logo/Logo-Light.webp"
				}
			},
			"mainEntityOfPage": {
				"@type": "WebPage",
				"@id": "https://playplus.com.tw/blog/{ArticleSlug}.html"
			}
		}
	]
	</script>
```

## 3. 含有常見問題（FAQ）之頁面（AEO 加強配置）

凡頁面中包含 FAQ 問答區塊（如首頁、四大專業服務內頁、深度知識筆記），建議於 JSON-LD 陣列中加入 `FAQPage`，使搜尋引擎與 AI 助理可直接抽取標準答案：

```json
		{
			"@context": "https://schema.org",
			"@type": "FAQPage",
			"mainEntity": [
				{
					"@type": "Question",
					"name": "{常見問題標題 1？}",
					"acceptedAnswer": {
						"@type": "Answer",
						"text": "{精準、具體且包含關鍵字與數據的完整解答內容}"
					}
				}
			]
		}
```

# 四、 頁面內容級 SEO / GEO / AEO 必備結構元素

為了讓網頁在傳統搜尋（SEO）、生成式 AI 引述（GEO）與精選摘要（AEO）中同時取得最佳表現，頁面 HTML `<body>` 內容必須遵守以下結構準則：

1. **嚴格且語意化的 Heading 階層**：
   - 全頁**僅能有唯一一個 `<h1>`**，且必須包含該頁核心關鍵字。
   - 依內容邏輯遞進使用 `<h2>` ➔ `<h3>` ➔ `<h4>`，嚴禁為了視覺字級大小而跳階使用標題標籤。
2. **AEO 問句型標題與「黃金 40～80 字直答塊」**：
   - 在服務頁或知識筆記中，適度將 `<h2>` 或 `<h3>` 設計為決策者常問的自然問句（例如：「什麼情況下企業應該選擇客製化系統而非套裝軟體？」）。
   - 在標題正下方第一段，先用 **40～80 個中文字（2～3 句話）直接給出明確結論或定義（BLUF 原則：Bottom Line Up Front）**，接著才展開詳細論述、清單或案例。
3. **GEO 高引用率內容元件（AI 快速摘要與結構化圖表）**：
   - **AI 快速摘要（Key Takeaways）**：長文或案例開頭提供 3 點濃縮重點，讓 AI 爬蟲與忙碌的企業決策者能在 10 秒內掌握全篇核心價值。
   - **結構化對比表格（`<table>`）与步驟清單（`<ol>` / `<ul>`）**：凡涉及「方案比較（如套版 vs 客製化）」、「開發階段流程」、「預算評估維度」，優先使用原生語意化 `<table>` 或有序清單呈現，大幅提高 Google 精選摘要與 Perplexity / ChatGPT 引用機率。
   - **事實密度（Factual Density）**：內容中具體寫出量化數據（如「100+ 個活躍系統」、「降低 60% 人工核對時間」）、實際工具名稱（Figma、Notion、LINE Messaging API）與真實應用場景。
4. **圖片優化與 Core Web Vitals 友善規範**：
   - 圖片全面採用 `.webp`（或向量圖 `.svg`）以確保極致載入速度。
   - 所有具資訊意義的 `<img>` 必須填寫具體描述情境與關鍵字的 `alt` 屬性（純裝飾圖則設為 `alt=""` 並加上 `aria-hidden="true"`）。
   - 建議明確標註 `width` 與 `height` 屬性以防止版面配置轉移（CLS），非首屏（Below the fold）圖片加上 `loading="lazy"`。
