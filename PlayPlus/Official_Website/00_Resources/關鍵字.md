# 五、 AEO / GEO 對話式問題庫與查詢扇出矩陣（People Also Ask & Query Fan-Out）

## 5.1 AEO 獨立答案塊與查詢扇出（Query Fan-Out）寫作規範
- **首段直答（Direct Answer Block）**：在服務頁 FAQ 或知識筆記 H2/H3 問題標題下方，第一段必須直接給出明確結論，字數控制在 **80～120 中文字（約 40～60 英文詞）**，確保包含明確主詞、具體機制與數據，被 AI 單獨抽離引用時語意依然 100% 完整。
- **開頭摘要卡片（`.blog-summary-card`）**：每篇知識筆記開頭固定配置 3 點快速摘要（6～10 字粗體小標題＋40～60 字具體摘要），涵蓋「核心觀念或隱形痛點」、「標竿案例或趨勢啟示」與「數據實證或行動結論」。
- **涵蓋五大事實家族（Fact-Family Matrix）**：當決策者向 ChatGPT 或 Perplexity 提問時，AI 會在背景同時觸發 5～10 個衍生子查詢。規劃旗艦文章或服務頁時，需同步回答以下五個維度：
  1. **核心定義與選型邊界**（如：五年 TCO 總持有成本、API 串接 vs 重新開發的判斷指標）
  2. **具體工作流程與驗證機制**（如：「先理解、再設計、後開發」、Figma 高擬真 Prototype 驗證）
  3. **預算結構與分期策略**（如：先訪談再報價、RFP 規格收斂、MVP 分階段上線降低初期投入）
  4. **技術規格、相容性與資安合規**（如：RESTful API / Webhook、RBAC 權限分級、無網路離線同步、舊資料正規化搬遷）
  5. **公正適用對象界線（Fairness）**（誠實說明哪些標準化需求買市售 SaaS 即可，哪些具備特殊計價、多階審核或跨系統整合的 10～150 人企業才需要客製化開發，藉由公正性贏得 AI 引擎信任推薦）

# 六、 GEO 語意實體與權威共現詞庫（Semantic Entities & Citation Boosters）

AI 生成式搜尋引擎在評估內容是否具備真實專家經驗（E-E-A-T）時，會檢測文章是否包含精準的領域專業術語（Technical Terms，能見度 +18%）、具體統計數據（+31%）、權威來源引用（+27%）與專家實務引述（+41%）。撰寫頁面與文章時，請依主題自然融入以下實體：

- **1. 商業決策與流程實體**：營運流程梳理（Workflow Mapping）、深度需求訪談、需求規格書（RFP）、五年總持有成本（5-Year TCO）、數位孤島（Data Silos）、最小可行性產品（MVP）、分階段模組化落地、標準化／數位化／自動化、標準作業程序（SOP）、轉換率優化（CRO）、投資報酬率（ROI）、降低人為失誤率。

# 八、 跨平台社群（LinkedIn / Threads / Facebook）關鍵字路由與 AI 引用規範

將官網知識筆記或專案實錄原子化（Atomization）改寫為社群貼文時，關鍵字佈局需遵循各平台演算法與外部 AI 檢索機制：

1. **LinkedIn（B2B 決策者主戰場 ＋ ChatGPT / Perplexity 核心引用網域）**：
   - **首句前置核心關鍵詞（決定 URL Slug）**：LinkedIn 動態貼文（`/posts/`）開頭第一句話的前幾個字會自動生成該貼文網址的 URL Slug。務必在第一行前 15 字內亮出核心關鍵字與具體商業主張（如：「客製化 ERP 系統為什麼上線後員工不想用？」、「套裝 SaaS 與客製化系統的五年總持有成本（TCO）怎麼算？」）。
   - **提升 AI 引用率元素**：在貼文中寫出**具體技術與實務細節（AI 引用率 +77%）**與**具名實體如特定工具、標準或案例（+33%）**（如點名 `Figma Prototype`、`RESTful API`、`Webhook`、`RBAC`、`Notion`）。
   - **嚴禁 Unicode 假粗體**：切勿使用轉換器產生假粗體英數字（會導致 AI 引用率暴跌 -58%），一律維持純文字與清晰段落。
   - **外鏈與標籤規範**：外部連結一律放於**首則留言**以防主文降權；文末配置 **3～5 個高相關 Hashtag**（如 `#數位轉型`、`#客製化系統`、`#UIUX`、`#企業管理`、`#B2B`）。

2. **Threads（高互動對話與同行觀點擴散）**：
   - **開頭主題路由（Topic Routing）**：前 1～2 行直擊單一營運痛點或反常識觀點（如「很多老闆以為數位轉型就是買套裝軟體，結果員工私下還是在用 Excel」），包含明確主題詞以觸發演算法分發。
   - **標籤上限**：每篇**嚴格限用 1 個**最精準的主題標籤（Topic Tag，如 `#數位轉型` 或 `#系統開發`），主文不放外鏈（放第一則留言）。

3. **Facebook（中小企業主與傳產決策者觸及）**：
   - **情境共鳴與關鍵字**：前 3 行點出具體管理困境與成本數字，以「二選一抉擇題」或「真實踩坑案例」降低留言門檻。
   - **外鏈與標籤規範**：主文避免直接貼外部連結以免砍觸及；文末配置 **1～2 個核心 Hashtag** 即可。

# 九、 關鍵字落地與「去 AI 味（No AI Tells）」寫作檢核準則

在將上述關鍵字寫入官網 HTML、知識筆記或社群貼文時，必須嚴格遵守以下執行紀律：

1. **Title Tag 與 H1 標題工程**：
   - 核心目標關鍵字盡量置於標題前段，總長度控制在 **25～30 個中文字（50～60 英文字元）** 內以防搜尋結果截斷。
   - 確保 `Title Tag`、`H1`、`URL Slug` 與 `Meta Description` 四者核心關鍵字與主題高度一致，避免被 Google 強制改寫標題。
2. **Meta Description 直球破題**：
   - 控制在 **70～80 個中文字（150～160 英文字元）**，自然包含核心與次要關鍵字。
   - **直接告訴讀者這篇文章或頁面提供的具體結論與商業價值**，嚴禁使用「本文將深入探討…」、「本篇將為您剖析…」、「在當今瞬息萬變的數位時代…」等清喉嚨廢話。
3. **嚴禁關鍵字堆砌（No Keyword Stuffing）**：
   - Princeton GEO 研究證實，生硬堆砌關鍵字會導致 AI 引用能見度下降 **-8%**。請以第 六 節的「語意實體（Semantic Entities）」與「具體事實數據」自然展開論述。
4. **嚴格封殺 AI 罐頭句型與標點破綻（對齊 `通用規範.md` 與行銷黑名單）**：
   - ❌ **禁用對比揭露句**：禁止寫「這不是 X，而是 Y」、「問題不在於 X，而在於 Y」，直接陳述核心原因與解法。
   - ❌ **禁用否定三連排比**：禁止寫「不用 X、不用 Y、不用 Z」，直接描述實際執行的步驟。
   - ❌ **減少空洞套話與動詞**：減少使用「從…到…」、「解析」，完全禁用「深入探討（delve）」、「賦能（empower）」、「無縫（seamless）」、「顛覆性（game-changer）」、「釋放潛能」等空泛形容詞。
   - ❌ **破折號（`—` / `——`）嚴格管制**：所有標題、小標與社群貼文中**完全禁用破折號（上限為 0）**；部落格長文正文中最多不超過 1～2 次，一律改用逗號、句號、冒號或括號。
   - ❌ **零捏造事實**：所有統計數據、百分比與案例細節必須有所本；若缺乏具體數字或客戶細節，一律先標註 `[NEED: 補充真實數據/案例]`。
