# 爽爽Shabu 提案資料整理

發生日期: 2026/09/23

多數餐飲品牌都知道應該要建立會員、再行銷，我們要再進一步思考，為顧客安排客製化的規劃，以及根據當天狀況動態調整優惠。在這個 AI 時代，要做到**客製化規劃**及**動態調整**的成本大幅降低，已經可以看見可行性，進而幫助餐飲業獲得更多顧客。

我們要打造 **AI 智慧獲客與營運管理 SaaS 平台**，並以**爽爽Shabu**的3家門市作為示範基地。

專案目標聚焦於「AI」及「獲客」，要做到「取代」Ocard 的會員系統、「整合」inline 的訂位系統。

我們的 SaaS 發想是參考國內外餐飲業數位科技，加上思考國內餐飲消費習慣，所整理出的功能概念。角色包含「消費者」及「餐飲業者」。

- **消費者**的使用場景為**平台**（Web／APP／LINE），目標是線上導購實體消費及線下消費轉換線上會員。
- **餐飲業者**的使用場景則為**行銷工具**，任務是品牌官網的把關及主被動行銷策略。

消費者取得餐飲資訊的途徑非常碎片化，可能從線上的搜尋、地圖、社群、廣告等管道取得，或者線下門市、口耳相傳、傳單等各種管道取得。

預算足夠的前提下，SaaS 實際操作應該包含 Web 、 LINE 及 APP 三種介面，用於應對多種場景。

### SEO / AEO 落地頁自動生成

系統透過資料庫自動產出高資訊密度的動態落地頁（Landing Page），目標鎖定傳統 Google 搜尋引擎與生成式 AI 的推薦引用，拓展自然搜尋客源。

頁面必須具備「不可替代的專屬資料點」，每個生成的子頁面除了共享品牌視覺外，必須強制綁定專屬的動態欄位，確保頁面間重複率低於 30%，避免受到 Google 懲罰機制。

- **核心資料矩陣動態渲染：** 系統會以實體資料庫為基礎，組成多種交叉組合，自動生成對應的專屬網頁。以火鍋店為例，可以組成「門市據點 × 用餐情境 × 招牌品項」交叉組合，例如「3 家門市 × 4 類核心用餐情境（單人社恐、家庭聚餐、朋友宵夜、情侶約會） × 8 種招牌湯底」共 96 頁。
- **AEO 機器可讀協定：** 在網頁原始碼內自動封裝 Schema.org 結構化資料（包含座標、營業時間、特色湯頭、用餐須知），讓搜尋爬蟲與大型語言模型提取真實門市資料，提高 AI 推薦解答的被引用率。

### SEO 架構檢測

自動化診斷品牌官網的技術健康度，確保網站頁面能持續被 Google 爬蟲檢索與收錄，維持穩定的搜尋排名。

- **索引與抓取狀態監控**： 自動核對全站 XML Sitemap、Robots.txt 規則與 HTTP 狀態碼，主動攔截 404 斷鏈、錯誤轉址與無效抓取頁面。
- **頁面語意標籤合規**： 檢核全站 Title、Meta Description、H1–H3 標籤階層及圖片 Alt 屬性，預防關鍵字或標籤缺失。

### AEO 結構化資料檢測

系統自動化驗證品牌官網與落地頁的 Schema 可讀性，確保實體餐廳數據能被大型語言模型精準解析與優先引用。

- **餐飲語意標記合規驗證**： 即時監控全站 JSON-LD 原始碼，校驗欄位語法，主動排除代碼錯誤或漏填。例如 @type: Restaurant（門市資訊）、@type: Menu（湯頭與套餐規格）等。
- **實體資訊一致性檢核**： 自動核對結構化資料與實體營運設定（如分店營業時段、不收服務費規範、用餐 90 分鐘限制），防範 AI 擷取到衝突或過期的門市資訊。
- **情境相容性評估**： 檢驗各情境常見問題的結構完整度，確保當潛在顧客詢問「台中哪裡有適合個人的單人鍋物」時，AI 答案引擎能直接將爽爽Shabu 列為首選推薦。

### LINE 交易型 AI 客服

傳統客服機器人只能根據關鍵字回答固定題目，我們將 LINE 客服整合大型語言模型與後端業務 API，兼具「品牌諮詢」與「實質交易」能力。實現 24 小時即時回應，將多數常規問答與訂位改期交由 AI 全自動消化，大幅釋放門市外場人力（尤其是減少接電話佔據時間）。

- **全天候門市資訊與菜單導覽**： 透過 RAG 技術串接門市知識庫，精準回答餐廳的營業時間、排隊與計費規則等，對話風格可依餐廳設定維持幽默、自在的品牌語調。
- **雙向串接代客處理業務**： 串接 inline 訂位 API 與會員系統，消費者直接在對話中即可完成「查詢與修改訂位時間/人數」、「查詢會員點數」與「領取活動優惠券」，縮減操作路徑。參考 [inline 訂位系統整合（串接 API）](https://app.notion.com/p/inline-API-3e5b965c45a680bfba41d971f64c75a2?pvs=21) 。
- **客訴安撫與人機協同防護**： 當辨識到顧客負面評價或抱怨時，AI 即時生成安撫回覆，並緊急通知管理者。

### 會員系統

會員系統是整個 SaaS 的基底。

降低加入會員門檻，填寫簡易資料並綁定手機號碼即可快速加入。可以從 Web 和 APP 登入會員，也可以從 LINE 官方號輸入手機號碼查找資料。

將來自搜尋、社群與實體門市的匿名訪客，轉化為數據資產，全面取代第三方會員點數平台（如 Ocard）。

- **一鍵入會**： 顧客於現場掃碼或點擊線上連結，從 LINE 完成註冊，系統同步自動派發「入會禮」點數或商品兌換券，加速轉化效率。未來僅需輸入手機號碼即可登入 Web 或 APP 會員。
- **消費積點與紅利兌換閉環**： 整合現場結帳核銷機制（支援發票載具 QR 掃描或手機條碼核銷）。顧客在 LINE 會員中心可即時查閱點數，隨時兌換人氣品項（如招牌肉盤、海鮮盛合），維持消費回饋感。
- **數據主權與彈性分級制度**： 會員基本資料、各分店造訪頻率、累積消費金額均完整沉澱於品牌專屬資料庫。後台可自由設定會員等級門檻與專屬權益，擺脫外部平台的功能限制與資料割裂。

### 智慧菜單推薦

將靜態菜單轉為主動式導購，縮短顧客的決策時間。

當消費者於 Web 或 APP 或 LINE 官方帳號瀏覽門市與菜單時，系統依據外在情境與會員歷史數據自動產出客製化推薦，提升轉換效率並帶動特色品項加購。

- **新客環境感知推薦（冷啟動模組）**： 初次造訪或未登入的新訪客，系統結合即時外部特徵（如當前氣溫、降雨）與門市銷量排行自動組合推薦。
- **熟客習慣智慧預測（溫啟動模組）**： 針對已入會顧客，演算法比對其歷史點餐記錄與口味標籤，主動推薦關聯搭配品項。
- **搭配優惠**： 推薦菜單整合成組合，搭配行銷優惠促進行動。

### inline 訂位系統整合（串接 API）

系統透過 API 或 Webhook 與 inline 進行數據介接，將線上訂位數據抓進會員系統。參考 [91APP 開發餐廳 APP 串接 inline API](https://91app.com/blog/restaurant-tools-integration/)。

門市外場人員維持既有作業習慣，繼續使用熟悉的 inline 平板進行桌況調度與現場劃位，無需額外學習新系統即可完成後台數據彙整。

- **會員身份自動歸戶（UID 關聯）**： 顧客在品牌官網或 LINE 官方帳號發起訂位時，系統自動帶入會員識別碼（UID），預約完成即刻同步建立關聯，減少外場手動比對身分的成本。
- **預約狀態雙向即時同步（Webhook 監聽）**： 系統即時接收 inline 的「預約成功、時間修改、主動取消、實際入座、爽約」等事件通知，作為後續自動發送提醒與標籤分析的觸發條件。

### 顧客輪廓建立

當顧客加入會員（綁定手機號碼），後續 inline 線上訂位或電話預約，系統自動將跨通路的行為軌跡進行動態貼標，建立顧客數據檔案，作為後續智慧推薦與再行銷的基礎。

- **多通路資料整合**： 透過綁定手機號碼，整合會員資料和 inline 紀錄。
- **動態偏好與情境標籤**： 系統自動標記「平日離峰客」、「週末家庭客」或「深夜宵夜族」等消費特徵。
- **顧客價值週期自動分級：** 依據造訪頻次、最後來訪間隔與消費貢獻度，自動將會員歸類為「核心熟客」、「活躍新客」或「沉睡預警客」，無需門市人員手動維護。

### 自動化回訪與調查

系統串接 inline 訂位結案狀態，於顧客離店後的黃金回饋期內，透過 LINE 官方帳號自動發送滿意度調查，將顧客反饋即時轉化為數據。

- **離店即時自動觸發**： 於離店後 1 至 2 小時內自動推送微型調查卡片，把握顧客用餐記憶最清晰的時間點。
- **輕量化作答**： 採用直覺式一鍵評分（如 1–5 星或分數），搭配簡易選項（湯底風味、肉品海鮮、自助吧動線、空間舒適度），顧客在 30 秒內即可完成作答。系統同步回饋會員點數以維持高填答率。
- **負評內部即時攔截機制**： 當顧客填寫低分（1–2 星）或表達不滿時，系統第一時間向門市店長發送內部警報通知，讓營運團隊在顧客轉往 Google 地圖發布公開負評前，即可在 LINE 管道內主動展開關懷與修復。

### 流失預警

透過演算法分析會員的回訪週期、消費間距與互動熱度，在顧客即將進入沉睡或完全流失前進行風險標記，為後續的「再行銷」提供名單依據。

- **個人化回訪週期**： 依據每位會員的歷史到店數據建立回訪週期，當顧客未造訪天數超過正常標準差時，系統自動將其轉為「沉睡預警」狀態。
- **多維度互動衰減評估**： 綜合追蹤會員在 LINE 官方帳號的點擊互動、點數過期天數、以及近期是否曾主動取消訂位等行為特徵，計算綜合流失風險等級（高、中、低風險）。
- **動態召回名單自動匯流**： 被判定為高流失風險的會員名單，將即時同步至數據中台，自動納入離峰限時促銷券或回流專屬禮的優先推播清單，無須門市人員手動匯出或比對報表。

### 離峰動態優惠投放

系統參考動態調節演算法，結合即時天氣、分店訂位負載與歷史客流走勢，在離峰時段自動向特定客群推播限時電子折價券，有效填補空桌並帶動額外營收。

- **多維度產能與氣候預測模型**： 串接氣象署即時資料（氣溫、降雨機率）與 inline 分店預約數據。當演算法推算出特定時段（如平日 14:00–16:30 或深夜宵夜時段）預約率低於門檻時，即時觸發離峰補貼機制。
- **分眾精準定向推播**： 透過 LINE 官方帳號或 APP 發送「限時 2 至 3 小時快閃優惠券」，優先投放給周邊常客、具備離峰消費紀錄者或流失預警名單，避免全面廣發。
- **毛利底線風控機制**： 後台設定每款套餐的食材成本與折扣下限（例如折價上限 15% 或限定抵扣指定加點肉盤）。當演算法計算出的邊際利潤低於安全閾值時，強制停止降價派券，確保每一筆離峰訂單皆具備正向毛利。

### 自動化行銷

依據顧客生命週期節點或特定事件，自動觸發個人化行銷訊息與專屬票券，並維持品牌一致的溝通風格，免除門市人員手動發訊與檔期排程的繁瑣作業。

智慧調配 LINE、APP 與 Email 通訊管道，兼顧觸達率及降低通訊發送成本。

- **客製化品牌語調**： 支援業者設定專屬品牌個性（如爽爽Shabu輕鬆幽默、親切無壓的調性），由 AI 自動套用該語調生成文案與卡片，避免制式化罐頭訊息造成顧客反感。
- **關鍵事件自動觸發**： 串接會員資料庫，於顧客生日當月、入會紀念日、重大節慶或累積達成消費里程碑時，自動派發專屬祝福卡片與限定禮遇（如壽星肉盤兌換券），精準鎖定聚餐時機。
- **多波段自動化行銷旅程**： 系統具備條件分支追蹤能力（如票券發送後第 7 天若尚未核銷，自動發送效期倒數提醒），逐步提高優惠券的實際到店兌換率。

### 點數生態循環

建構紅利積點與兌換，透過人氣商品兌換，將顧客的每一次到店消費轉化為下一次預訂的明確動機。以實體特色餐點兌換取代直接的現金折讓，能有效保護餐飲核心毛利率。

- **消費累點與商品兌換**： 顧客結帳時透過手機號碼即時完成累點，點數可在會員中心（LINE 或 APP 介面皆可開啟）兌換商品券，到店即可出示核銷。
- **行為引導與階梯加碼回饋**： 支援彈性設定點數活動規則，例如離峰時段來店點數雙倍、好友轉介註冊獎勵點數，引導會員在特定營運時段或行銷活動中採取對門市有利的消費行為。
- **點數即期自動喚醒機制**： 點數到期前 30 天與 7 天，自動透過 LINE 或 APP 推播「點數即期提醒」訊息，將沉睡點數轉為具體的回訪動力。
