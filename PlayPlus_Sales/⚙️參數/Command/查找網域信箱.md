# 爬蟲攻略

## 一、 網頁爬取與內容解析（三大管道 / 五大方法）

當程式訪問公司官網（包括首頁、常見的 `/contact`、`/about` 等聯絡頁面，以及內部關鍵字子頁面）時，會使用 `extract_emails_from_html()` 透過以下 5 種方式抓取頁面中的 Email：

1. **管道一：Cloudflare 混淆解密 (data-cfemail 屬性)**
   - 許多網站使用 Cloudflare 防止爬蟲抓取 Email，會把 Email 加密存於 `<span data-cfemail="...">`。
   - 程式內建 `decode_cloudflare_email()`，使用第一個 Byte 作為 Key 進行 **XOR 解密**還原真實 Email。
2. **管道二：解析 `mailto:` 超連結**
   - 掃描 HTML 中所有 `<a>` 標籤的 `href` 屬性，提取以 `mailto:` 開頭的信箱地址。
3. **管道三：解密 Cloudflare 防護網址**
   - 針對 `/cdn-cgi/l/email-protection#<hash>` 形式的加密超連結，解密 URL Hash 還原 Email。
4. **管道四：BeautifulSoup 解密後的純文字掃描**
   - 先透過 BeautifulSoup 將 HTML 實體轉化（如將 `&#x40;` 自動還原為 `@`），再以正則表達式掃描內文。
5. **管道五：原始 HTML 全文正則比對（Regex 補漏）**
   - 以正則表達式（`EMAIL_REGEX`）對原始 HTML 做最後補漏掃描。


## 二、 SMTP 伺服器主動 Handshake 驗證（SMTP 測試）

在爬取官網前，會先呼叫 `smtp_search_emails()`：
1. **MX Record 查詢**：利用 `dnspython` 查詢該網域的 Mail Server (MX 記錄)。
2. **Catch-all 檢測**：先用隨機產生的虛構信箱測試，防止某些伺服器對任何信箱都回應 250 (Success)。
3. **前綴主動握手測試**：若非 Catch-all 伺服器，自動嘗試常見前綴（如 `info@`, `service@`, `contact@`, `sales@`, `office@`, `mail@`），發送 SMTP RCPT 命令，若 Server 回應 `250` 代表該信箱真實存在。


## 三、 頁面檢索策略（網頁路徑探索）

為了提高找到 Email 的機率，程式不會只讀首頁：
1. **已知路徑輪詢 (`CONTACT_PATHS`)**：優先嘗試訪問 `/contact`, `/contact-us`, `/about`, `/service` 等 10 個常見路徑。
2. **優先權子頁面探索 (`collect_all_subpage_urls`)**：如果上述路徑沒找到，會解析首頁所有同網域連結，優先爬取含有 `contact`, `about`, `agent`, `service`, `聯絡`, `關於` 等關鍵字的內部頁面（最多額外探索 10 個頁面）。
3. **備用域名策略**：優先保留符合公司主網域的 Email；若主網域未找到，也會保留 ISP 信箱（如 `@ms26.hinet.net`），並自動過濾掉 `noreply`, `no-reply`, `postmaster` 等系統廢號。
